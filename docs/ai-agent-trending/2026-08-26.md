## Feature 深度卡片

### 1. [freestylefly/awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2)

**一句话定位：**面向设计师、运营内容团队和 Agent 用户的 GPT Image 2「案例画廊 + 结构化提示词模板 + Agent Skill」；它把散落社区示例变成可搜索、可复制、可组合的 Prompt 资产，不是模型或独立图像生成引擎。

**典型场景：**从样图找电商/品牌/UI/信息图灵感；将自然语言需求变成含布局、文字和负面约束的结构化 Prompt；做角色/卡牌/系列视觉参考；让 Agent 自动选模板与相近案例；登录网站快速试生成。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 条件 |
|---|---|---|
| [可视案例画廊](https://github.com/freestylefly/awesome-gpt-image-2/blob/main/docs/gallery.md) | 展示结果图、完整 Prompt 与案例页 → 看结果再选方向 → 创意探索/竞品参考 | 当前 **529 条实有记录**，编号 1–532，缺 12/169/170 |
| 多轴搜索与筛选 | 按关键词、13 分类、19 风格、10 场景缩小结果并大图预览 → 少翻长列表 → 定向检索 | [在线 Demo](https://gpt-image2.canghe.ai/)可直接浏览 |
| Prompt 复制与来源回跳 | 复制完整提示词并回到 GitHub/原社区来源 → 改写更快且可查出处 → 个人创作/团队评审 | 504 条有外部 `sourceUrl`，25 条只保留来源标签 |
| [22 个机器可读模板](https://gpt-image2.canghe.ai/style-library.json) | 覆盖 UI、信息图、海报、电商、品牌、摄影、角色、叙事等 → 从堆风格词转为填规格 → 商业物料 | 模板文档仍有 21/393 的旧口径，以当前 JSON 为准 |
| JSON 结构化 Prompt | 用主体、构图、文案、材质、比例、约束等字段表达 → 可替换变量和批量变体 → Agent/脚本流水线 | 是 Prompt 资产，不是稳定公共生成 API |
| 防坑与负面约束 | 按类别提示文字锁定、平台特征、身份锚点、禁止元素 → 提前暴露常见失败 → 中文排版/古风/角色一致性 | 方法论，不构成成功率保证 |

| 跨 Agent 安装 | `npx skills add`、Claude Marketplace、npm/GitHub Packages 同步 Skill → 进入既有 Agent 更容易 → 多宿主创作 | 安装 CLI 不是图片生成 CLI |
| 站内生成测试 | 登录后编辑案例 Prompt 并发起生成 → 从浏览进入快速验证 → 新手试模板 | Google 登录、积分/会员；第三方后端转发，非本地免费推理 |
| 收藏与可自托管网站 | 账户收藏案例；开发者可部署画廊、积分和支付面 → 做个人/团队提示词门户 → 高频复用 | 自托管需 Supabase、Vercel、API Key；支付需 Stripe/支付宝 |

**可用性、同类与缺口：**画廊、Prompt、模板和 Skill 可直接用；真正出图需 GPT Image 2 或站点积分，且 OpenAI API 另行计费。项目无 GitHub Release/正式 Roadmap；付费社群和支付开关仍有部署前置条件。相比 [wuyoscar/GPT-Image2-Skill](https://github.com/wuyoscar/GPT-Image2-Skill)，本项目案例、中文商业模板和 Web 筛选更强，但缺直接调用 OpenAI 的生成/编辑 CLI；相比 Toolcentral 的大规模模板集，视觉体验和人工防坑指南更强，但数据规模、Schema、国际化和语义搜索较弱。UI、模板、Skill、在线 Demo 齐全；缺公开 SDK、稳定公共 API、批处理队列、自动回归评测和确定性复现。

**限制与今日关注：**“工业级”“文字必须准确”是目标而非 SLA；OpenAI 官方仍列出精确文字、跨图一致性、复杂布局和耗时边界。案例来自社区整理，不是统一参数下 benchmark；[Issue #3](https://github.com/freestylefly/awesome-gpt-image-2/issues/3) 也曾修复样图与 Prompt 错配。MIT 不自动授予第三方图片/Prompt 商用权；赞助商的视频、CDN、批量 API/MCP 不是本项目 Feature。**事实：**今日 #1、+1,698，近期连续补案例并更新网站；**推断：**GPT Image 2 热度、强视觉 README、复制即用和“画廊→Agent Skill→站内试图”短闭环共同推动收藏传播，Stars 不等于模板成功率或生产采用。

### 2. [anthropics/claude-plugins-community](https://github.com/anthropics/claude-plugins-community)

**一句话定位：**面向 Claude Code/Cowork 用户与第三方作者，由 Anthropic 审核管线驱动的公共社区插件目录；它解决长尾插件的发现、分发与可复现安装，本身不执行目录内插件的业务能力。

**典型场景：**发现细分开发/知识工作插件；安装前检查组件和来源；以 user/project/local Scope 统一团队工作流；从 Cowork/Claude Code 共享生态；作者经表单、扫描、批准和固定 SHA 发布。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 条件 |
|---|---|---|

**限制与今日关注：**Agentic benchmark 在固定 FastAPI+React、Haiku 4.5、12 Feature、每臂 n=4 上报告平均 LOC -54%、Token -22%、成本 -20%、时间 -27%；收益集中于可换原生控件任务，简洁后端接近零，未启动服务/浏览器；“安全 100%”仅 5题×20执行。旧 80–94% 单轮口径仍可能误导。独立 480-run复测报告约少44%代码但在未声明边界条件上有稳健性损失；另有小样本显示工具/成本反升。Ultra 可能挑战过度、Hook需信任，[Issue #736](https://github.com/DietrichGebert/ponytail/issues/736)还有 Review 状态锁定个案。**事实：**今日 #14、+982，v4.9.0 加模式持久化/子 Agent范围并修大量跨平台问题；**推断：**“懒惰资深工程师”品牌、日期控件示例与可复测争论共同推动传播，不能外推普遍节省或正确性不降。

### 16. [asciimoo/hister](https://github.com/asciimoo/hister)

**一句话定位：**面向个人、家庭和小团队的私有自托管搜索引擎，把访问过的网页、浏览器历史、本地文件和抓取站点整理成可全文检索、可预览、可供 AI Assistant 读取的个人知识索引。

**典型场景：**找回只记得正文片段的网页；统一检索网页、PDF/DOCX/Markdown/Org；让 Claude Desktop/Cursor 查询私人资料；为家庭/小团队做账号隔离索引；把旧浏览历史、稍后读服务或整站文档批量迁入。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 条件 |
|---|---|---|
| [浏览器自动全文索引](https://hister.org/docs/browser-extension) | 扩展提交标题、正文、渲染 HTML、URL、favicon并跟踪 SPA 变化 → 比只存 URL/标题更易找回内容 → 日常阅读/登录后页面 | 需 Chrome/Firefox 扩展和常驻 Server |
| [浏览器历史导入](https://hister.org/docs/browser-ingestion) | 识别主流浏览器历史库，按访问次数/日期筛选，持久任务可恢复 → 将旧历史转知识库 → 首次迁移 | 抓的是页面**当前**内容，不继承登录态、非持续同步 |
| 网页/文件/服务统一搜索 | 搜网页与 PDF、DOCX、Markdown、Org、文本，并增量导入 Linkding/Readeck/wallabag等 → 减少资料散落 → 研究/PKM | 文件格式不及通用桌面检索广 |
| [精确查询 + Facet/建议](https://hister.org/docs/query-language) | 字段、短语、通配、否定、日期/访问范围、别名与多种排序 → 从渐进筛选到精确定位 → 大索引 | v0.18.0 增强建议和 Facet 计数 |

| [可选混合语义检索](https://hister.org/docs/configuration#semantic-search) | 以外部 embedding 向量与关键词结果合并重排 → 不记原词也能找 → 自然语言回忆 | 默认关闭；不内置模型，需 Ollama/llama.cpp/OpenAI-compatible endpoint |
| Web/TUI/CLI/HTTP API | 同一程序提供 Web、响应式 TUI、命令行和 `/api` 文档/JSON搜索 → 人和自动化共用一份索引 → 本地/服务器 | 无正式多语言客户端 SDK |
| [只读 MCP](https://hister.org/docs/mcp) | `search`、`get_preview`、`get_history` 让助手检索、读离线正文和历史 → 私人知识不用重新联网抓 → Claude/Cursor | 无写入/删除/抓取/Agent行动；不是完整 RAG/Agent平台 |
| 离线预览/历史/版本 | 保存压缩 HTML、indexed/opened时间线和页面变化 diff → 搜后直接读快照、审更新 → 政策/文档追踪 | 版本无自动过期 |
| 规则、别名和批量治理 | Skip/Priority/Version/Alias；按查询 dry-run 批改 owner/label/title/language → 控隐私、排序和长期维护 → 大资料库 | 规则需持续维护，旧内容未必追溯生效 |
| 多用户/认证/公共只读 | 用户隔离文档/规则/Token，支持密码、GitHub/Google/OIDC和匿名只读区 → 家庭/小团队共用 → 自托管 | 定位可信小组，非完整企业 IAM |
| 结构化提取 | GitHub/Wikipedia/StackExchange/Mastodon等专用提取；v0.18.0 加 Twitter/Bluesky/Reddit/Discourse → 保留作者、时间、回复等上下文 → 讨论归档 | 站点变化仍可能破坏提取 |

**可用性、同类与缺口：**[v0.18.0](https://github.com/asciimoo/hister/releases/tag/v0.18.0) 是 8 月 23 日稳定版，新增搜索建议/排序、社交提取、文件/服务导入、TUI、批量更新、完整历史和带 output schema/不可信内容标记的 MCP；`rolling` 才是 Dev Build。单二进制 + SQLite 的关键词搜索、Web/CLI/TUI、预览和单页索引开箱可用，官方提供 Docker/Nix、Quickstart 和 [公开 Demo](https://demo.hister.org/)；语义检索、OAuth/OIDC、动态 Crawler、PostgreSQL/pgvector和公网 HTTPS需配置。相比 Khoj，它的浏览器采集、查询语言、Crawler、版本与只读 MCP 更像搜索产品，但没有 Chat/生成/Agent；相比 Recoll，多用户 Web、登录态页面、MCP和版本更强，文件/邮件/压缩包格式更少；相比 Meilisearch，它已带 ingestion/UI，却缺通用 SDK、多索引/水平扩展和更广应用搜索能力。

**限制与今日关注：**“Private”指无强制云与可自托管，不是默认加密；HTML、历史和向量以所选服务器的存储保护为准。扩展会把登录后页面发给该 Server，远程 Embedding会收到文档分块；MCP 标不可信内容也不能消除 Prompt Injection。无自动总容量/版本过期，平均每页约 100 KB；没有一次命令彻底清除所有日志/导出/备份，默认文件监视上限 1 MiB，PDF 不含通用 OCR。核心关键词搜索不依赖 AI，`semantic:true` 在未配置时会退回关键词，因此它只是 AI 基础设施边界项，不能写成“内置 AI 第二大脑”。**事实：**今日快照 #16、+98，稳定 v0.18.0 刚发布；**推断：**local-first/private + MCP + personal search 的组合与密集 Release 共同推动关注，Stars 不等于企业级部署验证。

## 今天最值得体验的 3 个项目

1. **[openai/codex](https://github.com/openai/codex)：先体验结构化 `exec`、Sandbox/审批、专用 Review 与 Subagents。**它把“Agent能改代码”延伸到本地交互、可解析自动化和并行分工，用户价值与风险边界都最容易直接验证。建议从受限 Sandbox 和小仓 Review 开始，不要以 `--yolo` 或第三方高权限 Plugin 作为首体验。
2. **[asciimoo/hister](https://github.com/asciimoo/hister)：体验“关键词默认可用，AI按需外挂”的私有搜索。**单二进制、Web/TUI/CLI、浏览器采集、离线预览和只读 MCP 形成完整闭环；它比“再做一个聊天助手”更具体。先只索引非敏感资料，确认备份/HTTPS/存储策略后再接浏览器登录页或远程 Embedding。
3. **[freestylefly/awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2)：体验成本最低的多模态 Feature 资产。**从 529 个效果图反查 Prompt、套 22 个结构模板，再用 Skill 让 Agent 选型，几分钟内就能判断是否有用。把它当创作参考而非效果 benchmark；出图费用、第三方素材授权和文字准确率仍须单独核验。

若目标是垂直工作流而非通用工具，[AI Job Search](https://github.com/MadsLorentzen/ai-job-search) 是最值得追加试用的一项：它的差异点不在“会写求职信”，而在 Reviewer、PDF/ATS 成品检查和基于真实投递档案的面试准备；代价是 Claude Code/PDF 工具链、隐私管理和偏丹麦数据源。

## 值得持续跟踪的新 Feature 方向

1. **Plugin/Skill 供应链从“能安装”走向“能治理”。**继续观察签名、来源 Pin、权限/数据去向清单、宿主兼容、版本策略、行为 Eval、组织 allowlist 与回滚，而不是只追目录数量。
2. **个人知识库成为只读 Agent Retrieval 层。**Hister、claude-obsidian、OpenHuman分别从搜索、证据账本和长期记忆切入；下一步关键是引用到原文、时间新鲜度、删除传播、Prompt Injection隔离和本地 Embedding可用性。
3. **长任务的恢复语义产品化。**Event Log、Checkpoint、approval-resume 很快会成为 Agent 基础 Feature；应继续核验 exactly-once/at-least-once、工具副作用、版本迁移、人工介入和恢复成本。
4. **垂直 Agent 的验收物取代“聊天看起来不错”。**求职 PDF/ATS、金融 Decision Log、研究证据包、模型 Eval Artifact 都是可查产物；真正有价值的下一步是可靠外部 Grounding、可重复回放和领域风险门禁。
5. **多 Agent 从角色表演走向相关性控制。**Bull/Bear、Reviewer、Risk、Subagent分工容易 Demo，但共享模型、共享数据会产生相关错误；值得跟踪独立证据源、不同模型/工具、冲突保留、聚合准则和成本收益。
6. **样例库需要统一可复现标准。**“可运行”“tested end-to-end”“production-style”应拆成锁版依赖、Smoke、行为 Eval、安全扫描、外部服务 Mock、预期输出和 CI；否则目录增长只会扩大维护债。
7. **开放模型研发继续公开中间过程。**Marin 的数据、配方、运行、失败和评测比只发最终权重更有研究价值；应跟踪可下载产物、真实算力预算、License/数据 provenance，以及 500B+目标与已交付模型的距离。
8. **Coding Agent 规则从 Prompt 软约束走向可测 Policy。**Karpathy Skills/Ponytail 已把最小改动、复用与验证说清；下一阶段应有跨模型行为基准、确定性 Diff/依赖 Gate、任务适用范围和“少代码但稳健性下降”的显式权衡。
