1. **AI/Agent 已占默认 Trending 的绝对多数。** 19 个仓库中 15 个直接以 AI、LLM、Agent、Skills、模型路由、AI 可观测或 AI 教育为一等能力，合计新增 10,358 Stars。榜单不再只偏模型/框架，而是覆盖 Agent runtime、能力分发、垂直工作流和运维产品面。
2. **“常驻个人 Agent”继续从聊天入口扩展为长期执行系统。** Hermes、OpenClaw 与 OpenHuman 都把跨设备入口、记忆、周期任务、工具执行和多 Agent 组合在一起；claude-obsidian 则把长期知识变成用户可读、可改、可追溯的 Markdown/Obsidian 资产。价值是少重复解释，风险是错误记忆、权限扩大和第三方连接器供应链。
3. **模型碎片化催生本地统一入口。** free-claude-code 与 FreeLLMAPI 都强调多 Provider、统一协议、路由与故障切换；Hermes/OpenClaw 也提供多模型和本地端点。它们降低切换与试用成本，但“支持 Provider”不等于每个模型都稳定支持工具调用、图像、长上下文或同等推理质量，“免费额度合计”也不是单用户保证。
4. **Skills/Plugins 正成为 Agent 的新分发层，但资产类型差异巨大。** Karpathy Skills 是一份极短行为指南，Awesome Agent Skills 是发现目录，Claude Plugins Community 是经提交流程同步的市场镜像，AI Engineering From Scratch 则把课程包装成 Tutor Skills。目录数量、安装成功和功能可用不能混为一谈。
5. **垂直 Agent 产品开始强调“可验证产物”。** AI Job Search 不止写求职信，还检查最终 PDF/ATS 文本层并保留申请档案；claude-obsidian 用 provenance ledger、lint 和事务式写入保护知识库；AI Engineering From Scratch 要求每课交付证据。这比泛化“AI 帮你做事”更容易验收。
6. **成熟产品正在把 Agent 放进已有数据闭环。** PostHog 把分析、Session Replay、错误、日志、Feature Flags、实验和 AI 可观测放在同一产品上下文中，再让 Agent 诊断或建议修复。它的老牌分析能力与较新的“self-driving”/AI 能力成熟度不同，不能因产品面宽就默认自动修复可靠。
7. **发布治理仍是采用门槛。** 当天既有 Codex、AI Job Search、Maka、OpenClaw 等可锁定 Release，也有 Karpathy Skills、Claude Plugins Community、Awesome Agent Skills、awesome-gpt-image-2 等无正式 Release 的滚动内容库；采用前应锁 commit/版本、先跑最小 Demo，并为高权限动作保留审批与回滚。

## Feature 深度卡片

### 1. [Alishahryar1/free-claude-code](https://github.com/Alishahryar1/free-claude-code)

**一句话定位：**给希望继续使用 Claude Code、Codex 等熟悉 Coding Agent、又想在免费额度、订阅 API、商业 API 与本地模型之间自由切换的个人开发者，一个带管理界面的本地统一网关和启动器。

**典型场景：**聚合多家免费额度；多个 Coding Agent 共用一份模型配置；限流/故障时回退；用 Ollama/LM Studio 保护代码隐私；从手机文字或语音远程驱动工作站。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 条件 |
|---|---|---|
| [50 个预置 Provider](https://github.com/Alishahryar1/free-claude-code#choose-a-provider) | 在 UI 中配置 NVIDIA NIM、OpenRouter、Groq、OpenAI、Vertex、Bedrock、MiniMax、Kimi、Ollama 等 → 少研究端点/模型 ID → 多供应商试用 | 目录已用；每家账号、额度、地区和 ToS 独立 |
| [9 个 Agent 启动器](https://github.com/Alishahryar1/free-claude-code#run-your-coding-agent) | `fcc-claude/codex/pi/opencode/cline/hermes/dsh/grok/muse` 共用模型目录 → 保留不同 Agent 交互而统一后端 → 多宿主对比 | 已用；宿主自身仍需安装 |
| 一键安装、桌面入口与 Admin UI | macOS/Linux/Windows 安装，搜索/校验/应用模型配置并可启用本地 Bearer Token → 少手写网关配置 → 个人桌面 | 可用；远程脚本应先审阅 |
| 有序 Fallback | 主模型重试耗尽后按顺序切换下一模型 → 限流或免费额度耗尽时提高连续性 → 长任务 | 需配置；可能消耗多家额度，[部分流不回退](https://github.com/Alishahryar1/free-claude-code/issues/1543) |
| 模型档位与推理强度映射 | 把 Fable/Opus/Sonnet/Haiku 档位映射到不同模型，并统一 Off–Max reasoning → 按难度/成本分层 → 轻重任务混跑 | 已用；语义和质量仍取决于具体模型 |
| 流式、工具、Thinking 与图片转接 | 尽量保留 Coding Agent 原生交互 → 换后端不必退化为普通聊天 → 工具调用/视觉编码 | 网关支持不等于任意模型都兼容 |
| IDE/桌面客户端接入 | 提供 VS Code、Codex App、JetBrains ACP 和兼容端点配置 → 不迁移既有编辑器 → 固定 IDE 工作流 | 需逐客户端配置；无正式第三方 SDK |
| 可选 RTK 输出压缩 | 过滤常见终端噪声并将部分探测移出模型调用 → 少占上下文 → 构建/测试日志多的任务 | 可选；“最高减少 90%”是项目方口径，无通用基准 |
| Discord/Telegram 远程入口 | 从指定频道和目录提交、停止、清理任务并看统计 → 离开电脑仍能操作 → 个人远程工作站 | 需 Bot Token、allowlist 与目录权限 |
| 语音笔记转任务 | 以本地 Whisper 或 NVIDIA NIM 转写语音再交给 Agent → 手机上低成本输入长需求 → 移动办公 | 本地转写需模型/CPU/GPU；NIM 需 Key |

**可用性、同类与缺口：**UI、CLI、Agent/IDE 配置和截图齐全，Quick Start 可复现但必须有至少一个 Provider 或本地模型。当前 `pyproject.toml` 为 5.14.5、要求 Python 3.14；[Releases](https://github.com/Alishahryar1/free-claude-code/releases) 和正式 Changelog 为空。相比 Claude Code Router，FCC 更偏“免费额度策展 + 个人桌面/手机/语音”；后者的自定义端点、Credential Pool、条件路由、重写、请求日志和观测更强。相比 LiteLLM，FCC 缺 Virtual Keys、预算/RBAC/SSO/审计等团队治理。

**限制与降噪：**“Free Claude Code”并不免费提供 Anthropic Claude；“1.3B+ free tokens”是项目方对多 Provider 公开额度的合计，非单用户保证；“ToS-friendly”也不是永久法律结论。工具/图片/上下文和推理质量由具体模型决定，公开 Issue 还出现上下文快速占满、NIM 图片失败、Ollama 模型发现等个案。**事实：**今日 #1、+891，功能面已覆盖 Provider、Agent、Fallback、IDE、手机与语音。**推断：**低成本标题、熟悉客户端和一键安装形成极强传播闭环，是上榜的合理原因。

## 今天最值得体验的 3 个项目

1. **[Codex](https://github.com/openai/codex)**：最吸引人的是受控 Sandbox/审批、仓库级 `/review`、Subagents/Skills/Plugins，以及从交互 TUI 到 `codex exec`、SDK 和 CI 的连续路径。它能直接用于真实仓库，也能验证“编码 Agent 平台”而不只是聊天；建议从只读解释或 Review 开始，再逐步开放写入和网络。
2. **[AI Job Search](https://github.com/MadsLorentzen/ai-job-search)**：最值得试的是“职位发现/排序 → 事实约束定制 → Drafter/Reviewer → PDF/ATS 成品核验 → 申请档案/面试”的可验收闭环。它把垂直 Agent 的价值落在最终文件而不是一句好文案；建议先用一份虚构简历和一个公开职位走 Demo，再接邮箱/Notion。
3. **[PostHog](https://github.com/PostHog/posthog)**：最值得看的是 LLM Trace/Eval/Prompt 与真实产品用户、Session Replay、收入、Error、Flag 和实验共享上下文，再经 MCP/PostHog AI 调查。它代表 AI Observability 从“看 Token/延迟”走向业务结果闭环；初试先做只读 Trace 查询，不让 Self-driving 触及生产写权限。

**增长观察：**[awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2) 今日 +2,449 为入选项最高，视觉案例→模板→Agent Skill 的路径非常适合即刻浏览；但因缺版本、复现参数和完整版权链，更适合灵感与 Prompt 起点，而不是可复现生产基线。

## 值得持续跟踪的新 Feature 方向

1. **可验收的垂直 Agent：**继续关注求职 PDF/ATS、知识 Claim Ledger、课程 evidence gate 这类能输出客观检查结果的工作流，而不是只比较生成文本是否“像专家”。
2. **可读、可改、可追溯的长期记忆：**Markdown/Obsidian 可见性正在成为卖点；下一步需看来源、diff、删除、冲突、过期、反证、写入审批和错误记忆修复能否同时成立。
3. **模型路由从 fallback 走向可解释治理：**不仅要支持 Provider，还应暴露真实额度、Key 级预算、能力兼容、数据政策、降级原因和熔断；Catalog 数字需要可复算且及时。
4. **Skill/Plugin 供应链：**目录正在爆发，但条目数不是功能数。固定 commit、权限/外联声明、维护健康、价格、版本、跨宿主 smoke test 与语义 Eval 将成为采用门槛。
5. **Agent 与产品数据闭环：**PostHog 展示了 Trace、Prompt、Eval、Replay、Flag、Experiment、Revenue 同一身份上下文的价值；需继续追踪归因准确性、隐私模式和 AI 调查的漏报/误报。
6. **人可接管的长期执行：**Cron、可恢复 job、Run Inspector、Graph/Canvas 和 approval-resume 正在汇合；关键验证是跨重启状态、幂等、副作用去重、取消、回滚与因果链，而非“能跑很久”。
7. **Computer Use 的能力拆分与权限事实：**Browser、设备命令、OS GUI、Codex-native MCP、外部 driver 常被统一包装为 Computer Use。报告采用者应逐项核对平台、登录态、沙箱、审批和可复现 Demo。
8. **多模态 Prompt 资产的版本与版权：**案例库若要进入生产，需要模型快照、参数、输入参考、授权链、回归样例与失败标签；否则 Gallery 再大也只是高质量灵感目录。
