## 今日 Feature 趋势摘要

1. **Agent 产品正在形成“执行内核—控制面—问责层”三层分工。** Prime Agent 负责持久 RLM、Subagent 和长任务续跑；T3 Code 负责跨 Codex/Claude/Cursor 等本机会话的桌面、Web、移动控制；Paperclip 再向上提供目标、组织、预算、审批和审计；Semantica 则把决策、来源、时间与政策变成可查询证据。用户开始按控制与责任边界选产品，而不只按模型选工具。
2. **Skills/Personas 已成为可安装发行物，但“能复制文件”仍不等于“能运行团队”。** Agency Agents 有 270 个角色、16 个 CLI 目标和独立桌面台账；Agent Skills 有 24 Skills、8 Commands、4 Personas 与三层 Evals；LifeOS 把个人上下文、记忆、路由和技能打成一个 Skill。三者真正的边界都在宿主权限、调度、持久化、更新和兼容，而不是目录数量。
3. **RAG 正从“取一段文本”升级为有结构、有来源、可行动的上下文。** Firecrawl 把实时 Web 搜索、抓取、交互和结构化输出喂给 Agent；Code-Graph-RAG 把代码实体、调用和数据流变成可查改图；Semantica 再补决策、双时态、PROV-O、本体与规则。价值从“回答更多”转向“说明从哪来、影响什么、能否安全修改”。
4. **多模态/垂直模型的 Feature 竞争越来越依赖诚实边界。** WeatherNext 同时交付权重、Colab、数据 Feed 与托管推理；ComfyUI 把图片、视频、音频、3D、文本模型封装为节点图/App/API；RuView 尝试把 Wi-Fi CSI 变成边缘感知。真正重要的是数据许可、硬件、云费用、真实准确率和 Demo 是否使用模拟/摄像头，而不是最长的模型支持列表。
5. **“自治”正在被可停止、可恢复和可审计的控制原语替代。** Heartbeat、schedule、budget hard-stop、approval、quality gate、diff/test evidence、immutable activity 与 human override 在多个项目重复出现。最值得跟踪的不是 Agent 能跑多久，而是失败后是否能停、能解释、能恢复、能把成本归因到任务。
6. **发行面漂移是今天最大的误读来源。** Semantica 正式版后 main 已前进 197 个提交；Firecrawl GitHub Latest Release 与滚动 Cloud/API 文档相隔数百提交；Code-Graph-RAG 已连续打到 v0.0.605 tag，但 GitHub Latest Release/PyPI 仍是 v0.0.589；Agent Skills 的引用修复仍未发；T3 Code 也有 nightly/main 超前。首页 “Latest News” 不能自动回填为稳定可安装能力。
7. **今天最强传播词也最需要降噪。** “Open-source Palantir”“autonomous AI company”“self-improving RLM”“see through walls”“production-grade skills”都准确抓住用户焦虑，但分别不等于合规认证、业务自治、模型自训练、成熟摄像头替代或质量保证。本报告把这些词还原成可操作 Feature 与可复现前提。

## Feature 深度卡片

### 1. [semantica-agi/semantica](https://github.com/semantica-agi/semantica)

**一句话定位：** 给高风险或受监管 Agent、GraphRAG 与企业知识图谱团队使用的自托管上下文/问责层，把数据、决策、因果、时间和来源证据变成可查询图，回答“当时知道什么、为什么这样决定、证据来自哪里”。

**典型场景：** 授信/临床/SOC 决策审计；从合同/法规/数据库构建带来源 GraphRAG；用 OWL/SHACL/SKOS 治理术语与冲突；多 Agent 共享证据图；按历史时点复盘事实修订与决策影响。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **多源采集与 Pipeline** | 文件、Web/RSS、SQL、Git、邮件、MCP、Snowflake/Databricks 进入同一处理链 → 少写 ETL 胶水 → 企业知识库 | 常规路径可用；extras/凭据很多；v0.6.0 `PipelineWithProvenance` 有开放故障 [#858](https://github.com/semantica-agi/semantica/issues/858) |
| **实体/关系/事件抽取** | pattern、spaCy/模型或 LLM 建图 → 离线可起步、复杂领域可增强 → 合同/情报/文献 | 缺模型会降级；v0.6.0 Explorer enrich route 可 503 [#883](https://github.com/semantica-agi/semantica/issues/883) |
| **GraphRAG 切分与检索** | entity/relation/ontology-aware chunking、向量与多跳邻域 → 连接跨文档事实并给检索路径 → 法规/供应链问答 | 2–3 hop 后 token 膨胀；高层 Answer Engine 和独立质量 benchmark 较弱；[指南](https://docs.getsemantica.ai/guides/graphrag/) |
| **Decision Intelligence** | 记录决策、因果链、相似先例、影响、政策与例外 → 把选择从日志变成审计对象 → 授信/风控 | Python/MCP 可用；v0.6.0 Explorer `/api/decisions*` 有 500 故障 [#884](https://github.com/semantica-agi/semantica/issues/884) |
| **W3C PROV-O** | 记录来源位置、抽取方式、操作者、时间、置信度并导出 JSON/CSV/RDF → 结论可反查证据 → 审计/lineage | 能力可用但要求调用方正确打点；“compliance-ready”不是合规认证；[指南](https://docs.getsemantica.ai/guides/provenance/) |
| **确定性推理与政策** | forward/backward、RETE、Datalog、SPARQL 给可解释 premises/steps → 规则可复现 → AML/访问控制 | v0.6.0 RETE matcher 仍有限；生产 gate 要用真实规则回归；[推理](https://docs.getsemantica.ai/guides/reasoning/) |
| **双时态与历史重建** | 区分有效时间/记录时间，做 point-in-time、checkpoint diff、区间关系 → 回答“当时系统知道什么” → 政策/任职/临床 | 已发；时间边界常需调用方提供，部分导出形状需映射 |
| **本体与质量治理** | OWL/SHACL/SKOS、对齐/version/health、冲突检测与 provenance-preserving 去重 → 防矛盾静默覆盖 → 主数据 | SHACL/AI alignment 需 extras/模型；多类冲突路径测试不足 [#865](https://github.com/semantica-agi/semantica/issues/865) |
| **开放存储/导出** | RDF、LPG、向量多后端及 RDF/OWL/JSON-LD/Cypher/Parquet 导出 → 原型可迁移、少锁定 → 企业部署 | “一行切换”不等于操作完全等价；持久向量 metadata/统计有开放问题 |
| **Explorer + CLI/MCP/REST/Agno** | 分析师看图/时间线/本体，开发者与 Agent 用 CLI、12-tool MCP、API → 同一证据多入口 | Explorer/Agno 需 extras；Agno 是唯一原生 toolkit，其余框架 dedicated SDK 仍 Coming Soon；[MCP](https://docs.getsemantica.ai/reference/mcp_server/) |

**开箱、同类与限制：** ContextGraph、基础决策、in-memory/FAISS、规则抽取、基础推理/provenance、CLI/stdio MCP 可本地使用；Explorer、企业源、持久库、GPU/LLM 需安装、账号或费用。相比 Graphiti/Zep，Semantica 强在决策、规则、PROV-O、SHACL/SKOS 与多后端，弱在托管、多租户、权限与实时延迟目标；相比 Microsoft GraphRAG，治理更强但问答产品与 benchmark 更弱。最严重边界是 Web/API/Git ingestion 仍有 SSRF/注入 Issues [#867](https://github.com/semantica-agi/semantica/issues/867)、[#868](https://github.com/semantica-agi/semantica/issues/868)，不要直接处理不可信 URL。v0.6.0 后 main 已前进 197 commits，首页功能和修复不能倒算进稳定包。

**今日关注：** **事实**：MIT、自托管、MCP/UI/CLI 将决策/时间/来源/规则集中到一个产品；今日 #1、+970。**推断**：“Open-source Palantir for AI Agents”与可视 Explorer 很易传播，受监管 Agent 也正需要具体问责工具；未找到单一外部事件能解释热度。来源：[README](https://github.com/semantica-agi/semantica)、[v0.6.0](https://github.com/semantica-agi/semantica/releases/tag/v0.6.0)、[CHANGELOG](https://github.com/semantica-agi/semantica/blob/main/CHANGELOG.md)、[官方文档](https://docs.getsemantica.ai/)。

### 2. [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)

**一句话定位：** 面向不想从空白提示词开始的个人与团队，提供可读、可改、可跨工具安装的专业 Agent 角色与协作 Runbook；它预写“以什么角色、按什么流程、交付什么”，但本身不是 Agent runtime。

**典型场景：** 给 Claude/Codex/Cursor 加专业角色；组建 MVP/企业功能跨职能团队；同一角色规范跨工具迁移；按项目选择 division；在企业 fork 中审查/版本化交付模板。

## 今天最值得体验的 3 个项目

1. **[Prime Agent](https://github.com/PrimeIntellect-ai/prime-agent)：先体验“长任务如何不丢状态”。** 最吸引人的不是 self-improving 标语，而是持久 IPython、递归 Subagent、daemon detach/attach、Persistent Goal、bounded autonomous 与 quality gate 组成的可停止执行闭环。用一个可丢弃仓库做“并行审查→测试门→恢复会话”最能验证价值；不要把它放到无隔离的敏感环境。
2. **[Paperclip](https://github.com/paperclipai/paperclip)：先体验“多个 Agent 如何被管理”。** Goal→Project→Issue、组织图、heartbeat、预算硬停、审批和审计把 Agent 从聊天窗口变成有 owner/cost/sign-off 的工作单元。建议只试稳定核心，暂不把 Alpha Plugin、Experimental Sandbox/MCP 当采购依据。
3. **[WeatherNext](https://github.com/google-deepmind/weathernext)：先体验“前沿垂直模型如何做到可复现”。** Cyclones Mini Colab 把权重下载、推理、可视化和 track 放进免费/低门槛入口，公开 Feed 又能直接观察 64-member 概率集合。它最适合建立“模型输出是研究/辅助信号，不是官方预警”的正确使用感。

## 值得持续跟踪的新 Feature 方向

1. **可问责上下文层：** 从 embedding 命中升级为 source、valid/transaction time、decision、policy、exception 和影响链；重点看 provenance 是否由工具自动保真，而不是只提供字段。
2. **Agent 组织控制面：** Goal/Task/owner、budget hard-stop、secret scope、approval、immutable activity 与恢复将成为长任务基本件；下一步看多租户、SSO/RBAC、跨控制面互操作。
3. **Skill 的能力契约与可移植性矩阵：** 不能再只统计安装目标；应声明宿主是否支持 commands、hooks、Subagent、工具权限、产物和 eval，并对引用/依赖做可安装回归。
4. **确定性 Web 数据与状态式 Browser Agent 分层：** Scrape/Crawl/Map 适合可复现 context，Interact/Agent 适合未知路径；产品需要清楚披露两者的计费、失败恢复、登录态与自托管差异。
5. **物理感知变成 Agent 工具：** Wi-Fi、天气等现实信号经 API/MCP 进入自动化很有价值，但必须同时发布 ground truth、场景外失效、模拟数据占比、硬件/数据许可和 human override。
6. **垂直多 Agent 的时间与账本语义：** 金融/安全/医疗不能只靠更多角色辩论；需要严格 observation cutoff、组合/状态账本、证据引用、回放与可比较 eval。
7. **Release Surface Manifest：** 当 Stable tag、未发 main、Cloud、Preview、付费节点和路线图同时存在，项目应机器可读地标出 Feature 从“宣布”到“可安装/默认开启/支持”的状态，减少首页能力漂移。
