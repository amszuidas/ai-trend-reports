## 今日 Feature 趋势摘要

1. **Agent 能力正在以可安装、跨宿主的 Skill/工作区套件交付。** ECC 把 agents、skills、rules、hooks、memory 与安全扫描打包；book-to-skill 把长文档编译成按需加载的 Agent Skill；Claude Video 把下载、字幕、帧抽取和视频问答封装成 `/watch`。
2. **确定性治理开始补上“只靠 Prompt 要求 Agent 自律”的缺口。** Agent Governance Toolkit 把工具调用放进策略、审批、身份、审计与 kill switch；ECC 的 AgentShield、规则和验证工作流则更贴近 Coding Agent 工作区。
3. **实时语音 Agent 的可用形态正在分化。** Hugging Face speech-to-speech 提供可替换的 VAD/STT/LLM/TTS 与 OpenAI Realtime 兼容服务，偏开发者基础设施；AIRI 则把语音、Avatar、角色卡、聊天渠道和游戏连接整合成可直接体验的虚拟角色应用。
4. **Provider 与协议兼容成为降低锁定的重要 Feature。** aisuite 用统一 Chat Completions/Agents API 切换模型供应商并接 MCP；speech-to-speech 让 LLM 插槽对接 OpenAI-compatible 服务；这些兼容层降低迁移成本，但不能抹平各 Provider 的参数、流式与工具调用差异。
5. **MCP 正把传统垂直软件变成 Agent 可调用的数据工具。** free-stockdb 的主体仍是 A 股本地量化引擎，但已把本地行情、指标与回测暴露成 MCP；它说明今日的“AI 基础设施”不只来自模型或 Agent 框架，也来自可被 Agent 安全、稳定调用的专业数据面。
6. **“零配置”“任意视频”“无幻觉”等强宣传仍需降级阅读。** 本地语音依赖模型、硬件与系统库；视频 Skill 只看到抽样帧与转写；文档转 Skill 能加强来源约束但不能数学保证零幻觉；跨 50+ 宿主通常表示格式可安装，不代表逐宿主同等验证。

## Feature 深度卡片

### 1. [AIRI](https://github.com/moeru-ai/airi)

**一句话定位：** 面向 AI 伴侣、桌宠和 AI VTuber 用户/创作者的自托管虚拟角色产品，把多模型对话、实时语音、Live2D/Spine/VRM 角色舞台、视觉、MCP、社交通道与游戏交互放进跨端角色容器。

**典型场景：** 桌面常驻语音伴侣；导入美术资源快速制作 AI VTuber/角色原型；在云模型与本地模型间切换；让角色感知屏幕并调用 MCP/搜索/图像工具；接入社群或 Minecraft/Factorio 做游戏 Agent 实验。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **跨端角色舞台与桌宠** | Web/PWA 可试，正式版有 Windows/macOS/Linux、Android APK、iOS IPA；桌面含托盘、置顶、自动隐藏/点击穿透、拖动和缩放 → 不必自建角色 UI → 桌宠/陪伴/直播预演 | **主链可用**；真实对话仍需模型。移动资产存在但文档与物理设备验证弱于桌面，[v0.11.3](https://github.com/moeru-ai/airi/releases/tag/v0.11.3) |
| **角色卡与可携带角色包** | 保存人设、场景、提示词和模块选择，并把受支持显示模型一起打成 AIRI `.zip` 导入/导出 → 分享的不只是一段 prompt → 角色迁移/社区创作 | **正式版可用**；裸 `.json` 不再是主要导入路径，[Character Card V3](https://airi.moeru.ai/docs/en/docs/manual/tamagotchi/character-card-template/) |
| **多 Provider、云/本地混用** | 连接 OpenAI/Azure、Anthropic、Gemini、DeepSeek、OpenRouter、Bedrock、Ollama、vLLM、SGLang、LM Studio 等 → 在效果、隐私、成本间切换 → 私有/云模型混用 | **需 Key、端点或本地算力**；Provider 能力不等价；纯浏览器 WebGPU LLM 仍未完成，[清单](https://github.com/moeru-ai/airi#support-of-llm-api-providers-powered-by-xsai) |
| **双向实时语音** | 麦克风、STT、说话检测、TTS、音色测试和停止朗读；正式版会缓冲短转写并避免自身语音回灌 → 更接近免手陪伴 → 桌面角色/直播 | **配置后可用**；依语音服务、权限、语言和费用，[语音文档](https://airi.moeru.ai/docs/zh-Hans/docs/manual/config/audio/) |
| **Live2D / Spine / VRM / Tachie** | 控制 2D/3D 模型的位置、相机、注视、表情、动作和部分口型；Tachie 用九类情绪立绘降低美术门槛 → 从静态立绘到完整 3D 均可选 → 桌宠/VTuber | Live2D/Spine/VRM **正式可用**；Godot Stage **实验性**；Tachie 仅 7 月 28 日合入 `main`、尚未 Release，[PR #2115](https://github.com/moeru-ai/airi/pull/2115) |
| **持久语音静音** | 一键终止当前与排队 TTS，后续保持静音但保留动作、表情和插件信号，设置跨页面保持 → 办公/会议时能安静使用角色 → 日常常驻 | 7 月 28 日合入 `main`，**未进入 v0.11.3**；Pocket 共享实现但未完成物理设备手测，[PR #2128](https://github.com/moeru-ai/airi/pull/2128) |
| **视觉与 Computer Use 基础** | 捕获窗口/屏幕交给视觉模型；已有桌面观察、overlay、DOM-aware 动作和只读 DOM 检查基础 → 从围绕界面聊天推进到初步行动 → 屏幕讲解/UI 协助 | 视觉入口**开发者向**，需屏幕权限与视觉模型；Computer Use 明确为 **experimental foundation**，不能称稳定电脑 Agent，[视觉文档](https://airi.moeru.ai/docs/zh-Hans/docs/manual/config/vision/) |
| **MCP、插件与 Gamelet** | MCP UI 可编辑 JSON、测试、启停 server；插件提供工具、Bindings、Widget/Gamelet → 不改本体即可扩展角色 → 私有工具/互动小应用 | MCP UI **已发布**；需可信 server、命令和环境变量，权限风险自理；插件 API 仍早期，[v0.10.2](https://github.com/moeru-ai/airi/releases/tag/v0.10.2) |

| **社交通道与游戏 Agent** | Discord/Telegram 让角色进入群聊/语音；Minecraft 执行动作，Factorio 连接外部服务 → 从单机角色走向社群与环境行动 → 机器人/陪玩研究 | **需源码部署和平台/游戏凭据**；Minecraft 准备迁移运行时，Factorio 为 WIP/PoC，KSP/Helldivers 2 不可算成品，[集成文档](https://github.com/moeru-ai/airi/tree/main/docs/content/zh-Hans/docs/integrations) |

**开箱与依赖：** Web Demo、桌面壳、角色窗口、设置 UI、导入/预览和安装包可直接体验；LLM、STT/TTS、视觉、MCP、搜索、Artistry、社交与游戏均需配置。AIRI 本体开源，但云模型、语音、搜索和图像服务可能付费；Ollama、Kokoro、ComfyUI 等可本地化，代价是硬件与运维。

**同类差异与易用性：** 相较 [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber)，AIRI 强在 Web/桌面/移动入口、多 Avatar 格式、角色包、MCP UI、社交和游戏的组合，弱在完整离线、成熟语音打断与长期记忆；相较 [SillyTavern](https://github.com/SillyTavern/SillyTavern)，它更像具身跨端角色，但缺成熟 Lorebook/RAG、群聊和扩展生态。在线 Demo、集中 UI、包管理安装、角色卡模板与集成指南是强易用性信号；高级插件仍偏 SDK/源码用户，没有成熟扩展商店。

**限制与今日关注原因：** “Self-hosted/you-owned”不等于所有能力离线免费；浏览器数据库不等于长期记忆已完成；移动端、Computer Use 与游戏能力易被下载资产和 README 勾选放大。事实：最新正式版仍为 `v0.11.3`，相较昨日无新 Release；昨日后 `main` 新增持久静音与 Tachie，并增加容器 provenance/SBOM 元数据。推断：可视、可听、会动的 Demo，多平台安装，以及“用户自有角色 + MCP + 游戏”的组合持续带来传播。

### 2. [aisuite](https://github.com/andrewyng/aisuite)

**一句话定位：** 面向希望用一套近似 OpenAI Chat Completions 调用切换多家模型、再加工具循环与轻量 Agent harness 的 Python 开发者；它降低供应商切换和样板代码，但不是完整 LLM Gateway 或可视化工作流平台。

**典型场景：** 用同一评测/业务代码横向比较模型；为聊天应用加入 Python 工具循环；做可审批、可恢复的代码库助手；把现有 MCP server 接到不同模型；用 Ollama/LM Studio 或 OpenAI-compatible 服务开发本地模型应用。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **统一 Chat Completions** | 以 `<provider>:<model>` 路由并统一常用请求/响应 → 换模型通常只改字符串 → 模型对比/供应商迁移 | **PyPI 稳定包可用**；多数 Provider SDK 需对应 extra 与 Key，[Quickstart](https://github.com/andrewyng/aisuite/blob/main/docs/chat-completions-quickstart.md) |
| **多 Provider 与本地模型** | `main` 可见约 28 个 adapter，覆盖主要云厂商、聚合服务、Ollama/LM Studio → 在质量、成本、隐私间选择 → 多模型产品 | **配置后可用**；各家对参数、流式、图像和工具的支持并不相同 |
| **常用参数/响应归一** | 尽量映射 `temperature`、`max_tokens`、`tools` 等并统一 message 读取 → 少写适配层 → 共享业务逻辑 | **稳定包可用但只覆盖共同子集**；项目并不承诺标准化所有 Provider 参数，[Issue #225](https://github.com/andrewyng/aisuite/issues/225) |
| **同步、异步与流式** | `create/acreate`、`stream=True` 返回统一 chunk，工具调用也能流式输出 → 适合 UI 与并发服务 → 聊天/API | 异步与 Chat streaming **仅 `main`、PyPI 未发布**；流式不能与自动 `max_turns` 同用，[PR #358](https://github.com/andrewyng/aisuite/pull/358) |
| **Python 函数工具 + `max_turns`** | 从函数签名/docstring 生成 schema，自动执行并回填，或让应用手动处理 tool call → 快速得到有限轮 Agent → 查询/业务动作 | **稳定包可用**；依赖模型 tool calling；Groq/Ollama 自动循环有 [Issue #369](https://github.com/andrewyng/aisuite/issues/369)，plain install 工具路径有 [#329](https://github.com/andrewyng/aisuite/issues/329) |
| **`Agent` + `Runner`** | 声明名称、模型、指令和工具，再管理执行、继续运行与结果 → 从一次性调用升级到结构化任务 → repo 助手 | **仅 `main`，PyPI 0.1.14 不含 `aisuite/agents`**；尚未稳定发包，[Agents Quickstart](https://github.com/andrewyng/aisuite/blob/main/docs/agents-quickstart.md) |
| **Files / Git / Shell toolkits** | 挂载文件读取/补丁、只读 Git、受限 shell → 快速给 Agent 本地工作能力 → 代码/文件任务 | **仅 `main`**；所谓 sandbox 主要是路径、只读默认和命令校验，不是容器/VM 强隔离 |
| **Tool policy / 人工审批** | allow/deny、`RequireApprovalPolicy` 或自定义回调在执行前放行 → 控制副作用 → 有写入/外发动作的 Agent | **仅 `main`**；需应用自己提供审批 UI/回调，不是完整输入输出 guardrail |
| **MCP client** | inline MCP 配置或显式 `MCPClient` 复用连接、过滤工具、加前缀 → 让多模型复用企业工具 → 内部 Agent | **稳定包可用**但需 `aisuite[mcp]`、外部 server/runtime/凭据；第三方 server 安全自理，[示例](https://github.com/andrewyng/aisuite/tree/main/examples) |
| **状态持久化/恢复** | 内存、文件或 Postgres store 配合 `thread_id` 保存/继续会话 → 跨进程少丢上下文 → 聊天/中等长度任务 | **仅 `main`**；Postgres 需 extra；不是步骤级 durable execution、自动重试或灾难恢复 |
| **Artifacts、Tracing 与 Viewer** | 记录步骤、原始响应、tool/policy 事件和产物，本地 Viewer/Notebook 可复盘 → 调试与审计更直观 → Agent 开发 | **仅 `main`**；不是托管观测/评测平台；`aisuite-code` CLI 是独立子包，不在稳定主安装路径 |

**版本与依赖边界：** PyPI 最新仍为 `0.1.14`（2025-11-25），稳定 wheel 主要交付统一同步 Chat、Provider adapters、`max_turns` 工具循环和 MCP；README 展示的 Agents、toolkits、policy、state/artifacts/tracing/viewer、async 与 Chat streaming 是 2026 年合入 `main` 的未发包能力。库本身 MIT；云模型、托管 MCP/Postgres 可能付费，本地 Ollama 仍需硬件与服务。

**同类差异与易用性：** 相较 [LiteLLM](https://docs.litellm.ai/)，aisuite 更轻、更适合嵌入 Python 应用并自己掌控 harness，但缺 Proxy/Gateway、路由/回退、虚拟 Key、预算/成本、限流和管理 UI；相较 [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/) 或 [PydanticAI](https://pydantic.dev/docs/ai/overview/)，它强在 Chat 层的多 Provider 与简单本地 toolkits，弱在结构化输出、handoff/多 Agent、guardrails、评测和生产观测。SDK、Quickstart、Provider guides、Notebook、MCP/Agent 示例和本地 Viewer 齐，但主分文档与稳定包不同步，JS/TS 能力也明显窄于 Python。

**限制与今日关注原因：** “换一个字符串”只对共同子集成立；`max_turns` 只是有限工具循环；toolkit 的应用层范围约束不能替代最小权限与强隔离。OpenWorker 已通过 [PR #384](https://github.com/andrewyng/aisuite/pull/384) 迁到独立仓库，其桌面 UI、Slack/邮件连接器、PDF/文档和定时自动化不能算 aisuite SDK Feature。事实：`main` 近期集中加入 Agent harness 能力并把 OpenWorker 迁出。推断：Andrew Ng 背书、OpenWorker 的反向曝光，以及轻量多模型 + MCP 组合共同推动今日关注。

| **Function/Tool Calling** | 客户端声明工具，服务发调用参数，客户端执行回填后再让 Agent 口头总结 → 从聊天升级为搜索、控制设备和业务 API → 机器人/助手 | 核心流程**可用**；本地模型需能稳定生成可解析调用；不是内置 MCP client/工具市场 |
| **多语言与按轮切换** | Parakeet、Whisper、Paraformer、Qwen3-TTS 等按组合覆盖多语言，`language auto` 可按轮检测并提示 LLM 同语回答 → 一套服务面向多语用户 → 跨语言/中文助手 | **需三段能力匹配**；默认仍是英语；Transformers Whisper 非英语检测有开放 [Issue #375](https://github.com/huggingface/speech-to-speech/issues/375) |
| **多声音与有限 Voice Cloning** | Qwen3/Kokoro/ChatTTS/MMS/Pocket 提供不同音色，Pocket 可用自定义语音文件/HF 路径 → 角色/品牌声音可选 → 机器人/角色助手 | 预设与 Pocket cloning **可用**；Qwen3 参考音频 cloning/UI 仍是 Draft [PR #371](https://github.com/huggingface/speech-to-speech/pull/371)，不可算发布 |
| **平台感知加速** | Linux/非 macOS 默认 Qwen3 GGML，Apple Silicon 自动走 MLX；`--local_mac_optimal_settings` 一次配置 MPS/Parakeet/MLX-LM/Qwen3 → 少手配参数 → Mac 本地体验 | **可用但依赖敏感**：Linux 默认 wheel 对准 CUDA 12.8；其他 CUDA/CPU 需匹配 wheel；Apple Silicon 并发有 [Issue #377](https://github.com/huggingface/speech-to-speech/issues/377) |
| **并发 Pipeline Pool** | `--num_pipelines` 预建多个单元，一会话占一个 → 从单用户 demo 到有限并发 → 小规模服务/机器人 fleet | `v0.2.10` 起**可用**；复制模型/资源，未提供 autoscaling、队列、容量规划或可观测平台 |
| **浏览器 Demo 与 WebRTC** | Demo 有动态 orb、转写/聊天、voice、摄像头/搜索工具；`main` 新增 GA 风格 WebRTC SDP endpoint → 更容易验证真实交互 → 浏览器产品原型 | Demo 需单独部署；WebRTC **晚于 PyPI 0.2.11 合入 `main`**，当前须源码 + `[webrtc]`，公网还需 STUN/TURN，[Demo](https://github.com/huggingface/speech-to-speech/blob/main/demo/README.md) |

**开箱、依赖与成熟度：** `pip install speech-to-speech` 后已有 Silero、默认 Parakeet、Qwen3-TTS、Realtime WebSocket、本机/裸 WebSocket/TCP 和基础中断/工具事件，但默认还需 OpenAI Key、模型权重下载，Linux 可能先处理 CUDA wheel。PyPI 当前标为 **Alpha**；GitHub Latest 仍是 `v0.2.10`，PyPI 已到 `0.2.11`。外部 LLM、HF/OpenRouter 等可能付费；真正全本地需要本机模型服务与足够算力。

**同类差异与易用性：** 相较 [Pipecat](https://docs.pipecat.ai/overview/introduction)，本项目更像“一条命令启动的开源模型 Realtime server”，端点替换简单，但缺其 100+ 服务、客户端 SDK、电话/WebRTC/流程/部署生态；相较 [LiveKit Agents](https://docs.livekit.io/agents/)，本地模型与兼容端点更直接，但缺成熟 room/media network、移动端 starter、SIP、托管部署和观测。强信号是 CLI、详尽后端表、OpenAI SDK 示例、Python listen/play、浏览器 Demo、Reachy 指南与 Docker 示例；没有独立客户端 SDK、生产 SLO 或兼容测试矩阵。

**限制与今日关注原因：** 名字是级联 VAD→STT→LLM→TTS，不是原生 audio-to-audio；“低延迟”无跨平台 P50/P95；默认 Qwen3 TTS 甚至配置为非流式合成；多语言、工具、并发和许可证都取决于组合。Markdown 被 TTS 读出、Qwen GGML 能力缺口、diarization 未实现等问题仍开放。项目方称其后端运行于数千台 Reachy Mini，可作为真实应用信号，但没有公开流量/SLO，不能外推为任意企业场景成熟。事实：7 月 17 日发 PyPI 0.2.11，7 月 20 日 `main` 合入 WebRTC，近期 PR 活跃。推断：本地隐私 + 熟悉协议 + Reachy 实例共同推动今日热度。

### 6. [book-to-skill](https://github.com/virgiliojr94/book-to-skill)

**CLI、引用与隐私边界：** `pip install book-to-skill` 的 standalone CLI **只做文本抽取/诊断，不注册 Skill、也不生成完整知识包**；完整转换必须把仓库装进 Agent Skill 目录。产物有章级/主题定位，但没有逐条页码、原句哈希或可点击原文引文；临时 `full_text.txt` 最后会清理。宿主格式 validator 与未发布的注入扫描都不验证“摘要是否忠于原文”。本地抽取不代表全链路离线：云宿主模型仍可能接触敏感文档。用户还需拥有处理/生成衍生知识包的版权权限。

**限制与今日关注原因：** “No hallucination”只能理解为用实际副本降低训练记忆和盲猜风险；抽取、切章、蒸馏、fold-in 与最终回答仍会错。当前 [Issue #81](https://github.com/virgiliojr94/book-to-skill/issues/81) 显示 `SOURCE` banner 可被误作标题并破坏 fallback 章节计数；非英语标题仍有缺口。`v1.2.0` 是 6 月版本，`master` 的安全加固不能写成正式版已得。事实：不到三个月快速迭代到可安装包、多格式抽取和三宿主。推断：Agent Skills 标准扩张、价值叙事直观，以及高传播性的 token/$ 数字共同推动今日 +423。

### 7. [Agent Governance Toolkit](https://github.com/microsoft/agent-governance-toolkit)

**一句话定位：** 面向把自主 Agent 投入生产的平台、安全与合规团队，在 Agent 调工具、发消息、委派任务或执行代码之前加入确定性策略门禁，并补上身份、审计、权限与可靠性控制；它治理“被允许做什么”，不是替模型判断“想得对不对”。

**典型场景：** 高风险工具调用审批；多 Agent 零信任身份与受限委派；MCP 工具上线前扫描和运行时门禁；权限环、Saga 与 Kill Switch 限制失控影响；在 CI 做 policy lint、OWASP evidence、red-team、SLO/chaos 门禁。

|---|---|---|
| **Policy-as-Code 与审批** | `govern()` 用 YAML/程序规则/OPA/Cedar 在工具调用前 allow/deny/escalate，可接 callback/webhook/quorum → 不再只靠 Prompt 自律 → 发布、转账、外发、删库 | 核心**可用**；生产需显式策略、审批队列和回调；未配 handler/超时/异常默认拒绝，[Quickstart](https://github.com/microsoft/agent-governance-toolkit#quick-start) |
| **零信任身份与受限委派** | DID/Ed25519、短时能力凭证、轮换/撤销、信任评分、human sponsor，子 Agent 权限只能是父的子集 → 可追责且限制横向扩权 → 多 Agent/企业身份 | 基础 SDK**可用但需密钥/注册表/存储**；Entra/SPIFFE 等需外部服务，语言实现不完全一致 |
| **可验证审计/Decision BOM** | 记录策略、身份、工具、审批者与 trace，支持 JSONL/CloudEvents/OTel、多 sink、hash/Merkle proof → 事故复盘有可关联证据 → SOC/合规 | 本地**可用**；生产需外部 WORM/SIEM。Tamper-evident 不等于不可删除，审计也不证明外部动作成功 |

| **MCP Security Gateway/Scanner** | 运行时做工具策略、限流、审批、审计与响应 DLP；`mcp-scan` 查 poisoning、隐藏指令、Schema abuse、typosquat/rug pull，支持 live stdio/HTTP/SSE、fingerprint 和 CI → 双向保护 Agent/MCP → 接入评审 | Gateway/Scanner**有实现**；完整 1.0 Spec 仍 **Draft**，许多条目只是规范。MCP `2026-07-28` dual-stack 迁移 [#3130](https://github.com/microsoft/agent-governance-toolkit/issues/3130)/[#3131](https://github.com/microsoft/agent-governance-toolkit/issues/3131) 仍 Open |
| **OWASP/合规/Red-Team CLI** | `agt verify/lint-policy/red-team` 检查 evidence、策略、12 类 prompt 防御和内置 playbook，输出 grade/JSON/exit code → 把最低线前移到 CI → 合规/安全门禁 | CLI**可用**；“10/10 OWASP”是内部映射非认证，基础 verify 很大程度检查 import/组件存在，需 `--evidence --strict` 才更接近部署核验 |
| **五语言 SDK/框架适配** | Python、TS、.NET、Rust、Go 提供核心 policy/identity/audit/MCP/rings/SLO；Python 接 LangGraph/CrewAI/AutoGen/OpenAI Agents 等 → 混合技术栈可复用概念 → 企业平台 | **不完全 parity**；Dashboard/统一 CLI/verifier/多数 adapter 为 Python-only，包版本也不同步，必须组合测试 |
| **Dashboard 与 OTel** | Streamlit fleet、信任热图、allow/deny/escalate feed，另有 EventBus、Prometheus/Grafana/OTel → 平台/安全共享可视状态 → 运营大盘 | 默认 Dashboard 使用**模拟数据**；live 版只是 starting point。统一 Studio 仍 [2/32 路线图](https://github.com/microsoft/agent-governance-toolkit/issues/2729)，且设计只读 |
| **Shadow AI Discovery** | 扫本机进程、配置和仓库里的 Agent/MCP 痕迹，生成 inventory、owner/orphan、risk score → 先知道组织里有什么 → 资产盘点/孤儿清理 | 基础 scanner**可用**；不等于企业全网发现，深度 heuristic/integration 仍 Roadmap |
| **v4.x 包整合与迁移** | `[full]` 一次安装，legacy stub/重导出给旧 `agent-os`/agentmesh 用户迁移窗口；v4.1 加签名、动态策略、CrewAI 修复 → 降迁移摩擦 → 老项目升级 | 文档对 v4.0/v4.1 归属不一致；base wheel 不含 quickstart 模块；main 已写 5.0 但无 Release，按 **v4.1.0** 评估，[Release](https://github.com/microsoft/agent-governance-toolkit/releases/tag/v4.1.0) |

**开箱、依赖与成熟度：** 仓库与发行版整体明确是 **Public Preview**，即使部分包页写 Stable，也应以 Preview 为成熟度上限。最容易复现的是 `govern()` + strict YAML、`mcp-scan --static-only`、`agt verify --evidence --strict`。Azure Entra/ACA、SIEM/OTel、Slack/PagerDuty 等需外部服务；核心 MIT。Python 功能最全，其他语言不应只凭“有同名基元”判断等价。

**同类差异与易用性：** 相较 NeMo Guardrails/Guardrails AI，AGT 强在工具调用前动作门禁、身份、委派、权限环、Kill Switch 与 SRE；弱在对话轨道、结构化输出与 re-prompt。相较 LiteLLM/Portkey，它治理 tool/Agent 权限，但不做模型路由、缓存、prompt 管理和成熟 gateway 成本优化；相较 OPA/Cedar，它提供 Agent/MCP 领域封装，但底层通用 PDP 更成熟。CLI、五语言 SDK、YAML/OPA/Cedar 模板、框架示例、教程与 OTel 集成丰富；统一 UI/托管 control plane 仍缺失。

**限制与今日关注原因：** 门禁只覆盖正确接入的 intervention point；漏装 middleware/未加载策略可能 fail-open。公开 [#3297](https://github.com/microsoft/agent-governance-toolkit/issues/3297) 和 [#3137](https://github.com/microsoft/agent-governance-toolkit/issues/3137) 仍记录缺字段/策略 contract 的 fail-open 风险；关键 deny 规则必须做对抗回归。它不验证推理真实性、业务结果或跨 session 组合攻击。事实：当前正式版 v4.1.0、当日仍活跃；MCP scanner/gateway、policy 与 SRE 均有可运行路径。推断：企业 Agent 上线焦虑、MCP 安全热点、Microsoft 品牌和“两行 govern”叙事共同推动关注，但宽愿景不等于各模块同等成熟。

### 8. [Claude Video / `/watch`](https://github.com/bradautomates/claude-video)

|---|---|---|
| **公开 URL + 本地文件** | `/watch URL-or-path question` 接 `yt-dlp` 公网站点和 `.mp4/.mov/.mkv/.webm` → 少手工下载/截图/抄字幕 → 内容研究/支持录屏 | **已发布**；需 Python、yt-dlp、ffmpeg/ffprobe、宿主 Shell/网络/读图。登录、Cookie、DRM、地区/网络限制不在“any video”内 |
| **字幕优先、按需下载** | 先拉原生/自动字幕；`transcript` 有字幕时不下视频 → 最快最低成本粗读 → 播客/访谈/课程 | **已发布**；实现固定 `en.*`，并非自动利用任意语言字幕；原始语言支持 [PR #75](https://github.com/bradautomates/claude-video/pull/75) 尚未合入 |
| **Whisper 回退/长音频分块** | 无字幕或本地文件时提取音频，发 Groq `whisper-large-v3` 或 OpenAI `whisper-1`，超 25 MB 切块并容忍部分失败 → 无字幕也有时间戳文本 → 本地录屏/长访谈 | **需外部 Key/网络/额度，可能付费**；`--no-whisper` 可禁止外发但退化为仅画面；无本地 Whisper |
| **画面 + 字幕证据包** | 输出 JPEG 路径、`t=MM:SS`、选帧原因和转写供 Agent 读取 → 回答可回到具体时刻核查 → UI/代码/幻灯片 | **已发布**；本质是稀疏静帧 + 文本，不是原生连续视频理解 |
| **四档 Detail** | transcript、efficient 关键帧≤50、balanced 场景帧≤100、token-burner 不封顶 → 自主权衡速度/视觉覆盖/token → 快扫/默认/高保真 | `v0.2.0` **可用**；token-burner 可能产生数百帧和高成本，[实测](https://github.com/bradautomates/claude-video#detail-modes--measured) |
| **场景/关键帧 + 均匀回退** | 低成本关键帧或场景变化候选，不足时按时长均匀采样，封顶时覆盖全时间轴 → 比固定间隔更易抓转场 → 录屏/演示 | **已发布**；场景感知不等于动作/语义理解；新版 ffmpeg 风险会让所有画面模式零帧 |
| **Focus 时间窗** | `--start/--end` 把帧预算和字幕集中到指定区间 → 长片二次钻取更密、成本更低 → Bug 瞬间/开场 | **已发布**；最高仍 2 fps，受 detail 上限 |
| **Transcript-cue 定点帧** | `--timestamps` 强抓绝对时刻，可叠普通抽帧或在 transcript 模式只抓 cue → 捕捉“看这里”但场景不变的瞬间 → 教程/Demo | **已发布**；通常需先读字幕再二次运行；与同一 out-dir 组合有删源风险 |
| **帧预算/分辨率/FPS** | `--max-frames`、512/1024 宽、`--fps` 控制图像量与小字可读性 → 把上下文花在更多时间点或更清晰单帧 → 代码/终端 | **已发布**；1024 约显著增 token；2 fps 是硬上限，快速动作无逐帧逃生口 |
| **近重复去帧** | 16×16 灰度亮度差丢弃近似帧，可 `--no-dedup` → 静止课件不重复计费 → 低动态长视频 | `v0.2.0` **默认开启**；不是语义/perceptual 去重，低对比小变化可能误判 |
| **跨宿主分发/首跑检查** | Claude Marketplace、`npx skills add`、claude.ai bundle、手动安装；首跑查依赖与 Key → 沿用现有 Agent 宿主 → 快速试用 | **已发布**；“50+ hosts”是安装覆盖，不保证各宿主网络、Shell、读图权限；项目无独立 UI/API/SDK |

**开箱与依赖：** 最接近零配置的是已装 Skill + 系统依赖 + 匿名可访问且带英语字幕的 URL；无字幕路径需 Groq/OpenAI Key。原始视频不会发到 Whisper 服务，但无字幕时音频会；JPEG、音频、转写留在本地工作目录。`--out-dir` 是工作目录，不是按 URL/哈希管理的安全缓存或跨会话视频库。

**同类差异与易用性：** 相较功能 fork [pheistman/claude-watch](https://github.com/pheistman/claude-watch)，本项目强在四档 Detail、定点帧、默认去重、Focus、分辨率/帧数和跨 Agent 安装；对方强在更多 STT 供应商与长音频 Provider 策略。两者都缺独立 GUI、HTTP API/SDK、鉴权视频、真正连续动作理解、跨视频检索和生产批处理。单命令入口、49 分钟视频的速度/token 实测、自包含 Skill、CHANGELOG 和 pytest 是易用性信号，但仓库没有持续测试 workflow。

**限制与今日关注原因：** 长视频在 capped 模式会稀疏；音乐、语气、瞬时动作会丢；站点下载还受 `curl_cffi`/Deno/沙箱影响。严重风险仍未修：新 ffmpeg 移除 `-vsync vfr` 后画面模式可能零帧，[#99](https://github.com/bradautomates/claude-video/issues/99)/[#101](https://github.com/bradautomates/claude-video/issues/101) 与修复 [#102](https://github.com/bradautomates/claude-video/pull/102)/[#103](https://github.com/bradautomates/claude-video/pull/103) 均未合并；若源视频位于同一 `--out-dir`，重跑会先清目录并删源文件，[#80](https://github.com/bradautomates/claude-video/issues/80) 仍 Open。事实：今天无 Release/main 提交，最新仍 `v0.2.0`；昨日后只多了未合并兼容/字幕修复 PR。推断：价值直观的单命令 Demo、录屏诊断和跨宿主安装推动 +988，但热度也正暴露跨平台成熟度问题。

### 矩阵结论

- **终端用户最容易看到价值的是 AIRI 与 Claude Video**：前者有完整角色体验，后者把视频转成 Agent 当前就能读取的证据；但前者的未来能力很多，后者的兼容性问题最值得先做小样验证。
- **开发者最快接入的是 aisuite 与 speech-to-speech**：它们分别把多模型 Chat 和实时语音端点做成熟悉接口；真正生产化时，仍需自己补供应商差异、权限、SLO 与故障恢复。
- **团队级复用更偏 ECC 与 book-to-skill**：两者都把“Agent 应如何工作/知道什么”封装为可版本控制的 Skill，但不能把模板约束当成功能质量或事实正确性的证明。
- **治理与垂直数据面是互补层**：Agent Governance Toolkit 控制 Agent 可以调用什么，free-stockdb 则展示专业数据如何通过 MCP 被调用；前者不能替代底层 sandbox，后者也不能因有 MCP 就被视为完整 AI 产品。

## 今天最值得体验的 3 个项目

1. **[speech-to-speech](https://github.com/huggingface/speech-to-speech)：最适合做“端点替换”小实验。** 最吸引人的 Feature 是 OpenAI Realtime 兼容服务与可替换 VAD/STT/LLM/TTS：已有 Realtime 客户端可以较低成本换成部分本地后端。建议先跑 WebSocket + 单一语言短对话，实测首字/首音频延迟、打断和工具事件；默认 LLM 仍走 OpenAI，不能把默认配置误写成全本地。
2. **[book-to-skill](https://github.com/virgiliojr94/book-to-skill)：最适合验证“知识是否能变成工作流资产”。** 最吸引人的是框架/反模式/cheatsheet 的分层产物与增量 fold-in。用一本你熟悉且有文本层的短技术书做样本，把生成章节逐项对照原文；这样既能看到按需加载价值，也能直观识别缺页级引用和模型重构的风险。
3. **[Agent Governance Toolkit](https://github.com/microsoft/agent-governance-toolkit)：最适合安全/平台团队做门禁 PoC。** 最吸引人的是 `govern()` 的确定性动作前策略、`mcp-scan` 与 `agt verify --evidence --strict`。选一个有副作用的测试工具，写一条必须拒绝和一条必须审批的规则，并故意制造字段缺失验证是否 fail-closed；不要先上全套 Dashboard，项目仍是 Public Preview。

若目标是消费级视觉体验而不是开发/平台 PoC，则把第三名替换为 [AIRI](https://github.com/moeru-ai/airi)：Web Demo、角色包、语音与 Avatar 最直观，但应把 Computer Use、长期记忆和游戏能力视为分阶段实验，而不是现成承诺。

## 值得持续跟踪的新 Feature 方向

1. **标准兼容的本地实时语音。** 不只要“能连 OpenAI Realtime 客户端”，还要有事件级契约测试、WebSocket/WebRTC parity、插话/取消、工具调用、多语言与端到端 P50/P95。
2. **MCP 的双向安全与可验证发布。** 下一步价值不只是扫描 server 描述，而是请求前策略、响应 DLP、工具指纹、rug-pull 检测、审批证据与协议版本 dual-stack 一起落地，并默认 fail-closed。
3. **Agent Skill 的版本、来源与宿主兼容清单。** 跨宿主安装数量应升级为逐能力 manifest：哪些宿主支持命令、hooks、资源发现、UI、权限和更新；知识 Skill 还需细粒度来源、生成 diff 与 validator。
4. **从“会循环”到 durable Agent execution。** `max_turns` 和文件状态只是起点，值得跟踪的是步骤级 checkpoint、幂等重试、补偿、人工接管、长期任务恢复，以及与审计/预算的统一。
5. **垂直本地数据面 Agent 化。** free-stockdb 代表的机会是把专业数据库以 MCP 暴露；真正可用还需要来源/许可证、更新时间、Schema、聚合正确性、工具覆盖、错误语义和 SLA，而不只是“存在一个 MCP server”。
6. **多模态证据预算。** Claude Video 的 transcript-first、Focus、cue frames 说明多模态产品会从“把全部视频交给模型”转向按问题分配字幕、关键帧、分辨率和 token；下一步需要缓存、可追溯时间点与漏检评测。
7. **角色/具身 Agent 的状态连续性。** AIRI 已把角色、Avatar、语音、渠道与插件放在一起；真正形成长期产品差异的将是可导出记忆、权限隔离、跨设备连续状态和可控主动性。
