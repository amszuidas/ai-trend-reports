## 今日 Feature 趋势摘要

1. **Agent Skill 正从“提示词文件”升级为有安装、工具链和可复现产物的垂直产品。** Impeccable 把设计方向、浏览器决策页、图像预览和确定性检测串成工作流；Claude Video 把下载、字幕、帧抽取和视频问答封成 `/watch`；last30days 把多源搜索、打分、聚类和带引文简报封成一次调用。
2. **确定性护栏正在成为 Agent 产品的核心卖点。** Open Code Review 用可预览的文件范围、规则匹配和行级输出约束审查；Impeccable 用 60 条检测规则和 hooks 拦截常见 AI UI 痕迹；AG Kit 用安全 hook、manifest/lock、备份与回滚降低工作区自动化风险。
3. **多模态价值开始落到“可做事”而非只聊天。** AIRI 把语音、VRM/Live2D、Discord/Telegram 和游戏交互放进虚拟角色；Claude Video 把画面与带时间戳转写同时交给 Agent，用于内容分析、Bug 录像诊断和定点追问。
4. **垂直基础模型仍靠完整研究闭环获得关注。** Kronos 不只发布 K 线模型权重，还给出零样本预测、概率采样、私有数据微调和简单回测路径；但它仍是研究工具，不是可直接交易的生产系统。
5. **“支持很多宿主/来源”不等于零配置。** 跨 Agent 安装通常仍需宿主信任、Python/Node、`ffmpeg`、浏览器 cookie、API key、模型额度或平台登录；网页 Demo、CLI 安装器和 doctor/preflight 只能降低门槛，不能消除外部依赖。
6. **当天 Release 是今日热度的重要事实信号。** Impeccable 同日发布 Skill `v4.0.3`、CLI `v3.4.0`、Extension `v1.3.0`；Open Code Review 同日发布 `v1.8.0`。两者恰好也是今日 AI 入选项目中新增 Stars 最高的两个。因果关系仍属推断，不能只凭时间接近下结论。

- `AG Kit` 不是 Agent Runtime 或模型，而是直接交付 Agent 工作区规则、专用 Agents、Skills、编排、记忆、MCP 配置与工具安全 hook，因此纳入；必须同时注明本版生产兼容承诺只覆盖 Google Antigravity。

### 1. [AIRI](https://github.com/moeru-ai/airi)

**典型场景：** 常驻桌面语音伴侣；定制 AI VTuber/角色卡；围绕屏幕或图片进行多模态对话；把角色接入 Discord/Telegram；连接 Minecraft/Factorio 做游戏 Agent 实验。

### 2. [Impeccable](https://github.com/pbakaus/impeccable)

**一句话定位：** 给使用 AI Coding Agent 做前端的开发者与产品团队一套“设计上下文 + 可控设计动作 + 反 AI 套路检测 + 浏览器内迭代”工作流，让现有 Agent 少产出同质化 UI，并把设计检查接入本地开发和 CI。

**典型场景：** 从零生成或重做营销页；沿既有 Design System 精修页面；上线前做设计/可访问性/响应式审查；在真实页面中比较局部变体；通过 hooks/CI 阻止 UI 质量回退。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **持久 Design Context** | `init`/`document` 生成 `PRODUCT.md`、`DESIGN.md` 与 surface 记录 → 跨会话/Agent 复用产品事实与视觉约束 → 长期产品/多页面 | **可用**；文档过时会持续放大错误，monorepo 子应用 context 仍有 [Issue #367](https://github.com/pbakaus/impeccable/issues/367) |
| **23 个设计命令** | shape、critique、audit、polish、typeset、layout、distill、harden 等把“改好看”拆成明确动作 → 更易限定范围 → 局部精修/上线前检查 | README **确列 23 个**；但 v4 已弃用 `craft` alias，推荐直接描述意图，不能把 23 个都当同等推荐入口 |

| **浏览器 Overlay/DevTools** | 在真实页面标注问题、跳到 Elements、按规则筛选并重扫 SPA → 日志不再难映射到 UI → 人工 QA/修复复查 | GitHub 今日发 Extension `1.3.0`；本次 Chrome 商店仍是 `1.2.1`、文案 41 条，不能称商店版已覆盖 60，[Release](https://github.com/pbakaus/impeccable/releases/tag/ext-v1.3.0) |
| **Live Mode 写回源码** | 在运行页面选元素、给文字/pin/笔画方向、生成 3 个变体，通过 HMR 预览，接受后写回组件/CSS → 省去 mock 到实现二次翻译 → Hero/卡片/定价区迭代 | 官网分别称 **Beta/alpha**，保守记为 **Preview**；需 dev server/HMR/helper，Vue accept 仍有缺口，[Live](https://impeccable.style/docs/live) |
| **Coding-Agent Hooks** | Agent 编辑 UI 时自动运行检测；Cursor 可写前阻断，其他多写后提醒/结束复扫 → 问题仍在当前上下文中修 → 团队守门 | Claude/Copilot/Codex/Cursor/Grok 支持程度不同；Codex 需 `/hooks` 批准，Copilot manifest 要进默认分支，其他宿主多只有 Skill，[Hooks](https://impeccable.style/docs/hooks) |
| **Critique / Audit / 修复闭环** | LLM 评审层级、清晰度、品牌感，确定性规则抓明确违规，再交给 polish/harden 等修复 → 兼顾判断与可重复信号 → 发布评审 | **需宿主模型**；LLM 分数不是客观成绩，detector clean 也不代表设计优秀 |
| **多宿主安装与 Doctor** | `install/update/check` 生成 Claude、Cursor、Gemini、Codex、Copilot、Grok、OpenCode 等适配目录，doctor 查 schema/hook/context 漂移 → 跨 Agent 复用同一设计语言 → 团队迁移 | CLI `3.4.0` 需 Node ≥22.12；restart/trust/preview 设置各异，无通用业务 SDK |

**开箱与依赖：** Apache-2.0 Skill/CLI、正确安装后的源码/URL Detector、JSON/CI/ignore 可免费本地用；设计命令、Critique、写代码与 Live 变体需要 AI 宿主及其模型额度；无原生图像工具时预览会用用户自己的 OpenAI Key。Live 需本地 dev server；方向 worlds 还依赖官方公开 roll API。Native iOS/Android 目前主要是 alpha 指导层，没有 HTML/CSS Detector、Hook、Live 闭环。

**易用性与同类差异：** 有 CLI、方向决策页、Live picker、Overlay、11 个 anti-slop Demo、Neo Mirai Case Study、教程与 JSON/CI 接口。相较 Anthropic 的 [frontend-design Skill](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)，Impeccable 多了持久上下文、命令词汇、确定性扫描、浏览器决策/写回、hooks 和 doctor，代价是安装与兼容面复杂。它也不等于 Figma：没有多人矢量画布、组件资产治理和原型历史，“Figma without round trip”只能描述局部源码迭代体验。

**限制与关注原因：** “60 条”不等于任一模式一次执行 60 条；仅复制 Skill 时静态 HTML detector 还可能因依赖缺失静默降级（[Issue #434](https://github.com/pbakaus/impeccable/issues/434)）。Live 不是任意网站编辑器，严格 CSP、Vue、native 和 greenfield 整页都有边界；三变体、方向世界和规则集也不能保证“消灭 AI slop”。事实：今日 #7、+847，并在抓取前数小时同日发布 [Skill 4.0.3](https://github.com/pbakaus/impeccable/releases/tag/skill-v4.0.3)、[CLI 3.4.0](https://github.com/pbakaus/impeccable/releases/tag/cli-v3.4.0)、Extension 1.3.0。推断：v4 集中发布、“反 AI 同质化”共鸣和极易展示的 Overlay/Live Demo 共同推动上榜。

### 3. [Kronos](https://github.com/shiyu-coder/Kronos)

**一句话定位：** 面向量化研究者和金融时序开发者的开源 K 线基础模型，输入历史 OHLC（可选 Volume/Amount）与未来时间戳，生成未来整段 K 线预测，降低从零训练金融专用模型的成本。

**典型场景：** 分钟/小时/日线预测；新市场零样本基线；股票/币对批量扫描；私有行情微调；把预测结果接入研究型回测与数据增强实验。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **联合 K 线预测** | 一次输出未来 Open/High/Low/Close，并可含 Volume/Amount → 直接形成完整蜡烛路径 → 行情/信号研究 | **可用**；输入至少要小写 OHLC 与时间索引，不接新闻、财报、订单簿或任意协变量，[预测示例](https://github.com/shiyu-coder/Kronos#-making-forecasts) |
| **公开金融预训练权重** | mini/small/base 三档按资源预算本地加载 → 无需先做大规模金融预训练 → 个人/团队基线 | **需下载权重**；mini 4.1M/context 2048，small 24.7M/base 102.3M 均 context 512；499.2M large **未公开**，[Model Zoo](https://github.com/shiyu-coder/Kronos#-model-zoo) |
| **跨粒度/市场零样本** | 同一接口用于股票、加密货币、外汇及不同 bar 频率 → 少为每个市场重训 → 新标的 PoC | **可直接尝试**；论文覆盖不等于所有市场同等验证，期货证据也弱于主评测 |
| **可变预测长度** | 按未来时间戳长度自回归生成未来路径 → 同一模型适配多 horizon → 数小时/数日推演 | 接口**可用**；长周期误差累积，“可生成任意长度”不等于任意长度可靠；small/base 超 512 历史会截断 |
| **随机采样与集成均值** | 用温度、`top_p`、`sample_count` 采多条路径并内部求均值 → 降低单次随机性 → 稳健基线 | **可用但易夸大**；标准 SDK 不返回原始路径、quantile、区间或校准概率，官网概率/阴影是定制展示 |
| **批量预测** | `predict_batch` 并行处理多个同长度数据集 → 降低股票池逐个调用成本 → 批量扫描 | **可用**；同 batch 要相同 lookback/pred_len，不是不等长或流式服务 |
| **无成交量模式** | 只用 OHLC 运行并提供专门示例 → 适配量额不可靠/不可比的市场 → 外汇/部分指数 | **可用**；缺量额可能损失信息；只有 Volume 时 Amount 可由均价近似，不能当真实成交额 |
| **本地 WebUI + Demo** | Flask UI 上传 CSV/Feather、选模型/设备/采样并画预测；官网展示 BTC/USDT → 降低理解门槛 → 教学/试跑 | 本地 UI **可用但实验性**；官网“Live Demo”是预计算看板，本次最后更新 2026-07-04，并非实时交互推理，[Demo](https://shiyu-coder.github.io/Kronos-demo/) |
| **自有数据微调** | 提供 A 股 Qlib 与自定义 CSV 流程，可微调 tokenizer/predictor、支持 DDP → 适配私有市场 → 专用模型研究 | **需清洗数据、YAML、PyTorch 与 GPU**；不是托管一键微调，[finetune_csv](https://github.com/shiyu-coder/Kronos/tree/master/finetune_csv) |
| **研究型回测/下游任务** | 示例把预测接入 top-k 回测；论文展示收益、波动率、合成序列和投资模拟 → 从曲线走向策略原型 → 论文复现/因子初筛 | **研究级**；收益/波动率由预测 Close 派生，回测缺交易成本、滑点、市场冲击、完整风控，不能等同可交易 alpha |

**开箱与依赖：** 项目 MIT 开源；需 Python 3.10+、克隆仓库、安装依赖并从 Hugging Face 下载模型/tokenizer。可走 CUDA、Apple MPS 或 CPU，训练和 base 推理更适合 GPU。它没有正式 CLI、托管 REST API、版本化独立 SDK、付费官方微调或 GitHub Release；易用性主要来自 Python `KronosPredictor`、单序列/批量/无成交量示例、本地 WebUI、Qlib 与 CSV 微调材料。

**同类差异：** 相较 [Amazon Chronos-2](https://github.com/amazon-science/chronos-forecasting) 与 [Google TimesFM 2.5](https://github.com/google-research/timesfm)，Kronos 强在金融 K 线联合语义、OHLCVA 整段输出及配套量化示例；后两者强在更长上下文、通用多变量/协变量、显式分位数、PyPI/云集成等。Kronos 论文只对比当时版本，不能外推为胜过后来 Chronos-2/TimesFM 2.5。

**限制与关注原因：** “首个开源 K 线基础模型”是作者定位；large 未开放，mini 又未进入原论文主 benchmark。标准采样只回均值，不能包装成现成概率预测；NaN、复权、交易时段、异常、缺口需用户处理，[Issue #130](https://github.com/shiyu-coder/Kronos/issues/130) 还报告过负 Volume 风险信号。论文的 93% 是指定 benchmark 的 RankIC 相对提升，不是准确率或收益。事实：今日 #8、+441，公开三档权重、WebUI、预测/微调/回测材料，论文获 AAAI 2026 接收。推断：学术背书、金融 AI 题材、低门槛 mini 与可视 Demo 共同带来传播；热度仍高于产品化成熟度。

### 4. [Open Code Review](https://github.com/alibaba/open-code-review)

**一句话定位：** 面向开发者和平台团队的开源 AI 审查工具，用确定性的 Git 范围、文件筛选、规则匹配与评论定位约束用户自选 LLM；也可只借用其选文件/配规则能力，把判断委托给已有 Coding Agent。

**典型场景：** 提交前审 staged/unstaged/untracked；PR/MR CI 行评论；大变更中断续跑；遗留目录全量 `scan`；在 Claude Code/Codex/Cursor/OpenCode 中做生成代码二次质检。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **多 Git 范围 + Preview** | 工作区、branch range、单 commit 三模式，`--preview` 不调模型就显示文件范围/排除原因 → 花 token 前先核对覆盖 → 本地/CI | Preview **开箱可用**；实际 review 需 LLM，[CLI](https://github.com/alibaba/open-code-review/blob/main/pages/src/content/docs/en/cli-reference.md) |
| **全文件 `scan`** | 扫仓库、目录或指定文件，无需有意义 diff → 从 PR 审查扩展到存量体检 → 接手旧仓/安全专项 | README **已可用**；官网 CLI Reference 尚未完整同步，不能误写路线图 |
| **按文件并发与续跑 Session** | 默认并发 8，range/commit 保存每文件状态，`--resume` 只补未完成项 → 大 PR 失败隔离、节省重复 token → 限流/中断任务 | workspace 不可 resume；部分文件成功时进程仍可能退出 0，CI 要解析 JSON `warnings` |
| **仓库上下文 + 行级评论** | Agent 可读当前/其他变更文件、查文件名和全仓搜索，输出问题、锚点、可选修复 → 不只看孤立 hunk，直接落 PR/IDE → 跨文件核验 | **可用**；定位失败会 `start_line=0`，工具只辅助当前文件，不证明全仓完整缺陷覆盖 |
| **四层规则与可解释筛选** | CLI/仓库/用户/内置规则按优先级覆盖，include/exclude glob 与 `rules check` 显示命中原因 → 团队规范版本化、可调试 → 语言/目录专项 | **可用**；默认排除多类 test path，审测试需显式 include，[Rules](https://github.com/alibaba/open-code-review/blob/main/pages/src/content/docs/en/review-rules.md) |
| **IaC 专用覆盖** | `v1.8.0` 新增 `.bicep`、`.hcl`、`.tfvars` allowlist，`.tf/.hcl/.tfvars` 使用 Terraform 专用规则 → 云配置不再被扩展名跳过 → IaC Review | **正式发布**；`.tf` 原本已支持，本次不是“首次支持 Terraform”，[v1.8.0](https://github.com/alibaba/open-code-review/releases/tag/v1.8.0) |
| **BYOM / 本地模型** | 选 Anthropic、OpenAI、多家兼容 Provider、企业 Gateway 或 Ollama，TUI 录 Key/选模型并测连通 → 不锁模型，可控成本/数据边界 → 企业/本地 | OCR 免费；云 token 可能付费；模型必须原生 structured tool calling |
| **MCP 外部工具** | 把 Jira/知识库/linter/schema 等 MCP 工具给审查 Agent；`v1.8.0` 新增远程 Streamable HTTP、headers/env → 审查可核对内部需求/规范 → 企业流程 | remote 已发布但[当前 MCP 文档](https://github.com/alibaba/open-code-review/blob/main/pages/src/content/docs/en/mcp.md)仍只写 stdio；认证、Server 与费用自理 |
| **Delegation Mode** | OCR 输出文件范围与规则分组，宿主 Claude/Codex/Cursor/OpenCode 完成判断 → 复用已有订阅，不必再给 OCR 配 API Key → 日常 Agent 流 | **可用**；不免宿主配额，覆盖/格式更依赖宿主严格执行，[Delegate](https://github.com/alibaba/open-code-review/blob/main/pages/src/content/docs/en/integrations/delegate.md) |
| **Agent / VS Code 多入口** | Claude/Codex/Cursor Skills，OpenCode tools/commands；VS Code sidebar 提供范围、preview、日志、取消、内联线程和 provider 测试 → Review→确认→修复路径更短 → IDE 工作流 | Agent 集成可用；VS Code 分发仍偏本地 VSIX/早期版本，不能按成熟商用插件宣传 |
| **CI 评论与本地 Viewer** | GitHub Action/GitLab/Gerrit/Bitbucket 示例发布评论/汇总，`v1.8.0` 默认每 50 条串行分批；Viewer 看模型响应、token、tool call、错误 → 提高发布可靠性并可追溯 → 团队 CI | Batching 只改善评论 API 可靠性，不提升模型发现能力；Viewer 不是团队 SaaS，Session 含敏感代码/响应，[CI](https://github.com/alibaba/open-code-review/blob/main/pages/src/content/docs/en/integrations/ci.md) |

**开箱与依赖：** CLI 安装、diff/preview、规则、session/viewer、delegate preview 可不调用模型；标准 `review`/`scan`、VS Code 实审和 CI 需 endpoint/token/model，平台评论还需仓库权限，MCP 需另建 Server。项目 Apache-2.0 免费，但模型、宿主订阅和外部服务可能付费。Git ≥2.41；只支持 Git，不支持 SVN/Mercurial。

**易用性与同类差异：** 核心 CLI 命令面、JSON envelope、配置 TUI、本地 Viewer、Agent manifests、VS Code 与多平台 CI 示例较齐，但无独立 HTTP API/多语言 SDK或免凭据在线 Demo。相较 CodeRabbit/Qodo，OCR 强在开源、BYOM/本地模型、preview/rules/scan/delegate/session viewer，弱在托管 PR 对话、持续学习、跨仓知识、组织治理、SSO/团队 Dashboard；相较通用 Claude Code，它的覆盖和规则更确定，但开放式追问、修改代码和任意工具组合更弱。

**限制与关注原因：** binary、删除、未知扩展、默认 tests 与超 token 文件会被跳过；工具读取/搜索和每文件 30 轮都有上限；行定位、CI comment API 和部分成功退出码均需下游兜底。代码是否离开本机取决于所选模型端点，Session 也会本地保存完整消息。作者 [Benchmark](https://github.com/alibaba/open-code-review#benchmark) 是旧版固定命令自测，未比较 CodeRabbit/Qodo，且 OCR recall 更低；“约 1/9 token”不能外推为全面胜出。事实：今日 #9、+979，并在当天发布 `v1.8.0` 的 remote MCP、IaC 与 Actions 改进。推断：阿里内部使用背书、BYOM/本地可控、当天 Release 与“专用 reviewer harness”需求共同推动热度。

### 5. [Claude Video](https://github.com/bradautomates/claude-video)

**一句话定位：** 给 Claude Code 及兼容 Agent Skills 宿主的视频输入适配层，把公开视频或本地文件处理成带绝对时间戳的抽样帧与转录，让已有多模态 Agent 总结、问答或定位画面事件；它不是新的视频模型。

**典型场景：** 拆解广告/竞品视频的视觉 Hook；从 Bug 录屏定位异常；总结访谈/课程/发布会；生成带时间戳笔记；先读全文字幕，再定点核验“看这里”等视觉时刻。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **URL / 本地文件双入口** | 接 HTTP(S) 或 `.mp4/.mkv/.webm/.mov/.m4v/.avi/.flv/.wmv` 等路径 → 不先人工转码/上传 SaaS → 公开内容/私有录屏 | **可用**；URL 范围取决于 `yt-dlp`，不处理 Playlist，登录/地区/反爬视频可能失败 |
| **字幕优先、按需下载** | URL 先查字幕，`transcript` 模式有字幕即不下载视频 → 启动快、下载与图片 token 最低 → 演讲/播客摘要 | **可用但当前只请求 `en.*`**；非英文原生字幕不保证走免费路径 |
| **Whisper 双后端与分片** | 无字幕时提 16kHz 音频，调 Groq `whisper-large-v3` 或 OpenAI `whisper-1`，超约 25MB 自动分片并回填时间戳 → 长视频仍可转写 → 本地录屏/无字幕 URL | 需 API Key，可能付费并外发音频；部分分片失败会产生不完整 transcript |
| **四档 Detail** | `transcript` 0 帧、`efficient` 关键帧/50 上限、默认 `balanced` 场景帧/100 上限、`token-burner` 无硬上限 → 显式换速度/成本/覆盖 → 从纯摘要到高画面需求 | `v0.2.0` **已发布**；token-burner 高切换视频可能产生数百帧 |
| **时长感知帧预算** | 按时长分配帧，候选过多时保首尾并均匀覆盖，全局钳制 2fps → 避免长视频吃满上下文又看到结尾 → 默认扫描 | 长视频 capped 模式只是**稀疏扫描**，覆盖到尾帧不等于完整理解 |
| **场景/关键帧 + 均匀回退** | efficient 快速解码关键帧；其他模式检测场景变化，候选不足则均匀采样，每帧给时间与 reason → 更易命中镜头变化且产物透明 → 发布片/幻灯片/录屏 | **可用**；快速动作可能在 2fps 限制下丢失 |
| **近重复去重** | 将帧缩到 16×16 灰度，以亮度差默认删除近重复，并报告丢弃数 → 把图片 token 留给不同画面 → 静态 UI/幻灯片 | **默认开启**；不是语义去重，细微但重要变化可能误删，可 `--no-dedup` |
| **Focus 区间** | `--start/--end` 只处理指定窗口，字幕同步过滤、帧预算集中 → 全片太稀时看清关键几十秒 → “2:30 发生什么” | **可用**；仍受 detail 上限与 2fps 限制 |
| **定点帧** | `--timestamps` 强制抓指定绝对时刻并预留预算，transcript 模式可只生成这些帧 → 解决小变化画面未触发场景检测 → 按字幕提示核验代码/终端 | **可用**；Focus 外时间点会被丢弃 |
| **成本/清晰度控制** | `--max-frames`、`--resolution` 512/1024、`--fps` 控制图片量和小字可读性 → 让 OCR/代码阅读与预算可调 → 批量研究/幻灯片 | 1024 约显著增加图像 token；自设 fps 仍不会超过 2 |
| **多宿主分发与会话追问** | Claude Marketplace、`watch.skill`、`npx skills add` 安装到 Codex/Cursor/Copilot/Gemini 等；同一会话复用已读帧/字幕 → 少重复下载 → 多 Agent/多轮问答 | “50+”是安装目录覆盖，不是逐宿主认证；追问靠当前上下文/暂存目录，**没有跨会话缓存/索引** |

**开箱与依赖：** Skill、Detail/Focus/定点/去重/报告均已在 [v0.2.0](https://github.com/bradautomates/claude-video/releases/tag/v0.2.0) 发布。有可用 `yt-dlp`、`ffmpeg/ffprobe` 时，匿名可访问且带英文字幕的 URL 可不配 Whisper Key；`--no-whisper` 可阻止音频外发。宿主仍须能跑脚本、联网并读取 JPEG；macOS 可尝试 Homebrew 安装依赖，Linux/Windows 主要给安装提示。

**易用性与同类差异：** 入口就是 `/watch URL-or-path question`，README 有真实 49 分钟视频的成本测量，Skill 契约和合成夹具测试覆盖 Detail、去重、定点与 Whisper 分片；但没有独立 UI、服务 API、语言 SDK、持久视频库或免安装托管 Demo。相较 [Gemini 原生视频理解](https://ai.google.dev/gemini-api/docs/video-understanding)，Claude Video 强在跨站 URL、本地透明帧、字幕优先、场景去重、Focus/定点和不上传视频本体；Gemini 强在原生音视频联合输入、长视频 Files API、SDK/结构化应用集成。前者“看到抽样 JPEG + 文本”，不是连续视频理解。

**限制与关注原因：** “Watch any video”受 2fps、长片稀疏、匿名下载、Cookie/地区限制和托管沙箱影响；音乐、语气、瞬时动作可能丢失。去重非视觉 embedding；“50+ hosts”不保证每个宿主能联网/执行/读图；保留目录也不是真缓存，[Issue #80](https://github.com/bradautomates/claude-video/issues/80) 还警示同一 out-dir 重跑可能删除源文件。更关键的是 2026-07-27 的 [#99](https://github.com/bradautomates/claude-video/issues/99)/[#101](https://github.com/bradautomates/claude-video/issues/101) 报告新 ffmpeg 移除 `-vsync`，当前取帧模式可能零帧失败，今天应先验证版本。事实：今日 #11、+434，`v0.2.0` 提供自包含 Skill 与完整控制面；并非当天发版。推断：视频问答/录屏诊断价值直观、单命令 Demo 和跨 Agent 分发带来二次传播。

### 6. [AG Kit](https://github.com/vudovn/ag-kit)

**一句话定位：** 给 Google Antigravity 用户一次装进项目的 Agent 工作区成品包，包含专家角色、Skills、斜杠工作流、持久记忆、MCP 配置辅助、安全 hook 与更新/校验工具；它不是新的 Runtime、模型、UI、SDK 或独立调度器。

**典型场景：** 为新仓库铺统一 Agent 规范；按前后端/安全/测试/DevOps 专家视角工作；用斜杠命令固定研发流程；在 Antigravity 中并行研究/评审；安全维护团队共享的 `.agents/` 内容和 MCP 配置。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |

### 7. [last30days](https://github.com/mvanhorn/last30days-skill)

**典型场景：** 会前人物简报；产品/开源项目口碑研究；多竞品对比；热点发现与选题队列；watchlist 日/周报；用 `--as-of` 回看并在行动前复核易变数字。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **多源近期研究** | 按主题调用 Reddit、X、YouTube、TikTok、Instagram、HN、Polymarket、GitHub、Digg、arXiv、Techmeme、LinkedIn 等 → 一份简报同时呈现源特有字段 → 舆情/人物/事件 | 来源清单是**能力上限**，不会默认全跑；认证、地区、限流、费用各异，[Sources](https://github.com/mvanhorn/last30days-skill/blob/v3.18.3/README.md#sources-scored-by-the-people) |
| **Pre-research / Query Plan** | 先解析官方 handle、repo/user、subreddit、账号和第一方定位，再生成分平台查询 → 降同名噪声与漏检 → 人物/品牌/项目 | **Skill 工作流可用**；质量依赖宿主 WebSearch、模型与是否遵循长 contract，无宿主搜索可配置 Brave/Exa/Serper 等 |

| **Person / GitHub / Hiring Signals** | 人物/项目取 PR、repo、release、issues、live stars；公司读招聘页并解释投入方向 → 把“说了什么/做了什么/在招什么”对照 → 会前/尽调 | **可用**；招聘只能写“signal”，不能推导确定 roadmap/发布日期 |

| **Markdown / JSON / HTML Library** | 保存简报与 raw artifacts，输出版本化 Agent JSON/自包含 HTML，建立 FTS5 library/Atom feed → 一次聊天变可查资产 → 日报库/下游 Agent | **可用**；无独立研究 GUI；公开 HTML 需主动启用并审查隐私，raw/debug 可能含本地文本 |

**易用性与同类差异：** 主要界面是宿主聊天/Slash Command；CLI 覆盖 research、discover、doctor、queue、library、setup，另有 Claude Desktop MCP、Claude/Grok Plugin、Agent Skills 安装、模板化 comparison/hiring/discovery 输出和丰富示例。没有独立 GUI、稳定应用 SDK 或免配置托管 Demo。相较 Perplexity，它强在社交互动/评论、GitHub/Polymarket、watchlist/library 组合，弱在托管 UI、稳定 API/SDK；相较 Grok，跨 Reddit/YouTube/HN/Polymarket 更广但 X 原生权限更弱；相较 Exa，平台原生互动更强，但开放 Web 结构化 API、过滤、Monitor 与低延迟产品化更弱。

**限制与关注原因：** “30 天”各源并不完全同质，undated/evergreen 内容可能低置信流入；互动、聚类和市场概率均不能替代一手事实核验。Cookie/非官方抓取有隐私、账号限制和 ToS 风险，[Issue #882](https://github.com/mvanhorn/last30days-skill/issues/882) 还记录第三方 ScrapeCreators 授权链故障；50+ hosts 是安装覆盖，不是同等 WebSearch/cookie/renderer 能力。比较、Deep Discovery、transcript 与评论会增加分钟级时延和费用。事实：今日 #14、+240；[v3.18.3](https://github.com/mvanhorn/last30days-skill/releases/tag/v3.18.3) 是稳定性修复版，修了 Reddit 日期窗、Chromium 多 Profile cookie、评论排名、计划校验和 YouTube/Polymarket 路径。推断：多源互动信号、连续发布、Doctor/Library/Watchlist 和跨宿主 Skill 分发共同带来二次曝光。

## 今天最值得体验的 3 个项目

1. **[Impeccable](https://github.com/pbakaus/impeccable)**
   最吸引人的不是“又一个前端 Prompt”，而是 **方向发牌/决策页 → 可见 mock → 源码构建 → 60 条确定性检测 → Overlay/Live 写回 → Hook/CI** 的闭环。建议先在一个可丢弃的 Vite/Next 页面跑 `init`、`critique` 和 `detect`；Live 仍按 Preview 对待，Chrome 商店旧版不要当最新规则集。

2. **[Open Code Review](https://github.com/alibaba/open-code-review)**
   `preview + rules check + scan + delegation` 很适合把 AI 审查前移到本地，又能复用现有 Claude/Codex 订阅；当天 `v1.8.0` 的 remote MCP 和 IaC 规则也值得验证。建议先用 `--preview` 核对测试文件/超大文件是否被排除，再决定标准 BYOM Review 或 Delegate。

3. **[AIRI](https://github.com/moeru-ai/airi)**
   今天最完整、最直观的多模态成品体验：**桌面语音、角色包、Live2D/Spine/VRM、MCP、搜索/图片工具和游戏/社交通道** 已经能展示“角色如何从聊天走向具身”。建议先从 Web/桌面 + 单一模型/TTS 开始；记忆、Computer Use、Factorio/KSP 不要按成熟 Feature 预期。

> 备选快速试用：[Claude Video](https://github.com/bradautomates/claude-video) 的 `/watch` 对短英文字幕视频和 Bug 录屏非常直观，但今日应先确认 `ffmpeg` 未触发 `-vsync` 兼容问题，再用 `transcript/efficient` 起步。

## 值得持续跟踪的新 Feature 方向

1. **Agent 设计治理：** 从“让模型审美更好”走向持久 Design Context、方向决策、人审、确定性规则、浏览器证据与写回源码的闭环。
2. **证据可见的多模态 Skills：** 视频/屏幕能力不只输出答案，还应暴露时间戳、采样理由、转写、成本预算与 Focus 二次核验；下一步是原生连续媒体理解与可审计证据兼得。
3. **Agent 工作区供应链：** Manifest、完整性锁、依赖图、Doctor、Merge-aware Update、回滚和 Hook trust 正成为团队采用 Skills/Agents 的基础 Feature。
4. **垂直 Agent 的 Remote MCP：** Open Code Review 已把 Streamable HTTP MCP 放入审查链；值得观察更多垂直产品是否补齐 OAuth、租户隔离、Tool allowlist、审计和失败降级。
5. **多源研究的 Source Health / Freshness：** 未来竞争点不只是来源数量，而是能否准确报告 auth/rate-limit/no-results、识别转载依赖、复核易变数字并把“互动热度”和“事实置信度”分开。
6. **具身角色的长期记忆与本地推理：** AIRI 已有角色/语音/工具/游戏外壳，但真正决定长期价值的是可控记忆、跨端身份、权限边界和消费级本地模型体验。
7. **垂直基础模型的产品化输出：** Kronos 显示领域权重很受欢迎；下一步值得跟踪标准化 quantile/置信区间、协变量、数据质量校验、推理服务与能计入成本/滑点的评估闭环。
