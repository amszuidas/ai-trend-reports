## 今日 Feature 趋势摘要

1. **Skills 正在成为 Agent 产品的一等交付面。** Agency Agents、Agent Skills、Anthropic Skills 与 OpenMontage 都把可复用角色/SOP/工具说明作为用户能力；但“能被宿主加载”不等于有独立 runtime、持久状态或跨宿主行为一致性。
2. **多 Agent 的竞争焦点从“能开几个会话”转向治理。** Orca 强在 worktree、审阅、远程与移动值守；Paperclip 强在组织、预算、Secret、审批和审计；Prime Agent 强在长任务执行循环。三者不是同一种产品，不能只用“多 Agent”横向替代。
3. **可追责性正在从日志升级为业务对象。** Semantica 把决策、来源、双时态和规则作为一等对象；Paperclip 把成本与审批变成硬门禁；Daily Stock 用 DecisionSignal 做后验评估；Harvey LAB 用原子 rubric 与 deliverable 检查长任务结果。
4. **垂直 AI 产品开始交付完整工作流，而不只是聊天。** DeepTutor 串起资料、RAG、练习、长期记忆和交互教材；Daily Stock 串起多市场分析、选股、持仓、告警、推送与复盘；OpenMontage 串起研究、资产、审片、合成和交付。
5. **模型使用层正在向 Agent 接口靠近。** Transformers v5.15.0 已提供 tool/reasoning 解析、OpenAI 风格本地服务与 tiny-agents/MCP 最小闭环；但工具执行、授权、状态、生产级吞吐仍需外部系统。
6. **“正式 Release 与滚动 main 的差距”是今天最大的采用风险之一。** Code-Graph-RAG 的最新 tag/main 高于 PyPI/Release，Paperclip、Orca 的 main 大幅领先稳定版，Agent Skills 的若干 Codex 修复只在 main；报告一律以正式发行版为稳定口径，main-only 单列。
7. **长任务评测正从短问答转向“读材料并交付文件”。** Harvey LAB 的 matter、deliverable、criterion、回放和 sweep 能测完整法律 Agent 工作，但合成数据、LLM judge 与已知坏题意味着它是比较工具，不是法律可靠性认证。

## Feature 深度卡片

### 1. [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)

**一句话定位：**给同时使用 Claude Code、Codex、Cursor 等宿主的个人/团队一套可复制的专家 persona 与协作 SOP，用明确交付物和质量标准替代泛化的“扮演专家”；它不是自主 Agent runtime。

**典型场景：**按 NEXUS 推进 MVP；单独调用安全/RAG/营销/医疗等专家；在多种 Coding Agent 之间复用同一角色库；用 handoff/QA 模板组织交接；接第三方 MCP memory 延续跨会话项目。

| Feature | 能做什么 | 用户价值与适用场景 | 状态 / 条件 |
|---|---|---|---|
| [270 个角色 / 17 divisions](https://github.com/msitarzewski/agency-agents/blob/main/README.md#-the-agency-roster) | 覆盖工程、产品、设计、营销、安全、金融、GIS、医疗等角色，附使命、流程、交付物和指标 | 从现成职责模板启动专业任务，适合跨职能项目 | `main` 可用；README 的“230+”已滞后 |
| 交付物导向 Profile | 定义何时调用、输出格式、成功标准与沟通方式 | 比一句角色设定更可验收，适合代码、研究、策略和文档 | 纯 Markdown，效果取决于宿主模型/工具 |
| [16 个 CLI 目标](https://github.com/msitarzewski/agency-agents/blob/main/tools.json) | 转换/安装到 Claude Code、Codex、Gemini CLI、Cursor、OpenCode、Copilot 等 | 多工具团队只维护一份源内容 | 已有脚本；目标间元数据/行为不等价 |
| 选择式安装与 dry-run | 按 tool/division/agent 安装、自动探测宿主并可预演 | 避免一次塞入 270 个角色和误写目录 | CLI 可用；部分目标需先 convert |
| [NEXUS 三模式](https://github.com/msitarzewski/agency-agents/blob/main/strategy/QUICKSTART.md) | Full/Sprint/Micro 覆盖七阶段、角色分工、并行项与质量门 | 新手可照流程组合角色，适合完整产品、MVP、单任务 | 是操作协议，不会自动调度 Agent |
| [四套 Runbooks](https://github.com/msitarzewski/agency-agents/blob/main/strategy/runbooks.json) | 预制 Startup MVP、Enterprise Feature、Marketing、Incident Response 团队 | 降低选人和漏配 QA/支持角色的成本 | 主仓库可用；“一键执行”仍需宿主/人工 |
| [证据式 handoff/QA](https://github.com/msitarzewski/agency-agents/blob/main/strategy/coordination/handoff-templates.md) | 标准交接、PASS/FAIL、三次失败升级、phase gate | 减少上下文丢失，适合开发→测试等交接 | 模板不会验证证据真假 |
| [MCP Memory 配方](https://github.com/msitarzewski/agency-agents/blob/main/integrations/mcp-memory/README.md) | 约定 remember/recall/search/rollback 保存角色产物 | 长项目减少复制粘贴，支持回滚思路 | 必须另装兼容 MCP server；非内置记忆 |
| [桌面 Catalog Manager](https://github.com/msitarzewski/agency-agents-app/releases/tag/v0.3.0) | 搜索、筛选、部署、Teams/Projects、drift/更新/卸载 | 非 Shell 用户也能维护多工具角色 | 独立 app v0.3.0；首次需同步最新 catalog，Windows 未签名 |

**成熟度与门槛：**主仓库无 Release/tag，是滚动 `main@ebe9c99`；角色、NEXUS、runbook 和脚本可直接读/装，实际执行必须有外部 AI 宿主，MCP memory 需第三方服务。Web 选人器、Marketplace、personality quiz 等仍是路线图。

**同类与缺口：**相比 [wshobson/agents](https://github.com/wshobson/agents)，它在角色广度、业务角色、16 宿主和桌面管理器上更强；后者的 plugins/commands/orchestrators 与 eval 更像可执行开发工作流。这里缺少运行时、系统化能力评测、模型路由和可靠性认证。

**易用性信号：**有 CLI、dry-run、完整 profiles、runbooks、handoff 模板、examples 与独立桌面 UI；无统一 API/SDK，示例是可照抄流程而非自动评分 Demo。转换会丢宿主不支持字段，OpenCode 还有约 119 个注册上限；高风险行业角色不构成专业资格。

**今日关注：****事实**：榜单 #1、+958；当前工具契约 16 项，近期持续加入细分角色，主仓库无 Release。**推断**：角色广度、跨宿主复用和 GUI 安装同时击中“Agent 工具碎片化”痛点，容易传播；Stars/“battle-tested”不证明每个角色的效果。

### 2. [semantica-agi/semantica](https://github.com/semantica-agi/semantica)

**一句话定位：**给受监管/高风险 AI 团队提供上下文图与“决策问责层”，把事实来源、Agent 决策、规则、因果链和历史状态变成可查询资产；它不是聊天产品或完整编排框架。

**典型场景：**贷款/临床/法律 Agent 留痕；企业资料转 GraphRAG；多 Agent 共享事实与先例；用 OWL/SHACL/SKOS 治理术语；按时间点回溯政策、组织与证据链。

| Feature | 能做什么 | 用户价值与适用场景 | 状态 / 条件 |
|---|---|---|---|
| [多源知识摄取](https://docs.getsemantica.ai/modules/) | 处理 Office/PDF/网页/SQL/Git/消息流/数据平台并抽实体、关系、事件 | 少拼多套 ETL，适合企业 GraphRAG 数据准备 | 常见本地源可用；企业源需 extras/凭据，LLM 抽取可付费 |
| 实体消歧与冲突检测 | 合并别名并显式标记值、类型、时间、逻辑冲突 | 避免静默覆盖，适合主数据和跨来源尽调 | 规则模式可本地；复杂文本仍需抽样验收 |
| [Context Graph / GraphRAG](https://docs.getsemantica.ai/reference/context/) | 混合向量、邻接、多跳、路径、社区与语义距离 | 回答跨文档关联问题并展示关系路径 | 本地 FAISS 可试；持久后端高级操作并非完全等价 |
| Decision Intelligence | 记录类别、理由、结果、置信度、先例、因果与政策检查 | 可回答“为何当时这样决定”，适合审批/风控/复盘 | Python/MCP 已发布；[Explorer 决策 API 有 500 问题](https://github.com/semantica-agi/semantica/issues/884) |
| 确定性规则推理 | 前向链、Rete、Datalog、SPARQL 等返回推理路径 | 相同事实/规则可重复，适合合规和资格校验 | 无需 LLM；规则正确性仍由用户负责 |
| [PROV-O 与哈希审计](https://github.com/semantica-agi/semantica/releases/tag/v0.6.5) | 记录来源、生成/批准活动、修订、失效 tombstone、血缘与链校验 | 高风险 AI 可导出证据链并发现断链 | v0.6.5 正式；“audit-grade”仍需组织级权限/备份/验收 |
| 双时态与快照 | 区分有效时间/记录时间，做 point-in-time、diff、历史修订 | 避免用今天事实倒推过去，适合政策/合同/事件时间线 | 核心可用；时区、迟到数据规则需自定 |
| Ontology Hub | 管 OWL、SKOS、SHACL、alignment、版本 diff/影响 | 让图谱术语和约束可治理，适合集团/医疗/金融词汇 | SHACL/Explorer 需 extras；仍在快速加固 |

|---|---|---|---|
| 研究→成片流水线 | research/proposal/script/scene/assets/edit/compose，并要求来源 | 减少事实研究与创作交接，适合科普/行业视频 | 当前 main；流程约束不保证事实正确 |

### 17. [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)

**一句话定位：**给需要在本地代码/研究目录中执行长时间、可中断恢复、多 Agent 协作任务的开发者和研究者，把终端 Agent、持久 IPython、原生子代理、目标与后台调度放在同一 CLI/TUI。

**典型场景：**并行代码审查/仓库调研；跨小时修复与验证；heartbeat/cron 运维监测；把流程固化为 Skill/MCP；用持久 Python 状态处理大上下文研究。

| Feature | 能做什么 | 用户价值与适用场景 | 状态 / 条件 |
|---|---|---|---|
| [RLM 持久 IPython](https://github.com/PrimeIntellect-ai/prime-agent/blob/v0.7.2/packages/coding-agent/docs/rlm.md) | 模型通过单一 ipython 工具组合文件/shell/数据/Skill/子代理，变量跨 compaction 保留 | 中间数据不必反复塞回提示，适合长研究 | v0.7.2 可用；执行继承本机权限 |
| 递归子代理与通信 | child 独立上下文并行/后台运行，互发消息、完成后可重唤醒 | 主上下文专注协调，多角度 review | 稳定；`rlm()` 返回 handle 不返回答案，需显式回报 |
| Daemon 会话恢复 | TUI detach 后 worker 继续，可 list/attach/stop，磁盘恢复会话/child | SSH/客户端断线不毁长任务 | 可用；仍有挂起/恢复类开放用户报告 |
| `/refine` Continual Harness | 将有证据的改进写入补充 prompt、memory、Skill 描述或子代理 spec并可回滚 | 同会话减少重复踩坑 | 可用；不是训练/微调，改了什么的可见性仍弱 |
| Persistent Goal | 跨 turn 保留目标、token/耗时/续跑/预算，仅显式 complete 才完成 | 防压缩或自然回答误判结束 | 可用；必须用户/host 显式创建 |
| Autonomous + Quality Gates | 有界自动续跑，以 shell gates 作完成证据 | 无人值守修复仍有资源上限/验证 | 默认关闭；到预算上限不等于成功 |
| Heartbeat / Schedule | 用户/Agent heartbeat 与一次性/cron 提示，detach 后继续 | 原会话做巡检和延迟复核 | daemon 必须运行；不同调度面的所有权有别 |
| Compaction / 会话树 / steering | 自动压缩、fork/clone/resume，运行中排队或编辑消息 | 延长任务并探索替代分支 | 可用；压缩不是完成信号 |
| 可执行 Skills + MCP | `SKILL.md` 可带 Python typed callable；Linear/Notion 与远程 HTTP MCP | 团队工作流能程序化组合 SaaS | 第三方 Skill 需审查；MCP 仅 remote HTTP，无 stdio |
| TUI/JSON/RPC/ACP/SDK + 多模型 | 人用终端和程序嵌入；接订阅/API/兼容模型 | 从交互终端扩到 IDE/CI/自建 UI | 推理需订阅/key；SDK 包名仍保留旧品牌 |

**成熟度与门槛：**v0.7.2 今日凌晨发布，`main` 仅领先 3 commits，`qwen3.8-max` catalog 属 main-only。安装后还必须完成模型认证；并发 child、refine 和续跑会额外耗 token。稳定安装主路径偏 macOS/Linux；Windows 与 kernel/daemon 长会话仍需评估。

**同类与缺口：**相比 Codex CLI/Claude Code，差异是“持久 IPython + 原生 child + daemon 恢复 + goal/heartbeat/schedule + 有界 autonomous + refine”的长任务闭环；相比其血缘 pi-mono，已形成独立 CLI/发布。缺安全沙箱、stdio MCP、官方托管 Web/桌面 GUI；不适合把不可信仓库/Skill 直接以日常账号权限运行。

**易用性信号：**TUI、Agents View、CLI、doctor/update、JSONL、RPC、ACP、Node SDK、Quickstart 和多份专题文档齐全；无托管 Demo。v0.7.2 默认启用伪匿名 analytics，可用设置、`DO_NOT_TRACK=1` 或 offline 关闭；敏感环境需主动 opt out。

**今日关注：****事实**：榜单 #17、+1,138，为今日入选项目最高日增；v0.7.2 刚发布并改进队列/Agent 视图与 worker 恢复。**推断**：“self-improving RLM”与长任务/原生子代理叙事叠加发版带来曝光；self-improving 仅更新上下文资产，不会训练模型，Star 增速也不证明稳定性。

## 今天最值得体验的 3 个项目

1. **[Prime Agent](https://github.com/PrimeIntellect-ai/prime-agent)** — 今日最高日增（+1,138）且 v0.7.2 刚发布。最值得实测的是“持久 IPython + 原生子代理 + daemon 恢复 + goal/quality gate”：选一个 30–60 分钟、有明确测试命令的仓库任务，观察终端 detach 后能否恢复、子代理是否按协议回报、gate 是否真的阻止假完成。先用容器或低权限账号，关闭不需要的 analytics。
2. **[Orca](https://github.com/stablyai/orca)** — 适合已经同时使用两个以上 Coding Agent 的开发者。最吸引人的不是多开终端，而是 worktree 隔离、Design Mode、行级批注返修和 stacked PR；用同一小 bug 让两个 Agent 竞速并完整走一次 diff→反馈→CI→PR，能最快判断它是否减少审阅成本。不要把 worktree 当安全沙箱。
3. **[DeepTutor](https://github.com/HKUDS/DeepTutor)** — 今日较完整的垂直 AI 产品。把一份教材/论文建库，依次跑引用问答、Quiz/Mastery、Interactive Book，再检查 Memory Graph 是否能追到证据，能验证它真正差异化的“学习闭环”，而不是只看聊天 Demo。优先默认 LlamaIndex 路径，避免一开始把外部 RAG/生成服务故障混入评价。

**创作者加选：**如果核心需求是视频而不是开发/学习，[OpenMontage](https://github.com/calesthio/OpenMontage) 的 `make demo` + zero-key explainer + Backlot gate 是今天最值得看的非代码生产工作流；先跑零 Key，再开一个低预算付费 provider。

## 值得持续跟踪的新 Feature 方向

1. **从 Prompt 资产到可测试 Skill 供应链：**关注触发/误路由/行为 eval、依赖锁定、签名、许可、跨宿主兼容矩阵，以及单 Skill 安装是否能携带共享 references。
2. **Agent 控制面的三层分化：**执行层（Prime Agent）、开发工作区层（Orca）、组织治理层（Paperclip）正在分开成熟；后续关键是能否通过稳定协议组合，而不是各自继续堆同名“orchestration”。
3. **决策与 provenance 成为一等数据：**Semantica 的决策/时态/PROV-O、Paperclip 的运行/成本/Secret 审计、OpenMontage 的生产决策/预算、Daily Stock 的 DecisionSignal 都指向“结果必须能解释当时依据”。
4. **垂直 Agent 的可复核中间产物：**学习路径/题库、视频 proposal/scene/take、法律 deliverable/rubric，比单一最终回答更便于人类纠偏；应继续观察这些中间对象能否导出、版本化和跨工具复用。
5. **本地模型的 Agent 协议面：**Transformers 的 tool/reasoning/Serve 与 Prime 的多 Provider 说明接口正在统一；真正缺口仍是模型对多步工具、并行调用、错误恢复和长上下文压缩的可靠性评测。
6. **硬门禁替代“请 Agent 自觉”：**预算 cap、review gate、quality gate、sandbox/Secret grant 正在进入产品主路径。下一步要关注门禁是否由外部执行器强制、成本/权限数据是否可信，以及绕过路径是否可审计。
7. **Release 可复现性：**今天多仓无 Release、tag/PyPI 不一致或 main 大幅领先；未来值得关注 SBOM、迁移指南、版本化文档、兼容测试和可固定 Demo，而不是只看 capability count。
