## 今日 Feature 趋势摘要

1. **长任务 Agent 正从“会续聊”升级为可编程、可恢复的控制面。** Prime Agent 把持久 IPython、原生 Subagent、Agent 直连、daemon、Goal、Heartbeat、Schedule 和质量门禁放进同一 CLI；真正的新价值是断线后状态、子任务和计划仍在，而不只是再加一个聊天 UI。
2. **Agent Skills 从个人工程方法扩张为厂商官方操作目录。** `agent-skills` 与 Matt Skills 继续强化规格、验证和人机协作；Google 则一次性覆盖 Gemini、Agent Platform、GKE、BigQuery、Ads/Analytics。竞争焦点开始从“有多少提示词”转到版本、权限、质量评测和真实工具接入。
3. **多 Agent 的价值更适合落在“不同角色公开冲突”而非简单并行。** TradingAgents 让基本面、情绪、新闻、技术分析、看多/看空研究、风险与组合经理分别给出意见；用户价值是看见分歧和风险路径，但并不自动获得可复现超额收益。
4. **Day-2 能力进入 Feature 清单。** Google Skills 已把 Agent Eval、在线质量、Token/安全/幻觉告警和模型生命周期写成官方工作流；Prime Agent 强调后台恢复，TradingAgents 加 checkpoint 与 decision log。Agent 工具开始认真处理上线后的失败、漂移和复盘。
5. **“跨宿主可安装”仍不等于能力同构。** Markdown Skill 容易复制，但 slash commands、Persona、hooks、subagent、浏览器、MCP 和权限模型依赖宿主；应把“70+ agents”理解为内容可分发，而不是每个入口都能执行相同闭环。
6. **今天最该删除的营销等式：** Self-improving ≠ 模型自训练；RLM ≠ 必然更强/更省；官方 Skill ≠ 已开通云资源；104 Skills ≠ 104 项都稳定；Multi-agent trading ≠ 实盘投资系统；仓库有 SDK 文档 ≠ SDK 已有稳定发行渠道。

## Feature 深度卡片

### 1. [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)

**一句话定位：** 面向开发者与 AI 研究者的开源终端 Agent，把持久 Python 工作台、原生递归 Subagent、可回滚的 Harness 改进和可断线续跑的后台任务组合起来，服务代码、深研和长周期自动化。

**典型场景：** 多专家并行审查代码/文档；数小时到数天的迁移、实验或监控；先用 Python 筛选大仓库/数据再压缩给模型；用测试命令作为自治质量门；把反复工作沉淀为记忆、Skill 或 MCP 集成。

| Feature | 能做什么 → 用户价值 → 场景 | 状态 / 边界 |
|---|---|---|
| **持久 IPython RLM 工作台** | 模型用一个 Python 工具编排文件、Shell、数据、Skill 与委派，变量/导入跨轮次与压缩保留 → 少重复读上下文 → 大仓分析、研究自动化 | v0.7.1 已发，[RLM](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/rlm.md) |
| **原生递归 Subagent** | `rlm(...)` 创建独立会话/目录的子 Agent，可并行、保留、恢复、追问 → 主上下文更聚焦、工作量可扩展 → 审查/测试/调研 | v0.6 起已发；调用返回 handle，结果需消息/文件回传，[Release](https://github.com/PrimeIntellect-ai/prime-agent/releases/tag/v0.6.0) |
| **Agent 直接通信** | 父、兄弟、直接子代可看 roster、互发消息和继续保留会话 → 少由用户人工转发 → 实现后让原 Reviewer 复验 | 已发；作用域和默认递归深度受限，[长任务](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/long-running-agents.md) |
| **Continual Harness `/refine`** | 从轨迹小步更新补充提示、记忆、Skill 描述和 Subagent 规格，并快照/回滚 → 验证过的经验可跨会话复用 → 重复评测/项目习惯 | 已发；不是改模型或重写基础系统提示，[Harness](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/rlm-runtime.md#continual-harness-state) |

| **Heartbeat + Schedule** | 用户或 Agent 配置心跳、一次性任务和 cron 重入 → 主动检查外部状态 → 部署观察、测试轮询、巡检 | 已发；cron DOM/DOW 语义与稀疏计划有 [#940](https://github.com/PrimeIntellect-ai/prime-agent/issues/940) 边界 |

| **多模型与本地端点** | 订阅登录或 API Key 接 ChatGPT、Claude、Copilot 及多云/本地 OpenAI-compatible 模型 → 控制成本和供应商锁定 → 企业云/隐私环境 | 已发；能力与费用依 Provider，[Providers](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/providers.md) |
| **可执行 Skills/扩展/资源包** | 兼容 Markdown Agent Skills，并支持 Python Skill、Skill Creator、npm/Git/路径包 → 重复流程变可调用能力 → 团队规范/领域工具 | 已发；第三方包以用户权限执行，[Skills](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/skills.md) |

| **TUI + JSON/RPC/ACP/SDK 文档** | 人工终端、CI 事件流、编辑器协议与嵌入接口共享同一 Agent → 入口选择更灵活 → 日常开发/评测 Harness | TUI/JSON/RPC/ACP 可用；SDK 缺匹配本仓版本的稳定公开分发，[#949](https://github.com/PrimeIntellect-ai/prime-agent/issues/949) |

**开箱/配置/实验：** macOS/Linux 安装器、TUI、会话、Subagent、daemon、Goal/Autonomous、JSON/RPC/ACP 已进稳定版，但启动仍需模型订阅或 API 凭据。Serper 网搜、Linear/Notion、自定义 MCP、本地模型、定时与第三方包需额外配置或费用。RLM/Continual Harness 的效果仍是早期研究结论；Windows 的 IPython 内核存在阻断问题，本地 stdio MCP 与稳定 SDK 发行不能提前算可用。

**同类、易用性与限制：** 相比其上游 [pi](https://github.com/badlogic/pi-mono)，Prime Agent 独有/更强的是持久 RLM、原生 Subagent 注册表、Agent 直连、daemon、Goal/Heartbeat/Schedule/Autonomous 与 Continual Harness；弱项是无安全沙箱、无一方 Web/桌面 UI、无内置 Plan/Todo、API 兼容仍不稳定。TUI、Agents View、autocomplete、图片/文件、安装校验、AGENTS.md、Prompt/Skill Creator 与密集文档是强易用性信号；但模型生成的 Python/Shell 以用户权限运行，HTML 导出可能加载远程图片，Windows、消息示例和 SDK 仍有开放缺陷。[官方 RLM 实验](https://www.primeintellect.ai/blog/rlm) 也出现部分任务更差且耗时/Token 更高，不能宣传为普遍增益。

**今日关注：** **事实**：v0.7.1 于上海时间今日凌晨发布，修复网搜引导和后台恢复；今日 #1、+2,293。**推断**：Self-improving、RLM、原生多 Agent 与断线续跑同时踩中热点，叠加新版本和可复用主流订阅，推动快速传播；当前更适合干净 worktree/容器中的试验，不适合把接口当稳定企业契约。

**同类、易用性与限制：** 相比 `ai-hedge-fund`，它强在双层辩论、恢复、持久反思、数据/模型 Provider 和时点修复，弱在 Web 试玩；相比 Qlib/FinRL，强在自然语言解释与多角色研究，弱在数据/特征、模型训练、严格回测、组合状态、绩效指标和执行。CLI、Python 示例、Docker、env 模板、报告、截图/视频 Demo 齐全，但无独立文档站/REST/UI。历史日期分析不是严格 backtest，模型可能从预训练权重知道未来事件；结果不可复现，数据时点多版持续修复，公开图没有真实 holdings/capital/constraints，LLM 生成的 entry/stop 缺确定性一致性检查，风险委员会也不是硬风控引擎。

**今日关注：** **事实**：v0.3.1 是最新稳定版，集中修 Alpha Vantage 前视过滤、router、checkpoint、Crypto 情绪和重试；今日 #7、+126，但当天无新 Release/提交。**推断**：“虚拟交易公司”角色叙事、金融 Agent 热度、Ollama/多 Provider 与全球 ticker 让 Demo 极易传播；上榜不能归因于已证实的单一事件，更不能视作收益证明。

## 今天最值得体验的 3 个项目

1. **[Prime Agent](https://github.com/PrimeIntellect-ai/prime-agent)**：最值得亲手验证的是“持久 IPython + 原生 Subagent + detach/attach + 有界 Autonomous”的完整长任务体验。建议在一次性 worktree/容器里做多文件调研或测试修复，先限制 Token、时间和 Shell gate；不要直接在有敏感凭据的主工作区试无人值守。
2. **[google/skills](https://github.com/google/skills)**：Google Cloud 用户可先只装 `gemini-api`、Agent Eval 或 `bigquery-ai-ml` 等一项，观察官方流程、权限确认、模板和真实命令能否减少文档检索。不要一开始全装 104 项，也不要在未确认项目/地区/费用前让 Agent 执行写操作。
3. **[mattpocock/skills](https://github.com/mattpocock/skills)**：选择一个真实但范围可控的 Feature，依次体验 grilling→domain/ADR→spec/tickets→implement→双轴 review；若需求仍模糊，HTML Prototype 比继续写代码更有价值。优先整包正式 25 Skills，避免把 in-progress/misc 当稳定依赖。

## 值得持续跟踪的新 Feature 方向

- **RLM/REPL 成为 Agent 的长期工作记忆层。** 重点不是“Python 能执行”，而是变量、工具、子 Agent 和压缩之间是否能保持一致、可回放、可控成本；需跟踪独立评测，而不是只看项目方任务样例。
- **Subagent 从一次性 fan-out 变为可恢复的协作者。** roster、消息、追问、checkpoint、跨会话恢复和权限/预算边界将比“能 spawn”本身更重要。
- **Skills 的供应链与版本合同。** 官方厂商目录会继续增长，但真正的生产问题是 SemVer、固定 commit、签名/来源、依赖 Manifest、宿主 capability matrix、行为 Evals 与撤回策略。
- **Agent 的 Day-2 质量飞轮。** 从日志抽评测集、对轨迹/工具/答案打分，再把延迟、成本、幻觉、安全与 IAM 拒绝接入告警，会成为 Agent Platform 的标准 Feature 组合。
- **设计证据作为持久 Artifact。** CONTEXT/ADR、Tracer Ticket、Wayfinder、HTML Prototype、Review Packet 等比聊天摘要更可审查、更容易跨人/跨 Agent 续接。
- **领域多 Agent 的“角色冲突 + 硬约束”结合。** TradingAgents 已展示解释性辩论，但金融、医疗、运维等高风险领域最终还要加入确定性数据窗口、真实状态、规则引擎、人工批准和可审计执行，不能只靠更多 Persona。
