## 今日 Feature 趋势摘要

1. **Agent 的竞争层已从“模型能力”上移到“工作方法和组织记忆”。** Superpowers 用强制 brainstorm→plan→TDD→review 流程约束单次交付；Compound Engineering 再把 review 结论写成可复用知识；TencentDB Agent Memory 则把 Chat、Skill、Wiki、CodeGraph 变成带 ACL 与 Loadout 的团队资产。三者共同说明用户开始为持续性、可治理性和少重复劳动买单。
2. **Agent 安全正在从提示词规则走向可观测、评测和响应。** ADR 首次把多客户端会话采集、303-task/133-MCP Server 基准与会话检测器放进同一开源仓库；但最吸引人的 Explorer 与 Prevention 仍未开放，开源 Detector 也明确是研究产物。
3. **“便宜的 fast path”仍是 AI 数据入口的高价值 Feature。** pdf-inspector 不做 OCR，却可先把原生文本 PDF 还原为 Markdown，并把疑似扫描/乱码页或区域送给外部 OCR。价值来自少花模型调用、少上传敏感文档；风险是路由信号与复杂版面仍有公开失败样本。
4. **Agent Skill 正在进入多宿主分发阶段。** reverse-skill、Superpowers、video-use 与 Compound Engineering 都把能力交付为代码 Agent 可加载的 Skill/Plugin，并覆盖 Claude Code、Codex、Cursor 等入口；但“列出支持平台”不代表安装、Hook、子 Agent、审批和工具语义完全等价。
5. **多模态 Agent 从“理解媒体”迈向“生产媒体”。** video-use 把素材盘点、转录、剪辑策略、EDL、字幕、动画并行制作、渲染与 cut-boundary 自检交给 coding agent；LiveKit Agents 则继续聚焦实时语音/视频会话、电话与调度。前者是异步创作 Skill，后者是实时应用框架，不能互相替代。
6. **低显存推理依旧有强传播力，但容量和可用性必须分开。** AirLLM 能让 2.8T Kimi K3 checkpoint 在单卡完成生成，却仍要约 1.56TB 权重、约 900 秒初始化和约 292 秒/Token；“3.72GB 峰值显存”证明能跑，不证明适合交互、Agent 循环或生产服务。
7. **今天最该删除的营销等式是：** 正式 Release ≠ 产品脱离 Beta；仓库开源 ≠ 内部生产闭环开源；跨平台清单 ≠ 功能等价；自报 benchmark ≠ 任意文档/生产流量领先；“Agent 自检” ≠ 客观质量保证；Skill 数量/路由数量 ≠ 经真实任务验证的成功率。

## Feature 深度卡片

### 1. [TencentCloud/TencentDB-Agent-Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory)

**一句话定位：** 面向同时使用多个 Coding/工作 Agent 的个人与团队，把对话、跑通的方法、文档和代码沉淀为可治理、可分配、可被下一次会话调用的四类记忆资产；它管理记忆，不运行 Agent。

**典型场景：** 长期 Coding Agent 记住项目约束；Scout/Builder/Reviewer 按角色配知识；从成功排障沉淀 SOP；导入文档/代码/历史会话做项目冷启动；自研 Agent 通过 API/Proxy 使用团队记忆。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **L0→L3 Chat Memory** | 从原对话提炼事实/偏好、项目场景与 Persona，并可回查来源 → 跨会话恢复语境而不只留黑盒摘要 → 长期助理/开发 | 已发布；抽取质量依赖 LLM，[MemoryCore](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/v2.0.0/MemoryCore/README_CN.md) |
| **Skill 资产化** | 从任务/工具调用提炼含版本、资源、触发边界、步骤和验证的 SOP → 一次成功可复用、可审核 → 排障/Review/上线 | v2.0.0 已有强制归档，[Release](https://github.com/TencentCloud/TencentDB-Agent-Memory/releases/tag/v2.0.0) |
| **LLM-Wiki** | 把文档异步整理为结构化页面和链接图谱 → Agent 少从目录头开始通读 → 产品/设计/运维文档 | 已发布；构建需 LLM，[Knowledge](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/v2.0.0/MemoryKnowledge/README.md) |
| **CodeGraph** | 索引文件、符号、调用者/被调用者和影响路径，并可定时同步 → 改代码前先看影响面 → 大仓重构/排错 | 已发；同步默认关、私库/SSH 仍不完整，[边界](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/v2.0.0/README_CN.md#%E6%B3%A8%E6%84%8F%E4%BA%8B%E9%A1%B9) |
| **Memory Hub UI** | 创建 Team/Agent/Task，搜索、审核、分配四类资产，显示 Owner/版本/状态/用量 → 人能看见并纠错 Agent 的记忆 → 团队治理 | Web UI 已发、中英文；产品仍标 Beta |
| **ACL / Owner** | private/team/restricted，并可按 User/Role/Agent 授权；新记忆默认私有 → 分享经验而非默认泄露全部隐私 → 多成员/多项目 | 已发；公网部署仍需补网络与鉴权，[说明](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/v2.0.0/README_CN.md) |
| **Agent Loadout** | 为角色绑定不同资产、优先级和用法 → 控制噪音与越权 → Scout/Builder/Reviewer 分工 | 人工装配可用；全自动路由仍在迭代 |
| **Memory Proxy** | 兼容 Anthropic `/v1/messages` 与 OpenAI `/v1/chat/completions`，自动注入并回流记忆 → 少改现有客户端 → Claude Code/CodeBuddy/Hermes/OpenClaw | 需改 Base URL、Key、headers；并非零配置，[Proxy](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/v2.0.0/MemoryProxy/README_CN.md) |
| **多客户端接入** | 提供四个具名客户端与通用兼容路径 → 团队不必锁死单一框架 → 混合 Agent 工具栈 | 更广跨框架迁移仍在路线图；Hermes/OpenClaw 会话头有手工负担 |
| **HTTP API + TS/Python SDK** | 管理记忆、Skill、团队/Agent/Task/ACL 和知识工具 → 嵌入自研 Agent → SaaS/多租户工作台 | 源码/API 有；SDK 正式包分发未完全收口，[TS](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/v2.0.0/sdk/memory-core/typescript/README_CN.md) / [Python](https://github.com/TencentCloud/TencentDB-Agent-Memory/blob/v2.0.0/sdk/memory-core/python/README_CN.md) |

**同类与易用性：** 相比 Mem0，它多 Skill/Wiki/CodeGraph/ACL/Loadout，少成熟托管、包分发、导入导出、Webhook/多模态和广泛集成；相比 LangMem，它自带团队 UI 和资产产品面，但缺任意 schema/Prompt optimizer 的轻量开发原语。UI、部署脚本、Swagger、环境模板和视频 Demo 齐；可复现 benchmark 弱，PersonaMem 48%→76% 只能算项目自报单项结果。

**限制与今日关注：** 正式 `v2.0.0` 不等于脱离 Beta；发布后已有 Core/Knowledge 构建、MCP、启动脚本问题，生产 Bearer 鉴权也未与 Proxy 完整闭环。**事实**：8 月 3 日正式发版，今日 #1、+1,111。**推断**：四类资产 + ACL + 角色 Loadout 把“记忆”从向量检索升级为团队治理叙事，是热度主因；但流量增长明显快于工程收口。

### 2. [zhaoxuya520/reverse-skill](https://github.com/zhaoxuya520/reverse-skill)

**一句话定位：** 装进代码 Agent 上下文的“安全任务路由器 + 作业手册 + 工具索引/自举 + 证据与经验回写”，让授权逆向、渗透、CTF 先选正确流程再调用真实工具；它不是自治扫描平台。

**典型场景：** APK/IPA/二进制逆向；前端 JS/协议/流量还原；授权渗透与红队演练；CTF/漏洞研究；团队复盘与可复现交付。

| Feature | 能做什么 → 用户价值 → 场景 | 状态 / 边界 |
|---|---|---|
| **PRIMARY 路由** | 按目标、意图、工具链选择方法 → 少让 Agent 猜命令 → 陌生/跨域安全任务 | v1.0.0 仅 21 个 PRIMARY；main 的 40 个仍 Unreleased，[Release](https://github.com/zhaoxuya520/reverse-skill/releases/tag/v1.0.0) |
| **宽领域技能地图** | 覆盖移动、二进制、JS、恶意样本、固件、Pwn、API、LLM、云、AD、OT/RF → 一入口找 SOP → 综合研究 | 目录存在不等于逐项实战验证，[地图](https://github.com/zhaoxuya520/reverse-skill/blob/main/skills/SKILL.md) |

| **Evidence→Finding→Path** | 关联证据、判断和可走路径 → 便于复核/交接/重跑 → 长链路调查 | 模板与 case 工具可用；非不可篡改审计库 |
| **Tool Index** | 探测本机工具路径、版本、状态并刷新索引 → 不再猜依赖是否存在 → 新分析机/多平台 | clone 后须刷新；发现工具不等于 MCP 已注册 |

**状态、同类与易用性：** 当前 README 明确 **32 Skills、0 standalone agents**；reviewer/researcher 是 Skill-local prompt，而非常驻 Agent 库。核心 MIT；最新 `compound-engineering-v3.21.1` 于 8 月 4 日发布。Claude/Cursor 有插件路径；Codex CLI 是 self-contained native plugin；Codex App 尚不在内置 marketplace，须自定义 marketplace。相比 Superpowers，它闭环覆盖 Strategy、Product Pulse、knowledge、PR babysit/UX 更广，但 TDD/逐任务双审不那么绝对；相比 Spec Kit，它跨 SDLC/反馈更广，少专用初始化 CLI；相比 BMAD，它更轻、更贴工程产物，少 backlog/sprint/story 与成套角色。无独立 UI/API/SDK/托管 Runtime，主要入口是宿主聊天与 Markdown/HTML/PR。

**限制与今日关注：** 32 Skills 带选型、Token 和时间成本；跨宿主“支持”不保证 subagent 数、审查结果、安装/Windows/WSL 行为一致。Product Pulse 不自动补埋点；知识沉淀也非自动正确；LFG 不会突破 sandbox、分支保护或替用户做产品决定。**事实**：v3.21.1 紧邻今日发布，继续修复 PR babysit、work、handoff、dispatch、scratch 长流程可靠性，今日 #18、+40。**推断**：Coding Agent 关注点上移到完整 SDLC、Codex/Claude/Cursor 多宿主和高频可靠性修复共同带来热度。

## 今天最值得体验的 3 个项目

1. **[uber/ADR](https://github.com/uber/ADR)**：先用 `adr-sensor` 导出一个非敏感测试会话，再用 packed ADR-Bench 跑 keyless LlamaFirewall smoke test。最吸引人的 Feature 是把“Agent 在做什么”的统一会话数据与 17 类、133 MCP Server 的企业安全基准放在同一套可复现入口里。务必在隔离环境中运行；不要把未开源 Prevention 当现成功能。
2. **[firecrawl/pdf-inspector](https://github.com/firecrawl/pdf-inspector)**：无需 Key，直接用[浏览器 Demo](https://firecrawl.github.io/pdf-inspector/)丢一份自有的原生文本 PDF，再用包含扫描页/双栏/表格/CJK 的真实 corpus 比较。最吸引人的 Feature 是页/区域级 OCR 升级信号；体验重点不是“看能否输出 Markdown”，而是确认何时会静默输出错误。
3. **[obra/superpowers](https://github.com/obra/superpowers)**：在一个小而真实的功能上观察它是否自动触发 Brainstorm、可执行 Plan、TDD、Review 与 fresh verification。最吸引人的 Feature 是强制把“模型说完成”改成“当前证据证明完成”。先用小任务评估流程摩擦和 Token 成本，再决定是否推广到团队。

## 值得持续跟踪的新 Feature 方向

1. **记忆从向量检索升级为可治理资产。** 关注 Skill/Wiki/CodeGraph 的版本、Owner、ACL、角色 Loadout、错误记忆撤回和跨框架可携备份，而不只看“能记住聊天”。
2. **Agent Detection & Response 的生产闭环。** 下一步不是再加一张攻击排行榜，而是 Sensor→实时检测→策略/源码/情报上下文→人审→阻断/回滚，并同时解决 prompt/工具日志的隐私治理。
3. **跨宿主 Skill 的能力协商与一致性测试。** 同一 Skill 在 Claude/Codex/Cursor 的 Hook、subagent、approval、sandbox、browser、worktree 不同；需要 machine-readable capability contract、降级路径和跨模型行为 eval。
4. **按失败概率升级昂贵能力。** PDF 先本地解析再 OCR、编码任务用便宜 Executor 只在复杂处调 Planner、语音按合规/延迟选 cascade/realtime，都是“默认便宜、失败再升级”的共同模式。
5. **Durable Artifact 取代纯聊天状态。** EDL、plan U-ID、SDD ledger、solution docs、Goal evidence、Checkpoint、product pulse 让 Agent 工作可恢复、可审查；后续关键是并发冲突、版本迁移和外部副作用回滚。
6. **创作 Agent 的可解释决策与多模态 QA。** video-use 的“带理由 EDL + cut-boundary 检查”是好起点，但仍需要连续视觉语义、音画质量指标、人工审批层级和可复现素材/成片基准。
7. **多发行面的版本契约。** Reasonix CLI/Desktop/VS Code、pdf-inspector 四语言包等都显示“项目版本”已不足够；应跟踪每个 surface 的兼容矩阵、迁移提示和安全修复传播时间。
