## 今日 Feature 趋势摘要

1. **Agent 产品正在分成“执行内核”和“控制面”。** Prime Agent 把持久 Python、可恢复 Subagent、Goal/Heartbeat/Schedule 和有界 Autonomous 做成执行内核；T3 Code 则不再造模型，专注用桌面、Web、手机远程管理本机的 Codex/Claude/Cursor/Grok/OpenCode。用户开始为“如何持续、安全地操纵多个 Agent 会话”而选工具，而不只为模型本身。
2. **Skills/Personas 已从 Markdown 文件夹升级为发行产品，但能力合同仍碎片化。** Agency Agents 有 270 个角色、16 个 CLI 目标和独立桌面安装账本；Agent Skills 有 24 Skills、8 Commands、4 Personas 与三层 Evals；Google Skills 有 104 个官方 Skill 和插件。真正决定可用性的已是 Manifest、宿主原生入口、引用依赖、升级/回滚和权限，而不是仓库写了“支持 70+ 工具”。
3. **垂直 AI 的价值越来越来自“可用工作台 + 真实边界”，而不是再讲一个模型故事。** WeatherNext 同时给权重、Mini Colab、实时/历史 Feed、Weather Lab 和托管推理；daily_stock_analysis 把数据、LLM 报告、追问、推送、历史验证与持仓风险连成产品；ComfyUI 把复杂节点图封装为 App Mode 和 API。它们也共同暴露了数据许可、外部费用、硬件、时点和误用边界。
4. **评测正在转向“真实任务、真实文档、可审查 Rubric”。** Harvey LAB 不是法律聊天机器人，而是法律 Agent 的任务集、执行 Harness、评分与比较面；Agent Skills 也对 Skill 自身做结构、路由和行为 Evals。今天值得跟踪的是评测是否覆盖工具轨迹、证据与失败方式，而不是单一平均分。
5. **代码 RAG 正从“问代码”扩展到“结构化查改与安全边界”。** Code-Graph-RAG 同时提供多语言统一图、自然语言/语义检索、AST search/replace、MCP、dead-code 与数据流判断；但 v0.0.589 刚修复结构化替换的符号链接越界，高权限 Agent 接入首先要固定安全版本和审查写操作。
6. **多模态工作流的产品化路径变得清晰：专家搭建 → 普通用户消费 → 系统嵌入。** ComfyUI 的 Subgraph、App Mode、本地 API/Cloud API 与模板库构成这一链路；强项不是某个单模型，而是同一工作流在 GUI、简化应用和生产 API 之间迁移。Custom Nodes 与 Partner Nodes 同时带来供应链、付费和兼容性成本。
7. **今天最常见的误读来自版本面。** Code-Graph-RAG 的正式 Release/PyPI 是 v0.0.589，但 tag/main 已到 0.0.591；ComfyUI v0.31.0 才是 Latest Release，v0.31.1 只是 tag；Agent Skills 的引用修复已合入 main 却未发版；T3 Code 的 main 又比 v0.0.32 超前 62 个提交。报告统一按“稳定 Release / tag / main-only”三层记录，计划、Issue 和文档残留不会写成已用 Feature。

## Feature 深度卡片

### 1. [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)

**一句话定位：** 面向开发者、研究者和评测团队的开源终端 Agent，把持久 Python 工作状态、递归 Subagent、可恢复后台会话、定时唤醒和带质量门的自主续跑组合起来，服务数小时乃至跨终端会话的代码与研究任务。

**典型场景：** 大仓库并行审查/迁移；无人值守的修复—测试循环；长跑 benchmark/数据研究；周期巡检与定时工作；通过 JSON/RPC/ACP/SDK 嵌入 IDE、评测或自研界面。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **持久 IPython RLM** | 变量、导入、函数、数据和任务句柄跨 tool call/compaction 保存 → 少重复解析上下文 → 大仓审计、研究自动化 | v0.7.1 已发；[RLM 文档](https://github.com/PrimeIntellect-ai/prime-agent/blob/v0.7.1/packages/coding-agent/docs/rlm.md) |
| **递归 Subagent** | `rlm(...)` 启动独立 child session，可并行、保留、追问和提高递归深度 → 父上下文聚焦 → 多维审查/多实验 | 已发；调用先返回句柄，结果须消息或文件回传，不是同步答案 |
| **Agent 家族通信与 Agents View** | 父、兄弟、直接子代可互发消息，用户可观察、attach、stop 和下钻树 → Subagent 可被重新定向 → 协作复核 | 已发；通信范围是 nuclear family；v0.7.0 已改 steer-only，但长任务文档仍残留旧投递模式，以 [Changelog](https://github.com/PrimeIntellect-ai/prime-agent/blob/v0.7.1/packages/coding-agent/CHANGELOG.md#070---2026-08-05) 为准 |
| **Continual Harness `/refine`** | 把轨迹经验写为补充 prompt、memory、Skill 描述或 Subagent 规格并留 before/after 快照 → 复用验证过的习惯 → 发布检查、重复研究 | 已发；不是模型权重训练，也不自动把描述变成已安装可执行 Skill |
| **daemon、detach/attach 与恢复** | 关闭 TUI 后 worker、Python 状态、子 Agent 和计划任务继续，之后 `attach/resume/doctor` → 终端断开不重做 → 长构建、benchmark | v0.7.1 已发；生命周期隔离不是安全沙箱 |
| **Goal、Autonomous 与 Quality Gate** | 持久目标；按轮次/Token/时间自动续跑；命令门失败则反馈再修 → 自治可止损且可机验 → 修到测试通过、批量升级 | 已发；gate 只证明指定命令覆盖的条件，不代表任务整体正确 |
| **Heartbeat 与 Schedule** | 会话周期重入或按时间/cron prompt 唤醒 → 用户离线时继续检查 → 部署观察、实验轮询、日报 | 已发；定时执行仍继承本机权限、凭据和模型费用 |
| **Compaction、会话树与分支** | 自动压缩旧上下文并保留 Python 状态；支持 resume/tree/fork/clone/export → 长任务与替代方案可追溯 | 已发；摘要仍可能遗漏细节 |
| **Skills、Extension 与 MCP** | 加载 `SKILL.md`、Python Skills、Creator、第三方包；接 Linear/Notion/Serper/远程 HTTP MCP → 团队流程和业务工具可组合 | 已发；自定义 MCP 暂不支持 stdio；第三方代码与 OAuth 需信任/配置 |

**开箱、配置与成熟度：** v0.7.1 安装器、TUI、会话、Subagent、daemon、Goal/Autonomous、Heartbeat/Schedule、JSON/RPC/ACP 已可用；首次有效运行仍需模型订阅或 API Key，Serper、Linear/Notion、远程 MCP 和本地模型需各自配置/费用。`main` 仅比 tag 多 3 个提交：默认开启可退出的匿名产品分析、消息 UI 和 Homebrew 归属修复，均不可倒算为稳定 Feature。[v0.7.1...main](https://github.com/PrimeIntellect-ai/prime-agent/compare/v0.7.1...main)

**同类、易用性与限制：** 相比 Claude Code，它把持久 IPython、可递归 Subagent、daemon、Goal/Heartbeat/Schedule 和 `/refine` 组合得更完整，但缺 Claude Code 的成熟权限/Hook/worktree/团队表面；相比 OpenHands，它更适合本地单人长任务编排，却缺 Web/Cloud、多用户服务、RBAC 和内建隔离。TUI、Agents View、CLI、协议文档和示例是强信号；最大限制是模型生成 Python/Shell 以用户权限运行，必须在 disposable clone、干净 worktree 或外部容器中试用。所谓 Self-improving 指 Harness 更新，不是模型自训练；RLM 也不保证每项任务更快、更省。

**今日关注：** **事实**：v0.7.1 仍是稳定版，今日 #1、+2,356；近期一周密集从 v0.5 推到 v0.7.1。**推断**：“自我改进 + 递归 Subagent + 长跑不中断”的组合叙事叠加订阅登录和快速发布，推动连续传播；Trending 无法证明具体流量来源。

### 2. [vitali87/code-graph-rag](https://github.com/vitali87/code-graph-rag)

**一句话定位：** 面向大型、多语言单仓/微服务的开发者与 Coding Agent，把源码实体及调用、继承、引用、I/O 等关系存成可查询图，让用户用自然语言查关系、回取真实源码并在确认后做精确或结构化修改。

**典型场景：** 陌生仓库上手；给 MCP Agent 补可复用结构上下文；跨仓微服务端点追踪；dead-code/数据流安全审查；批量 API 迁移与编码规范重构。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **多语言统一代码图** | 将函数/类/模块和 calls/references/inheritance 等放进统一图 → 混合仓库同一口径查询 → polyglot monorepo | 已发；需 Python 3.12+、Memgraph；Ruby 仅结构级、Scala 开发中；[语言矩阵](https://github.com/vitali87/code-graph-rag/blob/main/docs/architecture/language-support.md) |
| **自然语言图查询与源码回取** | 将问题转为 Cypher，再按 qualified name/node ID 返回真实代码 → 关系答案可核验 → 调用链、实现/影响面 | 已发；需 LLM，正确度受模型生成 Cypher和索引近似影响 |
| **语义代码检索** | 按“认证代码”等意图搜索，配本地 UniXcoder 或远程 embedding/Qdrant/Milvus → 名称未知也能找功能 → 陌生仓定位 | 可选 `semantic` extra；远程 embedding 可能上传代码并计费；图重排仍是 Issue |
| **精确编辑 + AST search/replace** | surgical replace 或 ast-grep 跨仓结构查改，默认 dry-run 看 diff → 比正则批改更稳 → API 迁移、规范化 | 已发；需 `ast-grep` extra；v0.0.589 刚修 symlink 越界任意读写，高权限 Agent 必须升级；[Release](https://github.com/vitali87/code-graph-rag/releases/tag/v0.0.589) |

**开箱、配置与成熟度：** 任务/合成文档、CLI、sandbox、静态报告、办公 Skills 和 v1.0 快照 MIT；需 Python 3.12、uv、Pandoc、Podman，Windows 还需 WSL2/虚拟化。默认 judge 需要 Anthropic Key，双 Judge 另需 OpenAI，模型执行和逐 criteria 评分均按量收费；教程单题就示例约 210k input tokens，应先 dry-run/抽样。Enterprise Search 仅 main，相关 `docs_dir` 路径加固 PR #134 尚未合并；来源不明的 task config 不应直接运行。官方暂无托管规范 leaderboard。

**同类、易用性与限制：** 相比 LegalBench/CUAD/LEXam/BigLaw Bench，它强在开放式长任务、混合办公文件、工具轨迹、成品与整库 DMS，弱在便宜、快速和跨日期标准化；相比通用 Inspect 类 harness，它自带法律数据/Rubric/Skills，弱在生态、托管监控和多 sandbox backend。CLI 和 20 分钟 walkthrough 强；UI/API/SDK/商业 DMS 连接弱。合成数据不是现实客户分布；Issues 已发现 rubric/材料冲突、错名、混入文件，LLM judge 也有字段顺序导致 verdict 翻转案例。All-pass 是高风险缺漏门，但不是唯一质量分；固定模型之外还要固定 commit/config/judge/harness/重复次数。

### 12. [pingdotgg/t3code](https://github.com/pingdotgg/t3code)

**一句话定位：** 面向同时使用多个 Coding Agent、希望保留本机代码与已有订阅的开发者，用统一桌面、Web 和移动 UI 控制本机/远端 Claude Code、Codex、Cursor、Grok Build 与 OpenCode，并把项目隔离、会话监管、Diff/终端和提交 PR 串起来。

**典型场景：** 多 worktree 并行改动；同一入口使用不同 Agent/账号；离开电脑后手机监管/批准；从 Diff 到 commit/push/PR；把无 GUI Linux 服务器变成常驻 Agent 工作站。

## 今天最值得体验的 3 个项目

1. **[T3 Code](https://github.com/pingdotgg/t3code)**：今天最鲜明的可体验 Feature 是“五个本机 Provider + worktree/thread + 手机 Remote + Diff/批准 + Subagent 状态”。先在测试仓库用 `npx t3@latest`，把默认 Full access 改为 Supervised；同一局域网体验桌面与手机，再决定是否配置 Tailscale/SSH/T3 Connect。不要用 `main` 的 Usage/图片/侧栏能力评价 v0.0.32，也不要把它当完整 IDE 或模型额度服务。
2. **[WeatherNext](https://github.com/google-deepmind/weathernext)**：先跑官方 `WeatherNextCyclones_Mini_<2024` Colab，体验“全球预测→可视化→气旋 tracker”闭环；再用 Earth Engine/Open-Meteo 观察 WN2 Feed。Mini 能在免费 v5e-1/P100 推理，最适合验证产品面，但要主动确认 1° 与 0.25° 的效果差距、公共 6h 步长和数据许可，不要先申请昂贵托管 H100。

## 值得持续跟踪的新 Feature 方向

- **Agent Control Plane 成为独立产品层。** 需要同时管理本机/远端环境、Provider、账号、worktree、权限、Subagent、Diff、成本和手机审批；关键指标会从“回答质量”扩到任务存活、可停止、可恢复和跨设备一致性。
- **跨宿主 Skills/Personas 的 Capability Contract。** 未来不应只写“支持 Codex/Claude/Cursor”，还要声明是否支持命令、persona、hook、Subagent、MCP、权限、references、project/global scope 与卸载/回滚；同一 Markdown 在不同宿主的功能矩阵会成为标准文档。
- **Skill/Agent 供应链与安装账本。** 固定 commit/SemVer、依赖 Manifest、引用完整性、来源签名、source/render hash、modified/foreign 检测、备份和撤回，将和 Skill 内容同等重要。Agency App 的 reconciliation、Agent Skills 的 validator、Code-Graph-RAG 的签名制品都是早期信号。
- **真实任务 Eval + Judge 不确定性。** 长时程任务、混合文件、共享知识库、工具轨迹和可审查成品比短 QA 更接近部署；同时必须报告 criterion 质量、Judge 分歧、人工抽查、harness 配置和成本，而不是只给 leaderboard。
- **垂直 AI 的数据时点、许可和外部有效性。** 天气 checkpoint/在线 operational model、金融免费源/新闻时点、法律合成事项/真实客户分布都不能混同。Feature 文档需要把数据生成时间、训练截止、实时/历史条款、区域和上游 SLA 变成一等字段。
- **专家工作流的“封装降维”。** ComfyUI 的 Subgraph/App Mode/API 说明复杂图可以先供专家搭建，再暴露少量参数给普通用户和系统；Agent 工具也会走向类似的 workflow→template→app/API 路径。
- **MCP 写操作的分层授权。** 代码图 RAG、Cloud Skills 和桌面 Agent 都在从只读查询扩展到写文件/改云资源。Read-only、dry-run、可逆更新、不可逆删除、付费 compute 和 path/symlink 边界需要不同批准级别，并在宿主层强制而非只写在提示词里。
- **模型之外的持久 Artifact。** 代码图、Agent harness memory、SPEC/plan、安装 ledger、天气 Zarr、法律 transcript/rubric/report、Comfy 工作流 JSON 都比聊天摘要更易审查和续接。Agent 产品的长期价值会越来越取决于这些可版本化产物。
