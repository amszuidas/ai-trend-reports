## 今日 Feature 趋势摘要

1. **Agent 竞争点从“会对话”移到“能长期工作”。** Reasonix 把 CLI/TUI、桌面、Web、VS Code、子 Agent、Checkpoint、Goal 和 MCP 合并进同一引擎；TencentDB Agent Memory 把聊天、Skill、Wiki、CodeGraph 变成可治理资产；reverse-skill 则把专业任务路由、授权和证据交付做成作业规范。用户开始为连续性、可恢复性、权限和经验复用买单。
2. **本地推理同时走向两个极端。** AirLLM 用磁盘和分钟级/Token 延迟换极低峰值显存，回答“能不能跑”；ds4 围绕少数 DeepSeek/GLM 模型交付 CLI、兼容 API、Agent、KV 复用和多机能力，回答“能不能持续用”。两者都不是通用模型服务框架的等价替代。
3. **AI 数据入口在做“便宜的 fast path”。** pdf-inspector 不做 OCR，却能先把 born-digital PDF 快速转为结构化 Markdown，并把扫描/乱码页精确路由给 OCR；这类“先分类、只为失败样本升级昂贵模型”的能力，正成为 RAG 成本和隐私优化的新焦点。
4. **语音 AI 分成开发框架与本地创作产品。** LiveKit Agents 面向实时会话、电话、调度、模型组合和测试；Voicebox 面向本地克隆、TTS/STT、长文本、故事编辑与 MCP Agent 发声。前者重交付实时应用，后者重隐私与创作者体验。
5. **领域模型开始交付可用工作面，而不只是一篇论文。** Kronos 提供金融 K 线预训练权重、批量/概率预测、微调、WebUI 和在线样例；但 large 权重未开源，预测和回测也不能被包装成投资收益保证。
6. **常青课程仍是流量入口，但边界必须说清。** AI-For-Beginners 是从符号 AI 到深度学习、CV/NLP/RL 的基础课；Generative AI for Beginners 才覆盖 Responses API、Function Calling、RAG、图像、Agent 和本地模型。二者都不是生产级 Agent 平台或部署方案。
7. **今天最需要删除的营销等式是：峰值显存 ≠ 整机资源；“free” ≠ 永久免费模型；支持平台 ≠ 无需登录/不受风控；OpenAI-compatible ≠ 所有 Responses/工具语义等价；Beta README ≠ 没有正式 Release；自报 benchmark ≠ 任意文档都领先。**

## Feature 深度卡片

### 1. [lyogavin/airllm](https://github.com/lyogavin/airllm)

**一句话定位：** 面向开发者的 Python 推理库，用极低 GPU 峰值显存换取巨量磁盘 I/O 和极高生成延迟，让本来装不进单卡的 Hugging Face 大模型至少能完成离线推理或可行性验证。

**典型场景：** 小卡验证超大 checkpoint；低显存/大 NVMe 的少量离线任务；保留原始/原生 dtype 做对照；Kimi K3、DeepSeek-V3、Qwen3 等新模型冒烟测试。**不适合**日常聊天、Agent 循环、在线 API、批量高吞吐或低延迟产品。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **极低显存推理** | 让模型总权重远大于 GPU 显存 → 不换大卡也可先验证输出 → 单卡离线实验 | 路径可用；“70B/4GB”是项目宣称，缺完整可复现记录，[说明](https://github.com/lyogavin/airllm#tiny-gpu-huge-models) |
| **Kimi K3 2.8T** | 完整 1.56TB checkpoint 可生成 Token → 把极端 MoE 纳入单机兼容测试 → 前沿模型冒烟 | v3.1.0；3.72GB 是 RTX 6000 Ada 48GB 上的峰值分配，约 900 秒初始化、292 秒/Token、长上下文未测，[PR #316](https://github.com/lyogavin/airllm/pull/316) |
| **FP8 / MoE checkpoint** | 直接加载 DeepSeek-V3、Qwen3 FP8/MoE 等格式 → 少做转换 → 新模型试跑 | v3.0；DeepSeek-V3/~12GB 未见同等级端到端测量，[Release](https://github.com/lyogavin/airllm/releases/tag/v3.0.0) |
| **统一 `AutoModel` SDK** | HF repo ID 或本地路径自动选入口，继续用 tokenizer/`generate()` → Transformers 用户迁移小 → Notebook/研究脚本 | 已发布，[Quickstart](https://github.com/lyogavin/airllm#quickstart)；受限模型仍需 HF token |
| **多模型家族** | 覆盖 Llama、Qwen、DeepSeek、Mistral、Phi、Gemma、ChatGLM 等 → 一套入口横向试模 → 选型 | “virtually every / 当天支持”不等于逐变体验证，[列表](https://github.com/lyogavin/airllm#supported-models) |
| **4/8-bit 磁盘压缩** | 缩小每次读取量，项目宣称最高 3× → 在 I/O 瓶颈下缩短等待 → 离线推理 | 需 `bitsandbytes`；与 prefetch 不可同时用；速度/精度缺统一复现，[说明](https://github.com/lyogavin/airllm#model-compression---3x-inference-speed-up) |
| **Prefetch / Profiling** | 预取下一段权重并输出耗时 → 判断磁盘、搬运或计算瓶颈 → 硬件调优 | README 约 10% 自报；适用路径有限，[配置](https://github.com/lyogavin/airllm#configurations) |
| **缓存/磁盘控制** | 指定拆分目录并可删除原件 → 管理 TB 级权重位置和双份占用 → 多盘工作站 | `delete_original` 有删除后崩溃报告，先备份，[Issue #297](https://github.com/lyogavin/airllm/issues/297) |
| **CPU 推理** | 无 CUDA 也能完成加载和生成 → 扩大可验证硬件 → 极少量冒烟 | 可用但极慢；4/8-bit 路径仍有 CUDA 依赖 |
| **Apple Silicon / MLX** | M 系列 Mac 可用专门路径运行 → 无 NVIDIA 也能试 → 本地研究 | 仅 Apple Silicon，输入类型仍有开放 bug，[Notebook](https://github.com/lyogavin/airllm/blob/main/air_llm/examples/run_on_macos.ipynb) |

**开箱/配置/同类：** `pip install airllm` 和 Python SDK 已可用；K3 还需 `compressed-tensors`、`flash-attn`、CUDA 12 Torch、Transformers 4.56.x，并承担 TB 级磁盘/带宽。相比 llama.cpp/Ollama，它强在直接接 HF checkpoint、把“可运行模型上限”推得极高；缺 CLI/Web UI、GGUF 管理、REST/OpenAI API、并发、工具调用、多模态和广泛硬件后端。相比 vLLM，它不提供高吞吐、连续批处理、分布式生产服务。

**限制与今日关注：** 峰值显存不是整机资源；405B Notebook 用 bnb 4-bit 且无执行输出；DeepSeek-V3 是预量化 FP8，不能支撑“完全不量化”；remote code 与 pickle 权重还带供应链风险。**事实**：v3.1.0 于 7 月 29 日发布 K3 支持，今日 +1,085。**推断**：“2.8T → 3.72GB”的传播反差最可能推动上榜，但它证明的是可行性，不是交互可用性。

| **Discord/Telegram + Voice Note** | 远程排队/分支/停止 Claude Code，Whisper/NIM 转语音任务 → 手机可调用固定工作区 → 异地开发 | 非实时双向语音；Bot、Allowed User/Channel/Directory 与转录后端需配置，[Integrations](https://github.com/Alishahryar1/free-claude-code#optional-integrations) |

**开箱/配置/同类：** 一行脚本、Admin 和默认 NIM 路线最短，但先审阅远程安装脚本；NIM、OpenRouter/Gemini/Groq 免费层均可限流/改规则，付费 Key 仍按各家计费，本地则承担硬件成本。相比 OpenRouter 直连，它多本地 Provider、档位映射、桌面和手机语音，但多一个 daemon；相比 LiteLLM 缺虚拟 Key、预算、负载均衡、Fallback、审计和多租户；相比 Claude Code Router 更聚焦三客户端和固定 Profile，却缺自定义转换、Key Pool、条件路由、成本观测和 Linux GUI。

**限制与今日关注：** 本地公共 API 默认监听面与示例 Token 需要改为强随机值并优先绑定 loopback；Key/OAuth 存于 `~/.fcc`，Raw 日志可能含会话，Bot 权限就是代码执行边界。工具、Thinking、图片、Compaction 和长上下文必须逐模型验收；当前无 Releases/Tags，安装追随 main，版本固定/回滚较弱。**事实**：当前包 4.16.6，近期密集加入 ChatGPT OAuth、Codex App Catalog 与 Provider 兼容修复，今日 #12、+278。**推断**：名字击中成本焦虑，加上 31 Profile、三客户端和 GUI/手机入口形成传播；高星不等于所有 Provider 已生产稳定。

### 14. [livekit/agents](https://github.com/livekit/agents)

**一句话定位：** 面向要把实时语音、视频或电话 Agent 做成生产产品的开发团队，把模型编排、自然打断、工具/工作流、WebRTC/SIP、部署、观测和测试接在同一套实时媒体平台上。

| **Handoff/Tasks/Workflows** | 多 persona、任务组和 supervisor 拆长流程并保留 Session → 更易测试维护 → 接待转专家/多阶段收集 | 编码能力成熟；不是拖拽式业务流程套件，[Workflows](https://docs.livekit.io/agents/logic/workflows/) |

### 16. [jamiepine/voicebox](https://github.com/jamiepine/voicebox)

## 今天最值得体验的 3 个项目

1. **[pdf-inspector](https://github.com/firecrawl/pdf-inspector)：先体验“便宜地知道什么时候该用 OCR”。** 浏览器 Demo 或 CLI 对一份 born-digital PDF、一份扫描件、一份复杂表格各跑一次；重点看 Markdown、页分类和区域级 OCR 建议。它最吸引人的不是“万能解析”，而是把快速本地路径和昂贵 OCR 分开。不要用项目固定无 OCR 语料的 benchmark 外推所有业务文档。
2. **[Reasonix](https://github.com/esengine/DeepSeek-Reasonix)：体验一个 Agent 如何同时拥有规划、工具、子 Agent 与恢复点。** 从 TUI/桌面任选一入口，配置一个模型和一个只读 MCP，完成“计划→执行→Checkpoint→恢复”的小型仓库任务。最值得看的是多入口共享的 Goal/上下文与子 Agent 工作面；高权限工具、Windows sandbox 与兼容 API 仍需单独验收。
3. **[Voicebox](https://github.com/jamiepine/voicebox)：用本机打通“听写→精修→克隆发声→MCP”。** 先用 Kokoro/Whisper 验证安装，再只用本人或获授权的 10–30 秒音频试 Qwen 0.6B，并让一个 MCP Agent 播报结果。它把本地输入、输出、编辑和 Agent UX 做成了罕见的完整产品组合；不要把它当全双工/电话平台，也不要一次下载全部模型。

## 值得持续跟踪的新 Feature 方向

1. **精确升级而非全量升级的 AI 数据入口：** 页/区域级质量判定、可解释 OCR 路由、隐私分类和成本预算，会比“所有文档先过大模型”更适合规模化 RAG。
2. **Agent 记忆从向量检索升级为可治理资产：** Chat、Skill、Wiki、代码关系、ACL、Loadout、来源和删除/导出需要统一；下一步应关注跨框架可移植与自动路由的准确率，而非只数存储类型。
3. **编码 Agent 的恢复性和并行治理：** Checkpoint、Goal、子 Agent、证据链、Tool 权限和可审计回放正在汇合；真正的分水岭会是失败恢复、冲突处理和权限隔离的可测指标。
4. **Realtime Agent 的体验指标产品化：** Turn detection、误打断恢复、Fallback、电话转人工、语音回归测试和分段延迟观测，正从插件变成第一等 Feature；需要同时披露语言、Cloud/本地和数据保留边界。
5. **本地双向语音成为 Agent 的系统入口：** Dictation + 本地精修 + TTS + MCP 很有潜力，但下一阶段必须补鉴权、真实流式/VAD、移动端、声纹同意/水印与跨平台输入稳定性。
6. **本地大模型工具从“能加载”分化为“能服务”：** 峰值显存、首 Token、每 Token 延迟、并发、KV 复用、模型/工具协议正确率应同时报告；AirLLM 与 ds4 恰好代表容量验证和持续服务两端。
7. **Provider 网关需要能力元数据与故障治理：** 模型选择器若没有 Context、Tools、Vision、Reasoning、价格和限额元数据，很容易“能聊不能编程”；自动 Fallback、预算、强 Token、日志脱敏和团队 RBAC 将决定是否能从个人玩具走向基础设施。
