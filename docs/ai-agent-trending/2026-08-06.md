## 今日 Feature 趋势摘要

1. **Agent 的“电脑”正被拆成持久工作区和分层执行环境。** Cloudflare Computer 让一份持久 Workspace 在 Worker 文件 API、受限 Shell、JavaScript isolate 和完整 Linux Container 之间共用；最有价值的是“状态不随执行环境丢失”，不是屏幕/鼠标/浏览器自动化意义上的 Computer Use。
2. **长时间 Agent 任务开始需要独立的“控制平面”。** LoopX 把 Goal、Todo、Gate、Evidence、Quota、唤醒与交接从 prompt 记忆提升为可检查状态；TencentDB Agent Memory 再把对话、Skill、文档和代码变成可审核、可授权、可给不同 Agent 装配的资产。前者管循环，后者管知识，都不是模型或 Agent runtime。
3. **Coding Agent 的差异化越来越像“可安装的工程制度”。** Agent Skills 用 24 个 Skill、8 个生命周期命令和 4 个审查 Persona 覆盖需求到上线；Superpowers 用 14 个 Skill 强制 brainstorm→plan→TDD→review→verify。前者更广、更中性，后者更小、流程约束更强；两者都不代替 IDE、沙箱、模型或真实测试环境。
4. **成熟 AI 工具的新功能正从“再加一个模型”转向降低集成摩擦。** Supervision 0.30.0 把 OpenCV 改为可选，新增 Soft-NMS、LabelMe/CreateML、GeoTIFF 窗口读取与批量 slicing；pdf-inspector 则用本地分类、Markdown 和页/区域 OCR 信号把“什么时候值得调贵价 OCR”产品化。
5. **Agent 运行时开始补齐可观测和可安全停止。** Reasonix v1.20.0 加入原生任务监视器、有界子 Agent 进度、`update_goal` 安全完成、本地决策回执与 Extension Protocol v1；ADR 从另一侧提供多客户端会话观测、303-task/133-MCP 攻防基准和离线检测，但实时 Prevention 仍未开源。
6. **今日最该删除的营销等式是：** 有 npm/PyPI 包 ≠ 适合生产；“Computer” ≠ GUI Computer Use；正式 Release ≠ 产品脱离 Beta；支持多宿主 ≠ Hook/Persona/Subagent 功能等价；“低显存能跑” ≠ 可交互/可服务；项目自报 benchmark ≠ 普遍 SLA。

## Feature 深度卡片

### 1. [cloudflare/computer](https://github.com/cloudflare/computer)

**一句话定位：** 面向在 Cloudflare Workers/Durable Objects 上构建 Agent 的开发者，把每个 Agent 的文件长期保存在一份 Workspace，并让受限 Shell、JavaScript isolate 与完整 Linux Container 共享它；它是持久工作区 SDK，不是开箱即用的桌面 Computer Use。

**典型场景：** 长期对话/编码 Agent 保存代码与产物；模型先写 Markdown、Container 再调 pandoc 生成 PDF；低延迟 isolate 处理文本、遇到依赖安装/编译时升级 Container；生成仓库后发布为可 clone Artifacts；将图片/报告通过 R2 短链交付。

| Feature | 能做什么 → 用户价值 → 场景 | 状态 / 边界 |
|---|---|---|
| **Durable Workspace FS** | read/write/edit/ls/grep 与流式 I/O，状态随 Durable Object 保留 → 不再把文件状态塞入 prompt → 长任务/工作目录 | Preview 已发布；单 DO 存储上限受计划限制，[DO limits](https://developers.cloudflare.com/durable-objects/platform/limits/) |
| **FS-only 模式** | 不注册执行后端也可用 Workspace → 纯文件型 Agent 不必启动沙箱 → 笔记/资产生成 | 可用；仍需 Worker + SQLite DO + nodejs_compat，[快速开始](https://github.com/cloudflare/computer/blob/main/packages/computer/README.md#quick-start) |
| **统一多后端 runtime.exec** | 按 backend ID 在 Shell/JS/Container 间选择、首次懒连接 → 同一文件树按需升级算力 → 混合 Agent 工作流 | 可用；无公开 capability discovery，[#50](https://github.com/cloudflare/computer/issues/50) |
| **Container 完整 Linux** | 运行真实 shell、Node/Python、包管理器、自定义二进制与网络 → 覆盖编译/测试/转换 → Coding Agent | 需 Workers Paid/Container binding，本地需 Docker，[Containers](https://developers.cloudflare.com/containers/) |
| **Worker Shell** | 在 Dynamic Worker 运行 just-bash 及 grep/sed/jq/find 等 → 小任务冷启动更低 → 文本/代码搜索 | 不是完整 Linux、无公网；Dynamic Workers 付费且 open beta，[示例](https://github.com/cloudflare/computer/tree/main/examples/worker-shell) |
| **Worker JavaScript Code Mode** | 新 isolate 执行 ECMAScript module，输入/输出结构化，桥接 FS/Git/Artifacts → 少解析 shell 文本 → 数据转换/受限自动化 | 默认无网络、显式库/env；同样依赖 Dynamic Workers beta，[示例](https://github.com/cloudflare/computer/tree/main/examples/worker-javascript) |
| **AI SDK Tools** | createAITools() 生成 read/write/edit/ls/exec/publish 工具 schema → 少写 Agent tool glue → 对话/编码 Agent | 需 ai/zod 及自备模型循环；edit 宽松匹配有开放风险 [#51](https://github.com/cloudflare/computer/issues/51) |
| **Workspace Git** | 无系统 Git 也可 clone/add/commit，Shell 可用内建 git → isolate 也能版本化交付 → 代码生成 | 显式启用；Shell 只支持 HTTPS，status/log 已有边角 issue，[Git 文档](https://github.com/cloudflare/computer/blob/main/packages/computer/README.md#git) |
| **R2 只读挂载** | 将 bucket 投影为 Workspace 目录，写入返回 EROFS → 安全提供语料/模板 → RAG 预处理 | 需 R2 binding；不是通用可写对象存储挂载，[Container 示例](https://github.com/cloudflare/computer/tree/main/examples/container) |
| **Assets 短链交付** | Workspace 文件上传 R2，返回有时效的 presigned URL → 直接交付报告/图片 → 生成式 Agent | 需 R2 S3 凭据，示例明标 production-only cloud path，[Assets](https://github.com/cloudflare/computer/tree/main/examples/assets) |
| **Artifacts Git 交接** | 按 session 创建/列出 repo、签发 token、push → Agent 结果可 clone → 多租户代码交付 | Cloudflare Artifacts 仍 private beta，[官方公告](https://developers.cloudflare.com/changelog/post/2026-04-16-artifacts-now-in-beta/) |
| **事件流/取消/观测** | exec handle 可转 SSE，支持 get/kill/dispose 与 observer → UI 能看进度、长任务可停 → 异步 Agent | 部分示例仍 run-and-collect；长会话需手工 dispose stub，[执行文档](https://github.com/cloudflare/computer/blob/main/packages/computer/README.md#running-commands-and-code) |

**开箱/配置/实验：** npm @cloudflare/computer 已到 0.1.1，FS-only、Git、8 类 runnable examples 可试；Shell/JS 需付费/open-beta Dynamic Workers，Container 需 Workers Paid，Assets 需 R2，Think 示例需 Workers AI，Artifacts 需 beta 权限。整个包 README 明确写 **Preview only / NOT suitable for production**，docs/ 是前瞻规格，不能当已交付能力。

**同类与易用性：** 相比 [Cloudflare Sandbox SDK](https://developers.cloudflare.com/sandbox/api/)，Computer 独特之处是“文件持久性优先，多后端共享”；Sandbox 有更完整的进程、PTY、预览 URL、mount/backup。相比 [E2B](https://www.e2b.dev/docs)，Computer 更 Cloudflare-native，却缺 Python SDK、模板 VM、桌面/Computer Use 和托管控制面。项目有 TypeScript SDK、TUI/Web 对比示例、tutorial 与可复现性能文档，无独立管理 CLI/UI、Python/MCP、在线公开 Demo。

**限制与今日关注：** 它没有浏览器/屏幕/键鼠；Worker 后端不是真 Linux，顺序大 I/O 和大仓库不是优势，且 Cloudflare 计费/锁定明显。**事实：** 今日 #1、+891，0.1.x 新包。**推断：** “Give your agent a computer”、Cloudflare 品牌与可视化示例共同推高传播；真正值得试的是持久 Workspace 原语，不是标题暗示的完整“电脑”。

### 2. [huangruiteng/loopx](https://github.com/huangruiteng/loopx)

**一句话定位：** 给已在使用 Codex、Claude Code、OpenCode 或自有 runner 的维护者一个本地长任务控制面，把跨多轮/多天/多 Agent 的目标、待办、决策、证据、配额与交接保存为可恢复状态；它不执行 Agent 工作。

**典型场景：** 多日 Issue/PR 修复和评审；长周期研究/基准/ML 实验；配额感知的 PR watch/日报/巡检；Claude 实现、Codex 复核的跨宿主接力；有发布/外部写入审批门的内容和运营工作。

| Feature | 能做什么 → 用户价值 → 场景 | 状态 / 边界 |
|---|---|---|
| **Durable Goal State** | 持久 objective/scope/todo/gate/evidence/history/quota → 换会话仍能恢复 → 多日开发/研究 | v0.4.x 核心可用，[Capabilities](https://github.com/huangruiteng/loopx#capabilities) |
| **Typed Todo / Claim / Lease** | 按用户/Agent、推进/监控分类，peer 先 claim 再写回 → 少重复/抢写 → 多 Agent 分工 | 可用；宿主 identity 仍有边角 issue，[#2785](https://github.com/huangruiteng/loopx/issues/2785) |
| **Concrete Human Gates** | 把“等用户”变成具体决策，允许已审计 safe fallback → 人只处理真正判断 → 发布/隐私/方案 | 可用；不会代用户授予凭据/生产权限，[Current status](https://github.com/huangruiteng/loopx#current-status) |
| **Quota-aware Auto-Wake** | should-run 判断 run/wait/pause，无变化 monitor 静默且不计 slot → 少空转/花费 → 巡检/长任务 | 可用；宿主必须消费 scheduler hint，LoopX 不是通用 scheduler，[Quota](https://github.com/huangruiteng/loopx/blob/main/docs/quota-allocation.md) |
| **Evidence / Review Packet / Handoff** | 记录验证、blocker、accepted writeback 并生成 owner packet → “完成”有证据 → PR/实验/交接 | 可用；200+ 小时案例是 wall-clock 轨迹，不是连续自治运行，[Evidence](https://github.com/huangruiteng/loopx#evidence) |
| **多宿主 Adapter/Bridge** | 连 Codex App/CLI、Claude /loop、OpenCode、shell/webhook/worker/custom runner → 不必重写 Agent → 混合工具团队 | 分层可用且需配置；Claude opt-in，OpenCode 需 Bun/持久 TUI，[Connector catalog](https://github.com/huangruiteng/loopx/blob/main/docs/integrations/runtime-connector-catalog.md) |
| **CLI 上手/恢复** | no-clone 安装、doctor/connect/start-goal/update/backup → 接入与故障回退明确 → 多项目管理 | 核心可用；Python 3.11+、macOS/Linux shell，[Getting Started](https://github.com/huangruiteng/loopx/blob/main/docs/guides/getting-started.md) |
| **Read-first Dashboard/Status API** | 本地 UI 展示 goal/gate/todo/quota/evidence，CLI/JSON 仍是真值源 → owner 快速理解状态 → 多项目总览 | Dashboard experimental preview，写 API 默认关闭，[Dashboard](https://github.com/huangruiteng/loopx/blob/main/apps/presentation/dashboard/README.md) |
| **Capability Packs / Presets / Auto Research** | Issue-Fix、content ops、periodic report、daily triage、PR watch 与多角色研究 → 不再每次重写 prompt → 维护/运营/研究 | 成熟度混合；外部 provider/权限自备，启动 pane 不等于有结果，[Capability index](https://github.com/huangruiteng/loopx/blob/main/docs/capabilities/README.md) |
| **Explore Graph/Harness** | 记录节点/关系/finding/blocked frontier，planner 只读排序 → 长研究变知识图 → 实验/复杂问题 | supported optional、默认关闭；planner 不 claim/launch/spend，[Explore](https://github.com/huangruiteng/loopx/blob/main/docs/capabilities/explore/README.md) |
| **Reward Memory / Turn Recall** | 按 project/surface/agent/authority/freshness 召回历史纠错 → 复用偏好而不扩大授权 → Issue-Fix | 实验、provider-neutral、default-off；自动 recall/ingest 默认 false，[Reward Memory](https://github.com/huangruiteng/loopx/blob/main/docs/reference/protocols/reward-memory-architecture-v0.md) |

**开箱/配置/实验：** MIT、CLI 核心无外部 runtime dependency，Goal/Todo/Gate/Evidence/Quota 可直接使用；模型、Agent、scheduler、凭据和外部写入均在宿主。Claude/OpenCode/Auto Research/Dashboard/Lark/Reward Memory 各有显式配置。“Loop Agent / always-running digital worker”仍是方向；Reward Memory、Dashboard、Explore Harness 和部分 adapter 不应写成普遍稳定。

**同类与易用性：** 相比 [LangGraph](https://docs.langchain.com/oss/python/langgraph/persistence)，LoopX 不需把现有 Agent 重写成 graph，强在跨宿主 ownership/quota/gate/evidence，缺成熟 graph SDK、time travel 和托管部署。相比 [OpenHands](https://docs.openhands.dev/sdk/index)，它更轻且不绑 executor，但没有 LLM loop、工具箱、沙箱、成熟 GUI/IDE 和托管 RBAC。CLI/JSON 是最成熟表面，另有 Dashboard、presets、双语文档和公开长轨迹；集成列表不等于同等 qualification。

**限制与今日关注：** --harden 不是安全沙箱；Codex CLI headless 路径被维护者称不太成熟，pi-agent 支持仍无结论；高级 planner/reward 多是合同、预览或建议。**事实：** v0.4.1 于 8 月 4 日发布，今日 #2、+326，Release 主动说不声称长程 outcome uplift。**推断：** 用户痛点从“单轮会不会做”转向“多天如何不失控/不空转”，跨 Codex/Claude/OpenCode 与可视化状态让它容易传播。

### 5. [firecrawl/pdf-inspector](https://github.com/firecrawl/pdf-inspector)

**一句话定位：** 面向企业安全/AI 平台和 Agent 开发者，把 Cursor、Claude Code、Codex 等本地会话统一为安全遥测，再用 MCP 攻击基准与分层 LLM Detector 发现风险；当前开源只有 Sensor、ADR-Bench、Detector，Explorer、生产后端与 Prevention 未开放。

**典型场景：** 审计员工 Coding Agent 的意图/工具链；MCP 上线前回归；调查 prompt injection/凭据/越权/外传；比较 ADR 与 LlamaFirewall；加入组织自己的 MCP、策略、任务和威胁变体。

| Feature | 能做什么 → 用户价值 → 场景 | 状态 / 边界 |
|---|---|---|
| **多客户端 Sensor** | 解析 Claude Code、Cursor、Cline、Claude Desktop Agent Mode、Codex CLI、Warp 本地日志 → 不改主流程获得审计面 → 端点调查 | adr-sensor 1.0.0/PyPI Beta；公开表实际 6 客户端、无 Windows 条目，[Sensor](https://github.com/uber/ADR/tree/main/Sensor) |
| **统一 AgentEvent** | 归一 session、用户/主机/模型/路径、chat、工具参数/结果/状态 → 下游不逐工具适配 → 检测/SIEM/取证 | 开箱可用；公开包只落 JSON/JSONL，远传/SIEM 自建 |
| **CLI/Python/增量导出** | 按来源/会话/目录采集，默认近 14 天、可 all-history → 快速试用或嵌批处理 → 单机/cron | 可用、无 UI；依赖客户端缓存路径/格式。8 月 6 日 Warp 窗口修复只在 main |

### 13. [lyogavin/airllm](https://github.com/lyogavin/airllm)

**一句话定位：** 给显存装不下目标 Hugging Face 模型、且愿意用磁盘 I/O 和极高延迟换“至少能完成推理”的研究者/开发者使用；它压低超大模型单卡 VRAM 门槛，不提供实时聊天、Agent 或高吞吐生产服务。

**典型场景：** 70B/405B/671B/Kimi K3 checkpoint 可行性验证；低频离线私有批处理；租云前检查 tokenizer/prompt/输出；教学演示总权重远超 VRAM 仍可推理；用统一 AutoModel 对常见 HF 文本模型做低显存脚本实验。

| Feature | 能做什么 → 用户价值 → 场景 | 状态 / 边界 |
|---|---|---|
| **极低 VRAM 超大模型推理** | 模型总权重大于显存仍能 generate → 无同量级 GPU 也可验证 → 本地 smoke/教学 | 正式功能；70B≈4GB/405B≈8GB 等数字缺统一复现资产，[#295](https://github.com/lyogavin/airllm/issues/295) |
| **Kimi K3 2.8T / MXFP4** | 对约 1.56TB checkpoint 生成真实 token，短提示峰值 3.72GB → 超大 MoE 获得单卡路径 → K3 研究 | v3.1.0 已发；测试卡是 RTX 6000 Ada 48GB，非实体 4GB 卡；4 token/短上下文，[PR #316](https://github.com/lyogavin/airllm/pull/316) |
| **统一 AutoModel** | HF repo ID/本地路径自动选已支持模型类 → 少模型族专用初始化 → Llama/Qwen/DeepSeek/Mistral 对比 | Python API 可用；“几乎所有流行模型”不是认证矩阵 |
| **原生 HF / Safetensors** | 直接读 HF 分片/非分片 checkpoint，无需转 GGUF → 新模型少转换 → 原始权重研究 | 已发；gated 模型需 token；默认 remote code 与 pickle bin 有安全 issue [#293](https://github.com/lyogavin/airllm/issues/293) / [#296](https://github.com/lyogavin/airllm/issues/296) |
| **FP8 / MXFP4 预量化格式** | 直接用发布方低精度 checkpoint → 减搬运/显存 → DeepSeek/Qwen3/K3 | 已发；不是所有量化格式，GGUF 仍请求中 |
| **可选 4/8-bit 压缩** | 减小分层副本和读取字节 → 缓解容量/I/O → 较老 HF 模型 | 需 bitsandbytes；“最高 3×/几乎无损”不能泛化，[#330](https://github.com/lyogavin/airllm/issues/330) 实测反而慢 3.8–8× |
| **Shard 缓存/空间管理** | 指定分层路径、可删原件，K3 hard link 避免再复制 1.56TB → 管理多盘 → 大 checkpoint | 已发但高风险；首次可能双份占盘，delete_original 有问题报告 |
| **Prefetch / Profiling** | 尝试重叠读盘/计算并输出耗时 → 找 I/O 瓶颈 → SSD/PCIe 调优 | 预取明确只支持 AirLLMLlama2，压缩组合有兼容报告 |
| **CPU 推理** | 无 CUDA 也可走 CPU 路径 → 扩大可验证环境 → CI/极低频离线 | 已发但文档/性能证据薄，不能期待实用速度 |
| **Apple Silicon / MLX** | Mac 用 MLX + PyTorch 跑部分模型 → 非 NVIDIA 用户可试 → 个人实验 | 仅 Apple Silicon；不能外推 K3 已在 Mac 验证 |
| **Notebook / Transformers 风格** | pip 安装后 tokenizer + model.generate；通用、405B、macOS notebook → 熟悉 HF 的用户容易修改 → 单人研究 | 无 K3 专用 notebook、GUI、正式 CLI、REST/OpenAI server、Docker、Agent/RAG 集成 |

**关键测量边界与依赖：** [v3.1.0](https://github.com/lyogavin/airllm/releases/tag/v3.1.0) 的同一次 K3 运行使用完整约 1.56TB checkpoint、RTX 6000 Ada 48GB、短提示；初始化/链接约 900 秒，4 token 用 1168 秒，即约 292 秒/token，生成峰值 3.72GB。长上下文 KV cache、视觉输入、并发与其他 GPU 未测。K3 还需 compressed-tensors、flash-attn、CUDA 12 PyTorch 和 Transformers 4.56.x；普通包版本范围更宽，不代表 K3 能用 Transformers 5.x。

**开箱/配置/实验：** pip + AutoModel 对列明的常见 HF 家族可试；权重、磁盘、RAM/GPU、带宽和电费由用户承担，gated 权重许可另算。K3 长上下文/视觉/多轮工具、完整 VRAM 自适应、AMD/ROCm、GUI、Ollama 集成、多 GPU、流式服务仍未验证或处于 issue/PR，不能当现成功能。

**同类与易用性：** 相比 [Accelerate Big Model Inference](https://huggingface.co/docs/accelerate/en/usage_guides/big_modeling)，AirLLM 把极低 VRAM/逐层落盘包装得更直接并专门适配 K3；Accelerate 的 device map、多 GPU/多设备生态更成熟。相比 [llama.cpp](https://github.com/ggml-org/llama.cpp)/[Ollama](https://docs.ollama.com/api/introduction)，它直接吃 HF checkpoint、规模上限高，后者的 CLI/Web UI、GGUF、本地 API、流式/工具/视觉更适合交互。相比 [vLLM](https://docs.vllm.ai/en/stable/)，两者目标相反：AirLLM 求“能跑一次”，vLLM 求并发吞吐。AirLLM 只有轻量 Python/Notebook，服务、运维和集成面明显弱。

**限制与今日关注：** 显存小不等于整机门槛小；292 秒/token 不适合聊天、Coding Agent、RAG 或工具循环；无 HTTP server、batching、认证、限流、监控、SLA；“AI Agents Recommendation”只是推广链接，不是 Agent 能力；只应加载可信且固定 revision 的 safetensors。**事实：** v3.1.0 于 7 月 29 日发布，今日 #13、+833。**推断：** “2.8T / 1.56TB / 单卡峰值 3.72GB”的反差极易传播；许多 Stars 更可能是收藏极限方案/关注后续，而非已经下载权重做生产复现。

## 值得持续跟踪的新 Feature 方向

1. **持久 Workspace 与分层执行升级：** 轻 isolate 先做低风险/低冷启动操作，必要时升级 Linux/网络，同时保持同一文件状态；下一步看 capability discovery、后台进程、PTY、预览端口、快照/恢复和跨云可移植性。
2. **Agent 控制面独立化：** Goal/Todo/Gate/Evidence/Quota 不再只存在于聊天；值得跟踪 scheduler hint 标准、跨宿主 identity/lease、no-spend monitor、可审计 handoff 与 owner-facing read-first UI。
3. **可治理的团队记忆资产：** 从“向量库里有历史”升级为带 Owner/版本/ACL/状态的 Chat/Skill/Wiki/Code assets；重点不是更多召回，而是自动路由何时可信、私库/敏感数据怎样授权、错误记忆如何撤销。
4. **Agent Skills 的能力契约与 Evals：** 安装兼容需要继续升级为 commands/personas/hooks/subagent/tool parity；三层路由 eval、真实行为 trace、单 Skill 自包含 references 和多个元路由器冲突处理会决定 Skills 能否团队化。
5. **长任务的可观察、可停止与可恢复：** Task lifecycle、子 Agent 有界进度、Goal fail-closed completion、决定回执、压缩后恢复正在从“好用 UI”变成 Agent runtime 的基础能力。
6. **AI 数据入口的按失败升级：** PDF 原生 fast path、页/区域 OCR 信号、损坏文档恢复与质量回执可显著减少昂贵模型调用；下一阶段看公式/图表/图片语义、静默漏文检测和跨解析器策略评测。
7. **模型工具链的依赖减法：** Supervision 去掉 OpenCV 强依赖说明成熟 AI infra 的价值常在环境兼容、格式互操作和迁移清晰度，而非再加模型；同时要跟踪 Dataset API、tracker 拆包和后端像素一致性。
8. **Agent Detection & Response 的开源闭环：** 端点遥测和 benchmark 已出现，下一缺口是实时阻断、SIEM/OTLP、敏感遥测脱敏/RBAC/留存、Windows/多客户端稳定解析，以及 benchmark 与生产误报之间的校准。
9. **容量可达性与服务可用性的分离：** AirLLM 证明超大 checkpoint 可以在极低 VRAM 完成生成；下一步真正有用户价值的指标应包括首 Token/每 Token、总磁盘、长上下文峰值、吞吐、并发与可恢复服务，而不是只报峰值显存。
