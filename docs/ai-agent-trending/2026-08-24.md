## 今日 Feature 趋势摘要

1. **“Agent harness + Skills/Plugins”占据榜单主流。** Codex、mattpocock/skills、ECC、Ruflo、Awesome Agent Skills、Claude Plugins 与 free-claude-code 都在回答同一个产品问题：如何把模型变成可复用、可管理的工程工作流。差别很大——有的是完整 Agent runtime，有的是方法论/提示词资产，有的是目录或协议网关，不能统称为“Agent 框架”。
2. **Agent 正从私有终端走向共享工作区和可恢复执行。** Buzz 让人类与 Agent 共用频道、Git 和审计；Maka 记录可恢复的 append-only 执行事实；OpenHuman 把多 Agent 与可视 workflow 放入个人桌面；Hermes 则强化跨设备、持久会话和技能成长。用户价值从“帮我回答”转向“长期接手工作”，同时放大权限与状态治理难度。
3. **记忆开始要求可读、可改、可追溯。** OpenHuman 的 Obsidian Memory Tree、Maka 的持久事件记录、Ruflo 的语义记忆与 Codex/ECC 的项目指令/Memory Vault 都尝试让上下文跨会话延续。真正需要验收的不是“有记忆”，而是来源、更新、删除、错误纠正和是否会把推断写成事实。
4. **模型路由与“免费额度聚合”成为独立产品面。** free-claude-code、OpenHuman、Codex、Hermes 都允许不同程度的 BYOK、本地模型或 provider 切换。它能降低锁定和成本，但“列出 Provider”不等于工具调用可靠；“1.3B+ 免费 Token”“ToS-friendly”也没有自动变成可复算额度或法律保证。
5. **多模态创作从单一 Prompt 走向可复用生产资产。** awesome-gpt-image-2 把案例蒸馏成模板、JSON Prompt 和 Agent Skill；ComfyUI 用节点图、模型/节点生态、队列与 API 支撑可复现图像/视频流程。两者分别解决“如何表达需求”和“如何执行复杂管线”，不是同一种产品。
6. **功能面扩张速度超过稳定性面。** 当天项目里大量版本仍处于 0.x、Beta、rolling `main` 或无 Release 状态；README 数量口径、宿主兼容、付费边界与已发布包经常不一致。采用前应 pin 版本、从最小 Feature 路径复现，并保留人工审批和用量上限。

### 18. [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)

**一句话定位：**给希望长期自托管、跨设备使用且不绑定单一模型的个人和小团队，把“能记住用户、能积累流程、能调工具并长期驻留”的 Agent 带到 CLI、桌面、消息平台和远程主机。

**典型场景：**VPS 个人助理跨消息平台续会话；本地/远端工程操作；并行研究/审查；定时日报/监控；语音、浏览器和桌面自动化。

**同类、成熟度与缺口：**与 OpenClaw 重叠很大，Hermes 较突出的组合是可审核的记忆/Skill 学习闭环、细粒度 Provider routing、Subagents、API/ACP 和广泛 remote terminal；OpenClaw 的复杂 channel bindings/多 Agent 配置不等价迁移。Hermes 不是原生手机 App，代码质量也不能因工具面广而推定超过专用 Coding Agent。最新稳定版为 [v0.20.5 / v2026.8.19](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.8.19)。完整体验至少需要模型；浏览器、语音、消息、MCP 与远端均各有依赖/费用。

**限制与营销边界：**“自我改进”是记忆和文本 Skill 更新，不是模型权重自主训练；错误经验可能固化。Subagents 放大 Token；Computer Use 会触达真实账号/UI；反检测/CAPTCHA 表现部分来自第三方 backend；本地小模型工具质量会降级。高频补丁意味着生产应锁 tag、启 approvals、给 Cron/远程动作设预算与隔离环境。

**今日关注：****事实**：榜单 #18、+454，v0.20.2–0.20.5 密集发布，新增 zero-key web、群组 Bot、文件/PDF、Cron memory 与语音改进。**推断**：从一次性 Coding Agent 转向长期驻留、跨设备、有记忆的个人 Agent，正是当前关注方向；低门槛 onboarding 与迁移话题可能推动再次上榜。

## 今天最值得体验的 3 个项目

1. **[Codex](https://github.com/openai/codex)**：最值得体验的是 `codex agents`/`queue` 的多任务管理、受控 Sandbox/Review，以及从 `codex exec` 到 SDK/App Server 的可嵌入路径。它既能立刻用于真实仓库，也能验证“编码 Agent 平台”而不只是聊天 CLI；建议从只读解释或 `/review` 开始，再逐步放开写权限。
2. **[ComfyUI](https://github.com/Comfy-Org/ComfyUI)**：最吸引人的是增量重算、可从媒体恢复 workflow、Subgraph/Blueprint 和 App Mode；同一图还能通过 API/CLI/MCP 进入自动化。它代表多模态生成从一次性 Prompt 走向可复用生产管线；初次试用优先用官方模板和 Desktop，暂不安装不明 Custom Nodes。
3. **[Hermes Agent](https://github.com/NousResearch/hermes-agent)**：最值得看的是可审核的记忆/Skill 学习闭环、默认三并发 Subagents、跨设备 handoff 与 Cron/voice/browser/provider routing 的组合。它能检验“长期驻留个人 Agent”是否真的适合日常工作；建议先启写入审批、限定工作目录和预算，不让 Computer Use 直接碰高风险账号。

**备选观察：**Maka 的持久执行事实、崩溃恢复与内置 Eval 很有差异，但仍处 Incubator/CLI Beta，更适合跟踪或受控 PoC；Buzz 的“Agent 进入公共房间”也值得团队型用户试验，但协作产品面尚早。

## 值得持续跟踪的新 Feature 方向

1. **Agent harness 平台化：**关注 CLI 是否能共享到 SDK、App Server、Action、IDE 和 Cloud，而不是每个入口重复实现；审批、流式事件和会话恢复是否同一契约尤其关键。
2. **人类—Agent 公共协作面：**Agent 独立身份、频道权限、Git/工作流事件、取消/接管与审计将成为团队采用基础；Buzz 的移动、push、huddle 和完整审批是否落地值得追踪。
3. **可恢复、事件化执行：**Maka 的 append-only record、Hermes 的跨入口会话、OpenHuman 的 durable workflow 都指向“进程/模型上下文出错后还能继续”；需观察真正跨重启 job、幂等、回滚和因果追溯。
4. **可读可改的长期记忆：**不仅要有向量召回，还要来源、diff、删除、容量、错误纠正和写入审批；应持续追踪 OpenHuman 的记忆幻觉修复、Ruflo 的持久 driver 与 Hermes/ECC 的 review gate。
5. **Skill/Plugin 供应链治理：**目录正在快速扩张，但缺统一版本锁、兼容测试、权限/费用/维护健康标签和语义 eval。固定 SHA、安全扫描、渐进披露与宿主兼容矩阵将比条目总数更重要。
6. **Provider 路由的成本与合规控制：**下一步不只是 fallback，而是免费额度可复算、预算熔断、凭据隔离、数据留存政策、工具兼容矩阵和逐 Provider ToS 证据。
7. **Agent 驱动的多模态生产：**ComfyUI 的 App Mode/MCP/SDK 与 awesome-gpt-image-2 的模板/Skill 正在汇合；值得跟踪 Agent 自动构图的可靠性、工作流元数据保留、模型/节点版本锁和可视人工验收。
8. **资料“编译”为 Skill：**book-to-skill 展示了 narrow-and-deep 的知识资产形态；未来关键不是再加格式，而是 OCR/多栏/图表、逐条引用、语义忠实度评测、版权/私有发布和增量更新冲突处理。
