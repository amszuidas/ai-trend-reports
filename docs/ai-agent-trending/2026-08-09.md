## 今日 Feature 趋势摘要

1. **长任务 Agent 的卖点已从“能自治”转向“状态能否存活并可治理”。** Prime Agent 把持久 IPython、可恢复 Subagent、daemon、Goal、Heartbeat、Schedule、预算与质量门放在同一终端体验里；其未发布 `main` 又加入默认开启、可关闭的匿名使用分析，说明恢复能力之外，遥测与信任边界也成为产品 Feature。
2. **Skills 正从 Markdown 文件夹变成有发行入口的插件产品。** Google 已同时给出 `npx skills`、Claude、Codex 与 Antigravity 安装面；`agent-skills` 的 `main` 也补齐 Codex 原生插件流程。真正值得关注的是 Manifest、版本、依赖、安装后能力和回滚，而不是仓库声称支持多少宿主。
3. **Skill 的“引用完整性”是会直接阻断任务的功能问题。** `agent-skills` 0.6.6 中 11 个 Skills 的共享 checklist 路径可失效；`main` 已修复并加 CI，但尚未发布。对于生产团队，链接校验、依赖打包和行为 Evals 与 Skill 内容本身同等重要。
4. **官方云 Skills 开始覆盖 Agent 的 Day-2。** Google 的目录不只教人调用 Gemini，还覆盖部署、端点、Prompt、RAG、调优、模型注册、评测飞轮、告警与故障排查；价值从“生成一段示例代码”扩展到上线后的质量、费用与可靠性治理。
5. **多 Agent 的有效价值仍在“把分歧显性化”，不是把角色数量当收益保证。** TradingAgents 用分析师、多空研究、风险角色和组合经理公开冲突与复盘，适合研究假设压力测试；没有真实组合状态、券商执行、严格回测和硬风控时，不能把它包装成自动赚钱系统。
6. **今天最该删除的营销等式：** Self-improving ≠ 模型自训练；RLM ≠ 必然更快/更省；官方 Skill ≠ 零配置云能力；104 Skills ≠ 104 项都稳定；跨 70+ 宿主 ≠ Feature 同构；历史日期分析 ≠ 严格回测；多 Agent 交易 ≠ 投资建议。

## Feature 深度卡片

### 1. [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)

**一句话定位：** 面向开发者与 AI 研究者的开源终端 Agent，把持久 Python 工作台、原生递归 Subagent、可回滚的 Harness 改进和可断线续跑的后台任务组合起来，服务代码、深研和长周期自动化。

**典型场景：** 多专家并行审查代码/文档；数小时到数天的迁移、实验或监控；先用 Python 筛选大仓库/数据再压缩给模型；用测试命令作为自治质量门；把反复工作沉淀为记忆、Skill 或 MCP 集成。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **持久 IPython RLM 工作台** | 模型用一个 Python 工具编排文件、Shell、数据、Skills 与委派，变量/导入跨轮次与压缩保留 → 少重复读上下文 → 大仓分析、研究自动化 | v0.7.1 已发；[RLM 文档](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/rlm.md) |
| **原生递归 Subagent** | `rlm(...)` 创建独立会话/目录的子 Agent，可并行、保留、恢复和追问 → 主上下文更聚焦、任务可扩展 → 审查、测试、调研 | v0.6 起已发；结果靠消息/文件回传；[v0.6.0](https://github.com/PrimeIntellect-ai/prime-agent/releases/tag/v0.6.0) |
| **Agent 直接通信** | 父、兄弟和直接子代可查看 roster、互发消息并继续既有会话 → 少由用户人工中转 → Reviewer 复验、协同排障 | 已发；只覆盖 nuclear family，跨层需中继；[长任务文档](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/long-running-agents.md) |
| **Continual Harness `/refine`** | 从轨迹小步更新补充提示、记忆、Skill 描述和 Subagent 规格，并记录历史/支持回滚 → 验证过的经验可跨会话复用 → 重复评测、项目习惯 | 已发；不是模型权重训练，也不替代人工审查可执行 Skill；[Runtime](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/rlm-runtime.md) |
| **后台 daemon 与重连** | 会话、Python 状态、子 Agent、队列和调度在关闭 TUI 后继续，可 `attach/status/doctor` → 终端断开不必重做 → 长构建、监控 | v0.7.1 修复 worker 恢复卡死；[Release](https://github.com/PrimeIntellect-ai/prime-agent/releases/tag/v0.7.1) |
| **Goal、Heartbeat、Schedule 与有界 Autonomous** | 持久目标、周期/定时重入和按轮次、Token、墙钟、Shell gate 自动继续 → 自治可止损、可巡检 → 部署观察、测试轮询、长修复 | 已发；需用户设置预算、权限与 cron 预期；[Usage](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/usage.md) |
| **压缩、会话树、分支与恢复** | 自动压缩旧上下文，保留最近消息/Python 状态，并可浏览、fork、clone、resume → 长任务不中断、替代方案可回溯 → 复杂实验/排障 | 已发；压缩摘要仍可能遗漏细节；[Sessions](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/sessions.md) |
| **多模型、订阅与本地端点** | 可用订阅登录或 API Key 接多家云模型及 OpenAI-compatible 本地端点 → 在质量、隐私、成本间选择 → 企业云/本地实验 | 已发；模型能力、费用和工具调用兼容度不等；[Providers](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/providers.md) |

**开箱、配置与实验边界：** macOS/Linux 安装器、TUI、会话、Subagent、daemon、Goal/Autonomous、JSON/RPC/ACP 已进 v0.7.1；启动仍需模型订阅或 API 凭据。Serper 网搜、Linear/Notion、远程 MCP、本地模型、定时与第三方包各需认证、运行环境或费用。RLM/Continual Harness 的增益仍是早期研究结论；Windows 的 IPython 路径、stdio MCP 和稳定 SDK 不能提前算成熟能力。

**同类、易用性与限制：** 相比其上游 [pi](https://github.com/earendil-works/pi)，Prime Agent 功能强项是持久 RLM、原生 Subagent 注册表、Agent 直连、daemon、Goal/Heartbeat/Schedule/Autonomous 与 Continual Harness；弱项是无安全沙箱、无官方 Web/桌面 UI、API 兼容仍快速变化。TUI、Agents View、安装校验、AGENTS.md、Prompt/Skill Creator 和密集文档是强易用性信号；但模型生成的 Python/Shell 以用户权限运行，应在干净 worktree/容器内试用。官方 [RLM 实验](https://www.primeintellect.ai/blog/rlm) 也出现部分任务更差且耗时/Token 更高，不能宣传为普遍增益。

开放问题进一步限定了“长任务可靠性”：Harness 条目对子 Agent 的默认可达性仍有限（[#819](https://github.com/PrimeIntellect-ai/prime-agent/issues/819)），并发写可能丢更新（[#929](https://github.com/PrimeIntellect-ai/prime-agent/issues/929)），单次 headless 模式可能在子 Agent/auto-refine 收尾前退出（[#792](https://github.com/PrimeIntellect-ai/prime-agent/issues/792)），Goal 等待凭据或人工批准时可能空转耗 Token（[#986](https://github.com/PrimeIntellect-ai/prime-agent/issues/986)）。这些是已报告边界，不等于每次必现，但足以反对“无故障无人值守”的表述。

**今日关注与上榜：** **事实**：稳定版仍是 v0.7.1；`main` 比 tag 超前 3 commits，新增“匿名、聚合、默认开启但可关闭”的使用分析及两项 UI/安装修复，这些尚未发布。[Unreleased Changelog](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/CHANGELOG.md)、[Settings](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/docs/settings.md)。今日 #1、+2,483。**推断**：Self-improving、RLM、原生多 Agent 和断线续跑同时踩中热点，叠加前一日 v0.7.1 与主流订阅入口，推动继续传播；具体流量来源不可从 Trending 证明。

| **Checkpoint 与正确性防护** | 每节点 SQLite 恢复，并处理标的身份、行情快照、前视过滤、图形配置感知 ID 和 LLM retry → 少重跑、降低明显泄漏 → 高成本深研 | Checkpoint opt-in；v0.3.1 已改善但不等于严格回测；[v0.3.1](https://github.com/TauricResearch/TradingAgents/releases/tag/v0.3.1) |

**开箱、配置与实验边界：** Apache-2.0、CLI、Python 接口、报告、模拟流程和决策日志可本地运行；yfinance/Polymarket 可无 Key，但仍有稳定性/限流。必须配置云 LLM 或自备 Ollama/兼容模型与硬件，多 Agent/多轮会显著增加 Token 与延迟。Alpha Vantage、FRED、Azure/Bedrock 各需 Key、账号或费用。Analyst 并行、官方 Codex/MCP 合同、第一类 portfolio context、确定性跨阶段检查和数据来源审计尚未交付；没有官方真实券商、资金托管、交易授权与合规审计。

**同类、易用性与限制：** 相比 `ai-hedge-fund`，它强在双层辩论、恢复、持久反思、数据/模型 Provider 和时点修复，弱在 Web 试玩；相比 Qlib/FinRL，强在自然语言解释和多角色研究，弱在数据/特征、模型训练、严格回测、组合状态、绩效指标和执行。CLI、Python 示例、Docker、env 模板、报告和视频 Demo 齐全，但无独立文档站/REST/UI。历史日期分析不是严格 backtest，模型可能从预训练权重知道未来事件；结果不可复现，数据时点仍可能错，公开流程没有真实 holdings/capital/constraints，风险委员会也不是硬风控引擎。[Reproducibility](https://github.com/TauricResearch/TradingAgents#reproducibility)。

**今日关注与上榜：** **事实**：v0.3.1 仍是最新稳定版；`main` 比 tag 超前 6 个修复/文档提交，但仓库自 7 月 18 日后没有新的主分支 Feature commit。今日 #7、+153。**推断**：“虚拟交易公司”的角色叙事、金融 Agent 热度、Ollama/多 Provider 和全球 ticker 让 Demo 易传播；上榜不能归因于已证实的单一事件，更不能视作收益证明。

## 今天最值得体验的 3 个项目

1. **[Prime Agent](https://github.com/PrimeIntellect-ai/prime-agent)**：最值得亲手验证的是“持久 IPython + 原生 Subagent + detach/attach + 有界 Autonomous”的完整长任务体验。建议在一次性 worktree/容器里做多文件调研或测试修复，先限制 Token、时间和 Shell gate；若试 `main`，先看匿名分析设置，不要直接在有敏感凭据的主工作区无人值守运行。
2. **[google/skills](https://github.com/google/skills)**：Google Cloud 用户先只装 `gemini-api`、Agent Eval 或 `bigquery-ai-ml` 等一项，观察官方流程、权限确认、模板与真实命令能否减少文档检索。不要一开始全装 104 项，也不要在未确认项目、地区、配额和费用前让 Agent 执行写操作。
3. **[mattpocock/skills](https://github.com/mattpocock/skills)**：选一个真实但范围可控的 Feature，依次体验 grilling→domain/ADR→spec/tickets→implement→双轴 review；若需求仍模糊，先产 HTML Prototype 比继续写代码更有价值。优先整包正式 25 Skills，避免把 in-progress/misc 当稳定依赖。

## 值得持续跟踪的新 Feature 方向

- **RLM/REPL 成为 Agent 的长期工作记忆层。** 重点不是“Python 能执行”，而是变量、工具、子 Agent、压缩和恢复之间是否一致、可回放且可控成本；需要独立评测而不是只看项目方样例。
- **Subagent 从一次性 fan-out 变成可恢复协作者。** roster、消息、追问、checkpoint、跨会话恢复、权限和预算边界将比“能 spawn”更重要。
- **Skills 的供应链与版本合同。** 需跟踪 SemVer、固定 commit、签名/来源、依赖 Manifest、引用完整性、宿主 capability matrix、行为 Evals 和撤回策略。
- **Agent 遥测的最小化与可选择性。** 长任务需要 TTFT、失败、重试、压缩等观测，但默认值、事件字段、数据驻留、安装 ID、组织策略和离线模式必须成为明确可审查的 Feature。
- **Agent 的 Day-2 质量飞轮。** 从日志抽评测集，对轨迹/工具/答案打分，再把延迟、成本、幻觉、安全和 IAM 拒绝接入告警，会成为平台标准组合。
- **设计证据作为持久 Artifact。** CONTEXT/ADR、Tracer Ticket、Wayfinder、HTML Prototype、Review Packet 比聊天摘要更可审查，也更容易跨人/跨 Agent 续接。
- **领域多 Agent 的“角色冲突 + 硬约束”。** 金融、医疗、运维等高风险领域最终还要加入确定性数据窗口、真实状态、规则引擎、人工批准与可审计执行，不能只靠更多 Persona。
