6. **本地优先越来越强调“用户可查看和可恢复”。** claude-obsidian 把来源、主张和事务落到普通文件；OpenHuman 把长期记忆同步为可编辑 Obsidian Vault，并用审批/恢复处理多 Agent 与工作流；AI Job Search 也把个人资料和申请产物留在本机。需要注意：本地文件归属不等于模型推理、连接器调用或网页抓取天然离线。
7. **易用性与治理成熟度继续分化。** Browser Use、OpenHuman、Free Claude Code 提供 UI/CLI/API/SDK 等多个入口；Skills/目录类项目更轻，但能力和风险由宿主及第三方条目决定。Claude 官方目录有策展、固定 SHA 和统一安装，却仍明确不保证所有第三方 MCP/软件；滚动 `main` 内容库也应锁 commit 再采用。

## Feature 深度卡片

### 1. [tt-a1i/archify](https://github.com/tt-a1i/archify)

**一句话定位：**面向开发者和架构师，把系统描述、仓库上下文或 Mermaid 语义交给 Coding Agent，产出带校验、交互探索和多格式导出的自包含技术图；它不是通用拖拽绘图软件或运行时拓扑发现器。

**典型场景：**新成员仓库导览；PR/设计变更审阅；解释 CI/CD、缓存 miss、Agent 工具调用和审批流；梳理数据血缘、PII 与生命周期；把可交互单 HTML 附到 PR、文档和演示中。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 条件 |
|---|---|---|
| [Agent 原生自然语言制图](https://github.com/tt-a1i/archify#quick-start) | 在 Cursor、Claude Code、Codex、OpenCode、Raven 等宿主中从描述/仓库生成并对话式改图 → 无需先学专用 DSL → 架构说明/代码库导览 | 稳定；需 Node 18+ 与能读 Skill、访问文件、执行命令的 Agent；Mermaid 是 Agent 重构输入，不是无损 parser |
| [五种 typed 图](https://tt-a1i.github.io/archify/#diagram-types) | Architecture、Workflow、Sequence、Data Flow、Lifecycle 分别表达拓扑、泳道、调用、数据与状态 → 用正确视觉语言减少误读 → 技术沟通 | 稳定、开箱即用 |
| [JSON IR + 校验 receipt](https://github.com/tt-a1i/archify/tree/main/archify/schemas) | 对 schema、布局、走线、标签和产物做确定性检查，失败返回对象/规则/测量证据 → 图源可 diff、错误可修 → 正式文档/CI | 稳定；结构/几何通过不等于内容事实正确 |
| [单文件交互 Viewer](https://tt-a1i.github.io/archify/gallery.html) | 搜索/聚焦节点、追踪 authored route/reach、角色对比、主题/预设与演示 → 接收者无需安装即可下钻 → PR/会议/离线分享 | 稳定；只解释作者写入的关系，不是运行时依赖发现 |
| Guided Views / Story / 深链接 | 定义有限章节并分享 focus、route、reach、lens 或 view 状态 → 同一大图面向不同听众讲解 → 评审/培训/复盘 | 稳定、可选配置；运动尊重 reduced-motion |
| 四种视觉预设与品牌标识 | Classic/Signal Flow/Blueprint/Editorial × 暗亮主题，稳定版含 107 个有来源 brand marks → 提高识别和展示质量 → 云/工具架构图 | `v2.15.0`；未知图标需联网 capture 并固定 SHA-256 |
| 多格式导出与 Share Cards | 导出 PNG/JPEG/WebP/SVG/WebM，复制图片并生成全图/Route/Reach 1200×630 卡片 → 一份源覆盖 README、社交和演示 → 发布传播 | 稳定；WebM/剪贴板依赖浏览器，无专用 PDF/PPTX 按钮 |
| Last-Good Preview / Atomic Delivery | 只在新版本全部通过后刷新或替换最终 HTML，并保留上个可用版本 → 多轮 Agent 编辑不破坏正在展示的产物 → 正式交付 | 稳定、显式 CLI 模式；不是后台 SaaS |
| [Revision-verified Evidence](https://github.com/tt-a1i/archify/issues/59) | Architecture 节点绑定公开 GitHub、完整 SHA 和源码行范围，交付前核验并可点击打开 → 降低虚构路径风险 → 开源仓库导览 | 稳定但仅 Architecture、公开 GitHub、本地 repo root；不证明运行拓扑 |
| Architecture Delta | 比较两份已验证快照，生成 Before/Delta/After、精确变化列表和 receipt → 少靠肉眼找图 → 架构 PR/迁移审阅 | 稳定；需 ID 稳定的两份 JSON，不推断风险、blast radius 或 merge safety |
| Deployment Ownership Profile | 显式要求 owner、region、私有数据库与边界连线等 authored facts → 把部署图遗漏变成门禁 → 生产部署评审 | 稳定、opt-in；不发现真实云资源，也不验证线上一致性 |

**可用性、同类与缺口：**一条 `npx skills add tt-a1i/archify -g` 可安装，另有 `doctor/demo/guide/validate/preview/deliver/compare/visual-check` CLI、11 个 Proof Lab 场景、JSON 示例和中英文文档。相比 Mermaid/D2，Archify 强在 Agent 对话、质量 receipt、证据、Delta 和完整 Viewer，弱在图类型广度、自动布局、PDF/PPTX 与编辑器生态；相比 Structurizr，它更轻、更适合单件 Artifact，但缺 C4 workspace、ADR、长期架构库和多人协作。

**限制与今日关注：**“可验证”主要验证结构与 authored facts，不是事实/因果/性能自动发现；通用 auto-layout、WYSIWYG、托管分享、移动端产品面和无损 Mermaid 转换均不在当前范围。最新稳定版是 [`v2.15.0`](https://github.com/tt-a1i/archify/releases/tag/v2.15.0)，`main` 的 `v2.16.0-dev.0` 中文 Viewer 仍未稳定发布。**事实：**今日 #1、+1,035，已有真实在线 Artifact、近期品牌/证据/Delta 交付；**推断：**强视觉 README、Agent Skill 低门槛和“可交互且有证据”击中 AI 制图可信度痛点，共同推动传播。

### 2. [freestylefly/awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2)

## 今天最值得体验的 3 个项目

1. **[Archify](https://github.com/tt-a1i/archify)：体验“Agent 产物也可以可检查”。** 最吸引人的组合是 typed JSON → fail-closed receipt → 单文件交互 Viewer → revision evidence/Architecture Delta。建议先用一个 8–12 组件的公开仓库做 Architecture，再故意制造一处 schema/布局错误观察 repair receipt；不要一上来画超大图。
2. **[Browser Use](https://github.com/browser-use/browser-use)：体验“现有 Coding Agent 接上真实浏览器”。** 最值得试的是 CLI 3.0/Skill 自动附着可见 Chrome、本地 Agent 的 Pydantic 输出，以及在关键动作插入确定性 Tool/人工确认。先用只读抽取或测试站点，别把已有高权限 Profile 直接交给未限域任务。
3. **[awesome-gpt-image-2](https://github.com/freestylefly/awesome-gpt-image-2)：体验“从案例到结构化 Prompt 的最短路径”。** 先在 535 条画廊按场景/风格筛选，打开 22 个模板之一，再让 Style Skill 产 Prompt；这比直接试官网生成器更能代表项目本身，因为 Skill 不出图、官网入口又受登录/积分/方形 low 输出限制。

> 如果愿意投入更长时间，下一优先是 [claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian)：它的 Source/Claim Ledger 和可恢复事务比普通“AI 笔记”更值得验证，但初次 setup、独立 Vault 和证据审阅明显更重。

## 值得持续跟踪的新 Feature 方向

1. **Agent Skills 的可移植性从“路径兼容”走向“行为兼容”。** 下一步需要 machine-readable capability/permission/dependency manifest、tested-on 矩阵、版本锁、断链监控和宿主一致性测试，而不只是 1,000+ 数量徽章。
2. **Agent 产物的证据与事务门禁。** Archify 的 revision evidence/receipt、claude-obsidian 的 source/claim ledger + atomic apply、AI Job Search 的 reviewer + PDF/ATS 都在把“模型说了”升级成“产物可审、失败可停、改动可恢复”。
3. **Computer Use 的混合执行。** Browser Use 展示了自然语言 Agent + Custom Tools/Playwright/CDP + HITL/Cloud Browser 的阶梯；真正生产化的关键会是域名/动作策略、side-effect confirmation、schema 结果、重放和费用上限。
4. **目录/插件供应链治理。** Claude 两个 marketplace、Scientific Agent Skills、Awesome Agent Skills 都暴露同一问题：策展/扫描/SHA/测试分别解决不同风险，仍需端到端锁定动态 MCP、包管理器 `latest`、许可证和数据目的地。
5. **Local-first 从“文件在本地”走向“推理/Embedding/连接器分层”。** OpenHuman 和 claude-obsidian 都必须分别说明存储、推理、Embedding、抓取和 OAuth 是否出站；未来值得跟踪按 workload 的可证明 egress policy，而不是笼统的 local-first 标签。
6. **垂直科学 Agent 的安全契约。** Scientific Agent Skills 的临床/实验边界、Marin 的公开失败实验和 provenance 都很有价值；下一步是把结构测试、安全扫描、科研正确性验证和人类审批拆成可核验的不同门禁。
7. **从回答到可交付多模态 Artifact。** 技术图、图像 Prompt、网页演示、文章、PDF/ATS 材料和公开实验站点共同上榜，说明用户更愿意采用能产出可分享、可复查、可再编辑对象的 Agent Feature。
