## 今日 Feature 趋势摘要

1. **Agent 产品正从单一聊天面扩展到“浏览器 + 工作区 + 业务系统”的行动表面。** ego lite 让 Agent 复用真实登录态又隔离任务空间；holaOS 聚合桌面应用、浏览器、文件与 MCP；Macro 则把邮件、聊天、任务、通话和 CRM 变成共享上下文。共同价值是少搬运上下文，但权限、动作确认和数据边界也随之放大。
2. **Agent 的可复用能力正在产品化为规范、插件和领域 Skill。** Cursor Plugins 提供插件清单与官方目录，Spec Kit 把规格驱动流程封成跨 Agent 命令，Diagram Design 把制图规则封成可安装 Skill，Awesome DeepSeek Agent 则提供多宿主配置指南。它们分别是插件生态、开发流程、专业能力包和教程集合，不能混为一种“Agent 框架”。
3. **端侧 AI 继续从“能跑模型”走向具体交付。** Needle 在约 14MB 模型中提供工具调用、结构化抽取、检索和置信信号；Modly 将 image-to-3D 做成跨平台桌面工作流；Unsloth Desktop 把聊天、RAG、训练、导出与本地服务放进同一界面。主要门槛已从 API 接入转向硬件、模型许可、动作安全和版本兼容。
4. **RAG/上下文基础设施越来越重视可调试、可编辑与可问责。** RAGFlow 让团队检查 chunk、召回与引用，再把知识用于 Agent workflow；Semantica 强调 Context Graph、Decision、provenance、规则和本体。前者更像应用工作台，后者更像治理工具箱，都不能仅凭“降低幻觉/合规”口号替代实际验收。
5. **“开源核心 + 托管/企业 AI”边界成为采用前必须读懂的功能条件。** Macro、holaOS、ToolJet 都提供可自托管代码，但托管模型、OAuth 审批、团队记忆、企业 AI Builder 或高级治理并不当然随开源版等价交付；报告按 CE/托管/Enterprise 分层记录。
6. **Release surface 仍然碎片化。** Diagram Design、Cursor Plugins、Awesome DeepSeek Agent 没有统一正式 Release；holaOS 使用滚动 `latest`；Needle 的 PyPI/engine/main 仍在快速变动；Unsloth 最新 Beta 版本线更新频繁。对生产使用，pin 版本和按实际宿主复现比看 README 更重要。

### 2. [cactus-compute/needle](https://github.com/cactus-compute/needle)

**一句话定位：**给移动端、嵌入式和资源紧张的本地应用一个超小“自然语言 → 工具调用/结构化数据”模型；它不是通用聊天模型、长上下文推理 Agent 或安全执行平台。

**典型场景：**离线设备命令；App 内动作路由；票据/联系人结构化抽取；edge-first/cloud-fallback；领域工具模型定制。

| Feature | 能做什么 → 用户价值 → 场景 | 状态 / 条件 |
|---|---|---|
| 14MB 单文件模型 | 45M Needle 2 以单 `.cact`/engine 本地运行 → 小设备、隐私、无持续云调用成本 | 首次从 [Hugging Face](https://huggingface.co/Cactus-Compute/needle2) 下载；约 28MB RAM 是项目方测量 |
| Schema grammar | 按工具名、字段类型/枚举/范围约束解码 → 减少坏 JSON 和非法形状 | 已交付；只保证结构，不保证参数语义、授权或动作安全 |
| Python typing/Pydantic/raw schema | 从函数、类型或 JSON Schema 注册工具与抽取对象 → 原型到强约束接入 | PyPI 2.0.4 可用；复杂 schema/union 仍应按实际版本回归 |
| `complete()` / `run()` | 前者只返回调用供宿主审核；后者执行并回灌结果形成最多 8 步循环 → 兼顾受控集成与快速 Demo | `run()` 不自带审批、沙箱、幂等、回滚或权限治理，高风险动作优先 `complete()` |
| Typed extraction | 把短文本直接转成 Pydantic/JSON 对象 → 少写解析和重试胶水 | 已交付；不做 OCR，也不保证字段一定来自原文 |

## 今天最值得体验的 3 个项目

1. **[Diagram Design](https://github.com/cathrynlavery/diagram-design)** — 最低摩擦、最容易在几分钟内判断是否有价值。最吸引人的不是“图型多”，而是从网站建立品牌 profile、把旧 draw.io/Mermaid 按受众/尺寸/细节重绘并给出删改 ledger，再用静态优先动效交付。先用一个 10 节点以内的真实旧图测试；如果需要复杂拓扑、实时数据或多人画布，就不应选它。
2. **[Needle 2](https://github.com/cactus-compute/needle)** — 最适合验证端侧 Agent 到底能否从“离线聊天”走到“可靠动作路由”。建议先在 Playground 注册 5–20 个真实工具，比较 grammar 合法率、top-5 漏召回和 confidence 阈值，再决定是否微调；高风险动作只让 `complete()` 返回候选，由宿主确认后执行。
3. **[Spec Kit](https://github.com/github/spec-kit)** — 最适合软件团队体验“Agent 工作流产品化”。从一个真实中型 Feature 走 constitution → specify → clarify → plan → checklist → tasks → analyze → implement → converge，观察它是否提前暴露歧义和遗漏；小修不要机械跑全流程，组织采用前再评估 preset/bundle/catalog。

## 值得持续跟踪的新 Feature 方向

1. **共享浏览器/桌面环境的权限模型。** ego lite、holaOS、Macro 都让 Agent 进入真实登录态和业务对象；下一步关键不是“能点多少网站”，而是 profile 隔离、逐动作授权、可撤销、审计和最小权限能否成为可配置产品能力。
2. **可检查、可编辑、可迁移的长期记忆。** Macro 的团队记忆、holaOS 的 Markdown 记忆、RAGFlow 的四类 memory、Semantica 的 Context Graph 代表不同层级；值得跟踪统一导出、删除/失效、来源、冲突解决与跨 Agent 迁移，而不只是“记得更久”。
3. **Agent 流程组件的版本化供应链。** Spec Kit 的 extension/preset/bundle/catalog 与 Cursor Plugins 的多组件 manifest 都在把 prompt/SOP 变成可安装软件；需要继续看签名、依赖锁定、权限声明、compatibility test、回滚和组织私有目录。
4. **端侧工具调用的校准与安全执行。** Needle 已把 grammar、retrieval、confidence 和微调压进很小模型；真正决定能否上设备的是多语言校准、大工具目录 recall、动作风险分级、离线审计和跨平台高层 SDK。
5. **RAG 从回答质量转向“中间产物可观测”。** chunk 修订、Retrieval Test、引用回看、GraphRAG/目录增强会继续普及；下一步应关注版本化回归集、权限继承、删除同步、引用覆盖率和端到端 eval，而不是只增加解析器名称。
6. **决策 provenance 与政策门禁。** Semantica 把 decision、causal chain、PROV-O、temporal、ontology 放在一起；值得观察其 eval、跨后端一致性、未知状态处理和真实合规审计是否成熟，也要看这类能力如何与通用 Agent runtime 对接。
7. **多模态 Agent 产物进入可编辑流水线。** Diagram Design 与 Modly 的价值都来自“生成后还能按交付目标重绘/后处理/导出”；未来更值得看的不是再多一个生成模型，而是版本、人工修改、质量检查、格式 round-trip 和资产管理。
8. **开源核心与商业 AI 层的透明度。** ToolJet、Macro、holaOS 都同时存在 OSS、托管或 Enterprise 面；应持续要求功能矩阵按源码、镜像、license、模型路径、credits、数据流和版本拆清，而不是只看“open-source AI-native”标签。
