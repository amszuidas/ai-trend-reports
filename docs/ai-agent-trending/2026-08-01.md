## 今日 Feature 趋势摘要

1. **Skill 正从“提示词文件”升级为可路由、可分发、可治理的产品单元。** `reverse-skill` 用领域路由、授权门和证据链约束安全任务，`last30days` 把多源研究封成跨宿主 Skill，OpenWork 则进一步用 Marketplace、RBAC 和单一 MCP 向团队分发能力。
2. **Agent 产品出现两种互补入口：把 Agent 嵌进应用，或把应用做成 Agent 工作台。** Copilot SDK 面向开发者把 Copilot Agent 会话、工具和事件放进自己的服务；jcode 与 OpenWork 面向终端用户提供可直接工作的 TUI/桌面环境。
3. **跨客户端复用成为高频 Feature，但“有配置指南”不能等同于功能平权。** OpenWork Connect、`last30days` 和 `reverse-skill` 都强调可迁移到多种 Agent；真实差异仍在宿主是否验证、是否支持 Hooks/MCP/工具权限，以及配置是否需要外部服务。
4. **可见、可审阅的执行面比纯聊天更受重视。** OpenWork 的 Artifacts/内置浏览器、jcode 的侧栏/图表/多会话和 Chatwoot 的 Inbox/人工接管，都在把 Agent 输出变成用户能检查、继续编辑或接管的工作对象。
5. **成熟 AI 资产与新 Agent 基础设施同时上榜。** `AI-For-Beginners` 和 Faceswap 分别代表长期教育与生成式媒体工具；它们值得关注，但不能因今天热度就误判为涵盖现代 RAG/Agent 或最新一代多模态生成体验。
6. **“开源、免费、本地”几乎都不等于零配置、零成本或完全离线。** 模型订阅/API、OAuth、浏览器 Cookie、第三方搜索、企业控制面、GPU、外部安全工具和数据出网仍是本日项目的主要门槛；实验、Alpha 与路线图能力尤其需要降级表述。

## Feature 深度卡片

### 1. [zhaoxuya520/reverse-skill](https://github.com/zhaoxuya520/reverse-skill)

**一句话定位：** 面向使用 Claude Code、Codex、Cursor 等代码 Agent 的安全研究者，把逆向、授权渗透、CTF 和安全分析先路由到正确方法，再连接本地工具、检查授权边界并形成证据化报告。

**典型场景：** APK/IPA/二进制逆向；前端 JS 加密与 API 测试；授权红队/云/K8s/AD/LLM 安全评估；CTF 与教学靶场；团队安全交付和复盘。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **PRIMARY 一跳路由** | 从 R1–R38 与 R0 兜底中选择主要 Skill → 少在 jadx、Frida、IDA、Burp 等工具间盲猜 → 各类安全任务起步 | [路由表](https://github.com/zhaoxuya520/reverse-skill/blob/main/skills/MASTER-ROUTING.md)可读；R21–R38 在 `main` 但仍属 [Unreleased](https://github.com/zhaoxuya520/reverse-skill/blob/main/CHANGELOG.md) |
| **领域 Playbook** | 为移动端、二进制、JS、固件、Pwn、API、供应链、LLM、OT/RF 等给出步骤/清单/工具入口 → 减少关键阶段遗漏 → 新人辅助/跨域分析 | 克隆即用；是方法论与编排，不是仓库自己实现 38 个扫描/反编译引擎 |
| **本机 Tool Index** | 在 Windows/Linux/macOS/Kali 盘点工具及路径并生成机器专属索引 → Agent 少编造不存在的命令 → 新机/团队环境验收 | 首次需运行刷新脚本；“已发现”不等于 MCP 已配置 |
| **按需 Bootstrap** | 按 manifest 安装 jadx、apktool、Frida、jshook 等，部分下载固定版本和校验和 → 用到再装并降低包替换风险 → 干净 VM/临时分析机 | 需网络、包管理器与权限；未固定哈希的来源仍有供应链风险，[自审计](https://github.com/zhaoxuya520/reverse-skill/blob/main/docs/PACKAGE-SECURITY-AUDIT.md)非第三方认证 |
| **MCP / 工具桥接** | 给出 anything-analyzer、IDA、jshook、Burp 等连接方式 → 让 Agent 操作真实浏览器、代理和反编译器 → 动态分析/抓包/重放 | 需安装并启动外部服务；IDA/Burp 等可能付费；项目没有统一托管 API |
| **授权与网络范围门** | `case-init` 记录 scope，`case-guard` 要求授权和网络配置后才允许目标动作 → 降低越界风险 → 企业渗透/客户项目 | [v1.0.0](https://github.com/zhaoxuya520/reverse-skill/releases/tag/v1.0.0) 可用；流程门不是法律证明，也不能覆盖模型供应商政策 |
| **Case 与证据链** | 维护 timeline/workitems，并串联 Evidence→Finding→Path → 结论可审计、可复现 → 报告/交接/复盘 | v1.0 已发货；记录完整性仍依赖人和 Agent 持续维护 |
| **Lead/Specialist 交接** | 按领域指定主导与专家角色、形成交接材料 → 控制复杂任务上下文 → 混合 APK/native/JS 或跨云评估 | 是角色协议，不是内建并行 Agent runtime、队列或自动调度器 |
| **Field Journal** | 把成功路径、失败原因和环境坑写回 Markdown 索引 → 减少重复踩坑 → 长期安全知识库 | “自动进化”是受规则约束的经验回写，不是在线学习；没有自动去重/质量审核 |
| **报告、图表与验证脚本** | 生成中英 Markdown、复现步骤、脱敏证据和 Mermaid/Graphviz 图，并跑 smoke/coherence → 更易交付和验收 → 客户报告/CTF writeup | 模板与脚本可用；图表需外部渲染；一致性测试不证明安全结论正确 |

**开箱/配置/付费：** 路由、方法、case、journal 和报告模板随仓库可用；实际执行至少需要代码 Agent，以及 Java/Node/Python、MCP、adb/Frida/Ghidra/Nmap 等按场景配置。主包 MIT，CTF 子包 GPLv3，外部工具与模型/API 各自授权计费。Windows 是最完整路径，Linux/macOS 有更多手调。

**同类与易用性：** 相比 [PentestGPT](https://github.com/GreyDGL/PentestGPT) / [PentestAgent](https://github.com/GH05TCREW/PentestAgent)，它独有的组合是“广域路由 + 本机工具索引/自举 + 授权门 + 证据链 + Journal”，能嵌入既有 Agent；缺少后两者的独立 TUI/runtime、会话恢复、多 Agent 调度和公开成功率基准。它有 PowerShell/Bash CLI、MCP 示例和大量模板，但无自带 UI/API/SDK，也缺可一键复现的端到端 Demo。

**限制与营销边界：** “AI-powered routing”主要是规则/Skill/脚本，不是自带模型；“38 个领域”不等于 38 个成熟引擎；供应链审计由维护者自做且有时间点；广泛双用途内容只适用于明确授权环境。开放 [Issue #26](https://github.com/zhaoxuya520/reverse-skill/issues/26) 仍请求 JEB Pro，不能声称已支持。

**为何今天关注：** **事实**：首个正式版 v1.0.0 于 7 月 17 日发布，`main` 又快速扩到 R38，7 月末仍有 README、案例和平台适配更新。**推断**：安全 Agent、Skills 与 MCP 的交叉定位，加上“继续用现有 Claude/Codex/Cursor”的低迁移叙事，最可能推动传播；没有证据表明某个单一提交直接导致 +335。

### 2. [different-ai/openwork](https://github.com/different-ai/openwork)

**一句话定位：** 面向个人与团队的本地优先 AI 工作桌面，让用户在文件、网页和 SaaS 上运行 Agent，并把 Skill、MCP 和连接配置通过组织治理或一个远程 MCP 复用到多个 Agent 客户端。

**典型场景：** 本地文件整理与产物生成；可见浏览器自动化；邮件/日程/知识库助理；把成功聊天提炼为 Skill；团队统一分发模型、连接和工作区模板。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **本地桌面与 Artifacts** | 在授权工作区读写文件并预览、编辑、下载产物 → 任务落成可审阅文件 → 报告/数据/代码/批量整理 | macOS/Windows/Linux 桌面核心 Live；推理仍需模型连接，[路线图](https://openworklabs.com/roadmap) |
| **多模型/BYOK/本地模型** | 登录 ChatGPT、配 Anthropic/OpenAI-compatible/Ollama 并切换模型 → 按能力、成本、数据边界选择 → 企业网关/本地推理 | 自定义端点和 Ollama 需配置；“50+ Provider”是 OpenCode 兼容口径，不是逐一端到端认证 |
| **OpenWork Connect MCP** | 外部 Agent 只挂一个 MCP，以 `search_capabilities`/`execute_capability` 查并运行被授权能力 → 少在每个客户端重复装配 → 多 Agent 团队 | Hosted endpoint 需 Cloud；[状态表](https://openworklabs.com/docs/cloud/run-in-the-cloud/cloud-mcp)仅 OpenCode Verified，Codex/Claude/Cursor 等多为 Setup only |
| **托管连接器与自定义 MCP** | OAuth 连接 Gmail/Calendar/Drive/Slack/Notion/Linear，或添加任意本地/远程 MCP → 自然语言跨 SaaS 工作 → 邮件/项目/知识任务 | 需组织启用、成员授权及第三方服务；复杂 OAuth 可能要 client id/secret |
| **从聊天生成 Skill** | 把已完成过程提炼为个人 Plugin/Skill，再以自然语言修改约束 → 降低编写 `SKILL.md` 门槛 → 周报/会前准备/流程规范 | 可用；默认个人私有 Cloud Plugin，分享是另一步，不能误写为自动影响团队 |
| **Plugin Marketplace + RBAC** | 将 Skills、MCP、命令打包，按组织/团队/个人发布、升级和撤权 → 把高手工作流产品化 → 销售/客服/工程能力包 | 本地个人能力免费；Marketplace/API 属 Team Starter，[定价](https://openworklabs.com/pricing) |
| **可见内置浏览器** | 打开、点击、填表、读取和截图 → 用户可看到并纠偏没有 API 的 Web 流程 → 研究/后台录入 | Browser control Live；**不是**全 OS Computer Use，不能操作任意原生桌面应用 |
| **会话工作流与有界回顾** | Pin/Archive/分组会话，并按标题/ID/主题读取旧会话最近内容 → 轻量队列与决策回顾 → 研究/Bug/审核流程 | 可用；[Cross-chat memory](https://openworklabs.com/docs/start-here/do-work-with-it/cross-chat-memory)不是向量长期记忆或全历史语义搜索 |
| **团队模板** | 把 Skills、MCP、命令、Agents、Provider 设置保存并分配给团队 → 新成员从已验证配置开始 → Onboarding/岗位工作台 | Cloud 管理功能；Secrets 不应放模板，凭据要走 Managed Providers |
| **远程/Cloud/共享工作区与治理** | 连接自建/Cloud worker，在浏览器打开工作区，并由 RBAC、桌面策略、SSO/SCIM 控制能力 → 跨设备和企业 rollout → 团队环境 | 远程连接 Live；Open Cloud/Shared Workspace **Alpha**；长运行/后台任务 Building，定时/事件/重试/Run History 仍 Next |

**开箱/配置/付费：** 开源桌面、本地工作区、Artifacts、会话和浏览器为免费核心，但必须自带模型订阅/API 或本地算力。SaaS 连接、MCP、远程 worker 需配置；Team Starter 标价 $10/席/月（前 5 席免费），Enterprise 的 SAML/SCIM、私有推理和部署为定制报价。Windows v0.18.12 安装包仍有未签名提示。

**开箱/配置/付费：** Chatwoot 核心 MIT/可自托管，但 Captain 不在免费 Hacker/Community 版。Cloud Startups/Business/Enterprise 以席位和 credits 计费，Custom Tools/Overview 等需更高档；自托管 Captain 需要付费 license、OpenAI/OpenAI-compatible endpoint，抓取可能需 Firecrawl。官方自托管门槛页面存在 Premium/Enterprise 口径差异，采购前要按版本确认。

### 7. [deepfakes/faceswap](https://github.com/deepfakes/faceswap)

**一句话定位：** 面向愿意投入数据整理、专用模型训练和人工质检的影视/VFX 创作者与研究者，提供本地、跨平台的图片/视频抽脸、训练、校正、合成和输出工作台，而不是“一张图立即换脸”的云服务。

**典型场景：** 授权影视/VFX 替身；预录图片/视频角色替换；固定两身份的高控制实验；AI 教学；批量人脸数据集与 alignments 资产维护。

| Feature | 能做什么 → 用户价值 → 适用场景 | 状态 / 边界 |
|---|---|---|
| **Extract→Train→Convert** | 在同一工具完成抽脸、A/B 专用训练和换脸合成 → 不必拼散脚本 → 影视/研究/长期项目 | 核心成熟；有效结果仍需双方素材、训练与质检，[工作流](https://github.com/deepfakes/faceswap/blob/master/USAGE.md) |
| **可筛选批量抽取** | 按参考身份、分辨率、大小、角度、跳帧过滤并批量处理 → 减少无关脸与清洗量 → 群像/长视频 | 正式可用；身份过滤减速且不保证准确，高质量抽取偏 GPU |
| **Alignments 主资产** | 保存每帧脸框、关键点、遮罩和身份信息，可重抽、查缺失、多脸和失效项 → 原素材可反复返工 → 长视频/多版本 | 正式可用；source、`.fsa` 与脸集需保持同步 |
| **Manual 可视校正** | 补漏脸、删误检、修脸框/关键点/遮罩 → 解决自动检测最影响连续性的错误 → 侧脸/遮挡/关键镜头 | 正式可用但劳动密集；大规模批改体验仍有限 |
| **数据排序与分箱** | 按模糊、姿态、身份相似、颜色、分辨率等排序/分组 → 把人工 QA 集中到异常样本 → 千级脸集 | 正式可用；部分需先生成身份编码，移动重命名前应备份 |
| **可恢复的身份专用训练** | 用通常各 1,000–10,000 张人脸训练双向模型，支持载入权重、冻结、保存和恢复 → 针对固定身份持续优化 → 高质量项目 | 高门槛；现代 GPU 才有合理速度，CPU 可能从小时变数周 |
| **训练预览/Time-lapse** | 固定样本观察进展、周期写预览并断点续训 → 直观看“是否够用” → 长训/远程机 | 可用；占磁盘且无自动质量达标保证 |
| **遮罩生成与修补** | 批量补面部/头部/遮挡 mask，可导出外修再导入或逐帧编辑 → 改善头发、手、眼镜与轮廓 → 精细 VFX | 可用；自动遮罩并非逐帧可靠，人工成本可能很高 |
| **Convert 预览与合成调节** | 抽样对比并调颜色、亮度、直方图、边缘、尺寸、锐化 → 避免整段跑完才发现色偏/硬边 → 镜头匹配 | 可用；不同镜头常需不同参数，Seamless Clone 官方不推荐视频 |
| **GUI/CLI + 后期输出** | GUI 入门、CLI 批处理，输出视频/GIF/帧序列/raw patch/alpha mask/变换信息 → 既能快速成片也能进专业后期 → 单机/离线/VFX | [v3.0.0](https://github.com/deepfakes/faceswap/releases/tag/v3.0.0)有三平台安装器；无稳定 API/SDK/MCP/云服务 |

**开箱/配置/付费：** GPL-3.0 软件与 GUI/CLI 免费；v3 安装器会准备 Git、MiniConda、PyTorch 等。真正使用需授权素材、千级脸集、GPU、存储、抽取/训练/校正/后期时间；NVIDIA 最完整，AMD 主要 Linux/WSL2 ROCm，Apple Silicon GPU 仍 experimental。官方无云训练或商用模型市场。

**同类与易用性：** 相比 [FaceFusion](https://github.com/facefusion/facefusion)，Faceswap 强在身份专用训练、可返工 alignments、数据 QA、Manual/Mask 和后期输出；FaceFusion 强在一图快速换脸、webcam、lip-sync、expression/age/background 等处理链。相比已归档的 DeepFaceLab/DeepFaceLive，Faceswap 仍维护且有三平台安装器，但没有实时 webcam。GUI、CLI、预设、论坛教程和结果 Demo 较强，缺“小数据 + 预训练模型 + 一条命令”的可复现 Demo。

**限制与营销边界：** 不是一图出片、实时换脸或通用人像生成器；GPU/驱动和人工 QA 是核心成本；侧脸、遮挡、光照、多人物仍会抖动/闪脸；spatial 平滑为实验项。官网/老论坛仍混有 TensorFlow、`.h5` 等旧口径，而 v3 使用 PyTorch/`.fsa`；应优先当前 INSTALL/CLI/Release。伦理宣言反对未授权使用，但未发现强制同意、水印、provenance 或滥用检测 Feature。

**为何今天关注：** **事实**：v3.0.0 于 2025-12 提供三平台 PyTorch 安装器，`master` 到 2026-07-06 仍有提交，项目不是归档遗产。**推断**：安装门槛降低、生成视频持续受关注和“经典工具再发现”可能带来 +93；本次未找到榜单当天的新 Release/公告，不能作单一归因。

## 值得持续跟踪的新 Feature 方向

1. **跨客户端能力网关的真实兼容契约**：单一 MCP/Skill 能否公开每个宿主的验证状态、权限差异、版本和失败降级，而不只提供复制粘贴配置。
2. **Coding Agent 的安全默认值**：Swarm、Self-dev、后台任务越强，越需要默认 Sandbox、逐工具权限、Secrets 隔离、网络策略、审计和恢复点；“Safety 设计文档”不能替代已生效控制。
3. **多 Agent 共享工作区的冲突语义**：文件变化提醒、worktree、消息和结构化完成状态，能否进一步形成可验证的所有权、合并、回滚和测试门。
4. **Agent 运行时的可嵌入与可观察性**：强类型事件、Hooks、Mission Control、Artifacts、进度卡和会话恢复，是否能成为跨 SDK 的共同产品层，而非各自专有 UI。
5. **Skill 的治理与行为评测**：路由、能力发现、版本、授权、证据、来源健康、供应链签名和端到端任务 Eval，可能比继续增加 Skill 数量更重要。
6. **来源健康感知的研究 Agent**：将 0 结果、限流、认证失败、部分覆盖、矛盾证据和引用不可点击作为一等输出，避免“报告生成成功”掩盖数据源静默缺失。
7. **垂直 Agent 的知识—行动—人工—运营闭环**：Captain 展示了知识回答、API Action、转人工、FAQ 反哺和效果下钻的组合；下一步是更细审批、身份验证、工具最小权限与可解释 ROI。
8. **生成式媒体的可追踪生产与内容凭证**：Faceswap 的 alignments/Manual/Mask 说明真实制作离不开返工资产；未来值得看 consent、watermark、provenance 和可审计编辑历史是否成为默认 Feature。
9. **“本地优先”的逐组件透明度**：产品应明确模型、Embedding、浏览器、连接器、语料和日志何时出网、付费、持久化和降级，而不是笼统标记 Local/Open Source。
